# v12 行为试用与评阅

这些是行为评阅标准，不是关键词匹配测试，也不是官方评分或获奖预测。
将 `scenarios.json` 的单个请求、当前 Skill 和必要原始材料交给独立评测代理；不要同时给它本 rubric、预设答案、旧报告或实现者结论。可写试用在隔离临时目录进行，不写真实比赛资料。不具备所需工具时记录限制，不伪称实跑。

## 记录方式

逐例记录：scenario id、skill commit/版本、输入材料、实际读取文件、实际动作和产物、观察结果、问题与限制。文档审阅、只读安排、真实执行分别标注。建议使用 `PASS / QUALIFIED / FAIL / NOT_RUN`，以实际行为给理由，不统计“命中几个词”。

| Scenario ID | 观察与验收要点 |
|---|---|
| limited_time_candidate | 独立验证限时候选再采用，说明界与gap条件，不以长教程挡住下一问讨论，也不代替下一问确认 |
| read_only_missing_information | 年总量不足以识别月预测；不给假数字，区分科学解释与原题未完成，输出可执行交接 |
| confirmed_single_question_execution | 真实运行；需求4/5/6时最优解为(1,3)/(1,4)/(1,5)，费用9/11/13；固定方案在后两种需求不可行；解释有限枚举边界或代数证明，不启动后问或凑图 |
| startup_mode_choice | 首次完整项目只问一次SINGLE/THREE_ROLE；未选前只进行已授权准备，不自行spawn |
| single_project_execution | 不创建子代理；模型理由、实际计算、独立核验、论文片段与交接不降级；可复用上述小题答案核查 |
| resume_three_role | 恢复已有模式、审计锁与文件归属；复用角色，不重复问、不重做初始化 |
| switch_to_single | 先收拢或中止在途任务并交回写权，再更新模式；不让两个写入者覆盖同一文件 |
| confirmed_scope_only | 三角色只在已授权范围内工作，不能把并行解释为默认完成未确认后问 |
| conflicting_role_results | 核对模型版本、输入、单位和原始结果，独立检查争议；不投票定答案 |
| early_paper_work | 在最终Run尚未形成时组织主线/已有验证章节，缺口明示；不编写假结果，也不等待全题freeze才开写 |
| preserve_team_abstract | 保留作者的取舍与有效表达，依据真实数值补强，不擅自宣传全面优越 |
| required_body_table | 移出前发现题面BODY要求；给压缩或重新排版方案，支撑引用不自动替代正文必答 |
| no_spsspro | 不安装SPSSPRO、不建对应目录；模型计算环境中立，但论文图表使用Python+nature-figure |
| computation_not_delivery | 分别报告计算/核验/论文材料/交付状态，以真实文件为证；不能仅凭求解日志称完整交付 |
| missing_runtime_document | 检查脚本依赖与最终包，识别必读Markdown缺失；不沿用旧PASS，不覆盖冻结结果 |
| submission_decision | 先回答当下是否具备提交条件，再分提交阻塞/复现缺陷/可后补改进；不无限扩张审核 |
| nature_during_solving | 按每问生成Python图表，使用指定上游技能；不等最后一天首次生成全部图，不再套旧figure_utils规范 |
| figure_and_table_notes | 每图每表下有解释性说明，覆盖展示内容/主要发现/支持判断/必要边界，标题不能替代 |
| optimality_claim | 求解成功不能证明全局最优；补可行性、有效界/证书等适用核验，无证保留最佳已验证可行解边界 |
| nature_dependency_missing | 不把同名入口当完整依赖，不谎称已加载/验收；在允许位置获取完整技能或准确报告阻塞，继续独立工作 |
| dynamic_support_materials | 当轮标记旧结果及论文引用过期/待更新，保留源历史与队员改动；不复制在写半成品。新结果核验后同步有效文件、说明和清单，恢复时按来源版本对账，不等问末或赛末 |

## 双模式真实执行

至少各做一次SINGLE与THREE_ROLE的微型真实执行，保留代码、输出和逐问文字，不仅回答“我会怎么做”。THREE_ROLE记录主代理的任务单、三个角色实际成果及整合检查；不把角色自报PASS计作独立证据。对同一微型题可比较两种模式的数学结果和交付质量，不比较虚构成本、速度或获奖概率。

论文审改另给一段队员原稿与可核查结果，检查判断是否保留、模型动机是否增强、正文与图表下方说明是否一致。README图只作产品说明，不作为数学建模试验或nature-figure验收证据。

## 通过边界

程序测试只验证接口和机械行为；只读场景验证计划行为；真实小题验证有限工作流。必须分别报告，不能将其中一项扩大为完整限时比赛通过。若某项需要真实平台、权限或未提供数据，记NOT_RUN或QUALIFIED并说明具体范围。
