## 🌟 这是什么？

`cumcm-modeling-analyst` 是一个面向 **全国大学生数学建模竞赛（CUMCM）及同类 Mathematical Modeling Competition** 的 AI Skill，重点适配 **Codex、Claude Code** 等能够读取赛题附件、编写代码并在本地执行 Python 的 Agent。

它不只是“帮你做一道题”。

更希望在三天比赛里成为一个一直在线的 **建模学长 / 指导老师 / 研究搭档**：

- 后台认真读题、查资料、跑数据、写代码、做验证；
- 聊天窗口只告诉你真正重要的结论和风险；
- 复杂公式、EDA、实验、评分和文献记录自动沉淀到 Markdown；
- 每一问做完整后，再和队伍一起判断要继续深挖，还是及时推进；
- 有好结果会告诉你为什么值得高兴，发现坑也会及时提醒；
- 没有新发现时宁愿明确说“没发现”，也不为了显得厉害硬凑研究成果。

**研究可以很深，聊天不必很长。**

---

## 🤝 更像一个一起比赛的搭档

传统 AI 很容易变成：

```text
收到题目
↓
输出几千字
↓
套几个模型
↓
再输出几千字
↓
等待“是否继续”
```

这个 Skill 更希望是：

```text
我先把题目和附件彻底看懂
↓
自己做探索、比较方案、跑实验
↓
把完整研究写进 Markdown
↓
聊天里只告诉你：发现了什么、有什么用、我建议怎么走
↓
和队伍一起推进下一步
```

例如一问做完后，AI 更可能这样和你说：

> 我刚把问题一完整跑完了，这一问现在基本站稳了。主模型比 baseline 稳定不少，而且参数变化时结果也没怎么飘，这对问题二挺关键的。完整实验我已经放进 `问题1_研究记录.md`。
>
> 我还看到一个方向可能值得多查一轮，因为它可能影响问题二的输入稳定性。你们想再冲一下，我就继续；如果现在更想赶进度，我们直接上问题二也完全可以。

而不是把整个研究报告重新复制到聊天窗口。

## 🧠 核心思路：对话要轻，研究要深

整个 Skill 分成三层：

| 层 | 做什么 |
|---|---|
| **研究内核** | 深读题、探索、选模、Python、验证、文献核验、上下问衔接、原题回查 |
| **赛时协作层** | 判断当前进度、风险、是否值得继续研究、什么时候应该推进 |
| **对话层** | 用自然口语告诉队员刚做了什么、发现了什么、有什么用、下一步建议 |

**聊天变短 ≠ 研究缩水。**

后台可以做大量实验、阅读和计算，但聊天窗口默认只保留真正影响队伍决策的信息。

---

## 🔬 探索性研究：先看数据，再选模型

数学建模里，模型不应该由题目关键词决定。

题目写“预测”，不代表一定用 ARIMA / XGBoost / LSTM；题目写“评价”，也不代表一定上 AHP / TOPSIS。

Stage 1 允许 Codex 使用轻量 Python 做：

- 数据结构、字段、样本量检查；
- 缺失、异常、重复、单位检查；
- 描述统计与必要可视化；
- 趋势、周期、季节性、自相关、结构突变；
- 相关性、共线性、类别分布；
- 聚类倾向、图结构、可行域规模；
- 简单 baseline；
- 候选模型关键假设验证；
- 小规模算法可行性实验。

流程更接近：

```text
理解题目
→ 看数据
→ 提出候选模型
→ 做必要的小实验
→ 更新判断
→ 再决定正式路线
```

**模型是分析结果，不是分析起点。**

---

## 🧭 第一阶段：完整研究，极简汇报

第一阶段内部仍然会完整完成：

```text
深度读题
→ 附件审计
→ 探索性研究
→ 每问候选方案
→ 100 分评分
→ 整题路线
→ 文献 / 数据 / 参数证据
```

但聊天窗口默认只说最重要的东西，例如：

```text
我把整题和附件都看完了，也跑了一轮探索。

问题1：更推荐 XXX，主要因为……
问题2：建议 XXX + XXX，这里最大的风险是……
问题3：承接问题2的 XXX 做……

整体我更倾向路线 A。
完整 EDA、候选方案评分和证据已经整理进 第一阶段_完整研究.md。
```

完整信息进入 Markdown，不让聊天窗口变成一堵文字墙。

---

## 🚦 每一问做完后：可以停，也可以继续研究

每一问原本该做的流程必须先完整结束：

```text
原题要求回查
→ 必要探索
→ 最终模型
→ Python 实现
→ 实际运行
→ 结果验证
→ 直接回答本问
→ 上下问交接
```

只有到这里，这一问才算真正完成。

之后才进入可选的 **Stage Gate（阶段闸门）**：

```text
当前问题已经可交付
        ↓
有没有真正值得继续研究的东西？
      ↙       ↘
    有           没有
    ↓             ↓
继续一轮扩展研究   推进下一问
```

### 继续研究不是“多做点东西”

AI 想继续研究，必须先能回答：

1. **研究什么？**
2. **为什么值得？**
3. **它可能改变什么决策？**
4. **什么时候应该停止？**

说不清楚，就不继续。

严禁：

- 为了丰富结果随便多跑几个模型；
- 为了创新而制造创新；
- 把噪声解释成规律；
- 为了“研究深入”无限扫参数、堆图表；
- 为了完成任务而制造垃圾结果。

宁愿告诉队员：

> 这轮我没看到值得继续挖的东西了，再往下做大概率只是堆实验，我建议把时间留给下一问。

---

## 🔎 扩展研究允许“没有发现”

一次真实的扩展研究可以有三种结果：

```text
MEANINGFUL_FINDING
真的发现了会改变决策或明显增强证据的结果

NO_MEANINGFUL_FINDING
认真研究过，但没有值得采用的新发现

INCONCLUSIVE
当前数据 / 时间 / 证据不足，无法可靠下结论
```

后两种不是失败。

**没有发现，比编一个发现出来强得多。**

---

## 💬 研究结论也要有“人味”

每一问里出现真正重要的结果时，AI 会给队员适度的情绪反馈。

不是无脑夸奖，而是让你知道当前研究意味着什么：

| 真实情况 | 更自然的交流 |
|---|---|
| 模型稳定、验证通过 | “这下这一问基本站稳了。” |
| 及时发现关键假设错误 | “这个坑发现得挺及时，不然后面很容易一起被带偏。” |
| 新模型明显优于旧路线 | “这轮值得，路线确实该换。” |
| 扩展研究没新发现 | “这轮没挖到新东西，反而说明现在这版已经比较稳。” |
| 当前路线失败 | “这条路确实跑不通，我们换，不硬撑。” |

但 Skill 明确禁止：

- 无依据说“稳了”“完美”“肯定获奖”；
- 为了情绪价值夸大结果；
- 用热情语气掩盖不确定性；
- 为了让队员开心而创造不存在的成果。

---

## 🌐 实战比赛和旧题测试，不使用同一种联网策略

为了既不削弱正式比赛研究能力，又能防止历年旧题测试被答案泄漏污染，Skill 提供两种联网模式。

| 模式 | 用途 | 联网规则 |
|---|---|---|
| **LIVE_RESEARCH_MODE** | 正式比赛 | 正常查论文、数据、参数、标准、领域案例、算法和库文档 |
| **BLIND_BENCHMARK_MODE** | 历年旧题能力测试 | 禁止用题号、题名、原文、附件特征等定位历史答案 |

### 实战赛题

保留正常研究能力，可以搜索：

- 学术论文；
- 官方公开数据；
- 参数来源；
- 国家 / 行业标准；
- 相似领域案例；
- 算法与 Python 库文档。

只禁止以寻找**当前比赛现成完整答案 / 泄露解答**为目的的搜索。

### 旧题盲测

禁止主动搜索或阅读：

- 年份 + 题号；
- 完整题名；
- 题面原句；
- 附件文件名；
- 特殊常数 / 数据片段；
- 该题历史优秀论文；
- 现成完整解答；
- 对应博客、仓库和成品源码。

但仍然可以去题目标识化地搜索：

- 通用理论；
- 原始模型论文；
- 官方数据；
- 通用参数来源；
- 算法 / 库文档。

如果盲测过程中意外命中历史完整答案，必须立即停止继续读取并标记：

```text
ANSWER_LEAKAGE_DETECTED
```

严格 benchmark 已经存在污染风险，不能再声称完全独立。

独立求解结束后，经用户明确同意，可以进入：

```text
POST_SOLUTION_COMPARISON
```

再去和历史优秀论文 / 已有解法做对照。由此产生的改进必须标记：

```text
POST_HOC_IMPROVEMENT
```

不能倒灌回去冒充原始盲测能力。

## ⚙️ 第二阶段：两种解题方式

路线明确以后，如果用户没有提前指定，可以选择：

| 模式 | 更适合 | 特点 |
|---|---|---|
| **A. 逐题深度求解** | Codex / Claude Code / 正式比赛 | 一问一问做深，每问完整闭环后再推进 |
| **B. 一次性完整求解** | Chat / 队伍前期快速参考 | 沿整题主路线连续完成全部问题 |

### A. 逐题深度求解

```text
问题 k 原题回查
→ 上下关联探索
→ 问题级探索
→ 最终模型
→ Python 实现
→ 实际运行结果
→ 验证
→ 代码解析
→ 本问资料 / 文献
→ 本问答案
→ 向下一问交接
→ Stage Gate
```

每一问都是真正完整的小研究循环。

如果实际运行结果推翻原路线，可以触发：

```text
ROUTE_REOPEN_REQUIRED
```

重新比较方案，而不是因为前面已经选了就硬做下去。

### B. 一次性完整求解

连续解决全部问题，但真实性、代码、验证和上下问衔接的质量底线不变。

## 📝 重要研究信息不会只留在聊天里

比赛持续数天，不能依赖聊天记录保存核心结论。

赛时建议持续沉淀：

```text
其他/赛时协作/
├── 当前进度.md
├── 第一阶段_完整研究.md
└── 研究决策日志.md
```

逐题还会继续保存：

```text
题目详解/问题k/问题k_完整教程.md
其他/文献与来源/问题k_资料与文献.md
源码/.../问题k/...
```

这样聊天可以很轻，但重要研究不会丢。

## ✅ 最后必须重新读一遍原题

全部问题完成后，不直接急着写论文。

AI 必须重新读取原题并建立 Requirement Traceability：

| 原题要求 | 对应问题 | 最终结果 | 对应代码 / 输出 | 是否完整回答 |
|---|---|---|---|---|

重点检查：

- 有没有漏掉某个子要求；
- 单位、范围、边界有没有处理；
- 各问结果是否真正传递；
- 有没有“模型做了很多，但没回答题目”；
- 最终结论是否超过数据和模型能支持的范围。

## 📚 文献、数据、参数必须真实

Skill 明确禁止：

- 编造题名、作者、年份、DOI；
- 猜测或拼接 URL；
- 把搜索结果页当正式来源；
- 没读全文却说读过全文；
- 页面能打开就声称全文可下载；
- 给参数编一个“文献常用范围”。

文献访问状态区分：

```text
PAGE_VERIFIED
DOWNLOAD_VERIFIED
METADATA_ONLY
PAYWALLED
DOWNLOAD_UNVERIFIED
BROKEN_LINK
REJECTED
```

只有真正核验过的全文下载入口才能标记为 `DOWNLOAD_VERIFIED`。

## 📈 建模图表默认由 Python 生成

预测图、误差图、敏感性图、热力图、路径图、网络图、Pareto 图、仿真图等默认根据 **真实数据和真实模型结果** 用 Python 生成。

用户没有明确要求 AI 生成图片时，不主动使用图片生成工具做建模结果图。

## 🔎 组员手搓论文后，还可以再回来终审

AI 完成交付后，队员应自己理解、核查并重写最终参赛论文。

组员论文完成后，可以再次交给 Skill，进入：

```text
FINAL_PAPER_AUDIT
```

这不是普通“润色”。

AI 会重新对照：

```text
原始赛题
+ 组员最终论文
+ 最终模型路线
+ Python 源码
+ 实际运行结果
+ 图表 / 表格
+ 文献和数据记录
```

至少执行三轮：

```text
正确性审计
↓
一致性审计
↓
语言与格式审计
```

重点检查但不限于：

- 问题一写成了问题二的解法；
- 模型名称对但公式抄错；
- 参数、单位、小数点、正负号错误；
- 正文结果与 Python 输出不一致；
- 图表所属问题写错；
- 摘要、正文、结论互相打架；
- 思路和解释错误；
- 把相关性写成因果；
- 原题某个子要求漏答；
- 错别字、病句、图号、表号和引用问题；
- 其他可能造成失分的真实问题。

问题分为 `P0 / P1 / P2 / P3` 四级。

默认输出：

```text
最终论文审核报告.md
```

## 🎯 设计原则

**先读懂题，再选模型。**  
**先看数据，再给方案评分。**  
**模型是分析结果，不是分析起点。**  
**对话要轻，研究要深。**  
**像朋友一样说话，像研究者一样做事。**  
**流程可以隐形，质量不能缩水。**  
**每一问完整结束后，再决定要不要继续深挖。**  
**没有新发现完全可以，禁止为了研究而制造研究。**
