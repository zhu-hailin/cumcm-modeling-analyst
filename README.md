## 这是什么？

`cumcm-modeling-analyst` 是一个面向 **全国大学生数学建模竞赛（CUMCM）及同类赛事** 的 AI Skill。

它把 AI 从“模型名称生成器”变成一个完整的建模工作流：

```text
深读题
→ 探索数据
→ 理清各问依赖
→ 用证据比较模型
→ 用户选择解题模式
→ 正式求解与 Python 实现
→ 验证
→ 回查原题
→ 参考论文与四包交付
```

核心目标不是堆复杂模型，而是让 **题意、数据、模型、代码、结果和各问之间的逻辑真正对得上**。

## ✨ 核心能力

| 能力 | 做什么 |
|---|---|
| 🧠 **深度读题** | 识别题面事实、动作词、边界、单位、输出要求和隐藏依赖 |
| 🔬 **探索性研究** | 在正式选模型前使用轻量 Python 做 EDA、baseline、趋势、可行性和模型前提检查 |
| 🧩 **逐问拆解** | 每一问明确核心任务、输入、输出、约束、前后依赖和验收标准 |
| 📊 **100 分方案评分** | 用统一标准比较真正有差异的候选方法，不凭感觉随便推荐 |
| 🔗 **跨问题关联** | 强制检查上一问结果如何进入下一问，避免各问成为“模型拼盘” |
| 🧪 **真实 Python 求解** | 路线确认后生成并执行最终 Python，保存实际结果、图表、表格和中间产物 |
| 📚 **真实文献核验** | 核验题名、作者、DOI、URL、全文访问和下载状态，禁止伪造来源 |
| 📝 **逐问代码教学** | 每一问都提供代码解析、运行方式、结果解释和相关资料/文献 |
| ✅ **原题逐条回查** | 全部问题完成后重新读题，确认每个要求都已经被结果和代码回答 |
| 📦 **四包交付** | 最终整理为题目详解、参考论文、源码和其他资料四个 ZIP |

## 🚀 为什么不是直接让 AI 开始写代码？

普通 AI 很容易这样做：

> 评价题 → AHP / TOPSIS  
> 预测题 → ARIMA / LSTM  
> 优化题 → 遗传算法

问题是：**模型名字对，不代表模型适合这道题。**

这个 Skill 会先问更关键的问题：

- 数据量到底够不够？
- 时间序列有没有趋势、季节性、突变？
- 分类任务是否类别失衡？
- 聚类是否真的存在可分结构？
- 优化问题的规模和可行域是什么？
- 简单 baseline 是否已经足够？
- 某个复杂模型的关键前提是否成立？

只有看完这些证据后，才进行候选模型评分。

# 第一阶段：深读题 + 探索性研究 + 路线决策

Stage 1 不再输出一大串难找重点的 `1.1 / 2.3 / 4.2` 小标题，而是按实际问题清晰分区。

示意：

```text
# 问题一

一句话判断
核心思路
关键探索证据
候选方案
推荐 / 备用 / 切换条件

---

# 问题二

一句话判断
核心思路
关键探索证据
候选方案
推荐 / 备用 / 切换条件

---

# 问题三 / ...
```

每一问只展示**真正影响模型选择的探索证据**，不会把几十张 EDA 图和长表格直接塞进第一阶段回复。

## 探索性研究可以做什么？

在 Codex、本地 Python 或其他可执行环境可用时，Stage 1 可以进行轻量探索：

- 读取全部工作表、字段、样本量和数据类型；
- 检查缺失、重复、异常值、量纲和编码；
- 描述统计和必要的基础可视化；
- 相关性、共线性和变量关系初查；
- 时间序列趋势、周期、季节性、自相关和结构突变检查；
- 分类/聚类的数据规模、类别分布和可分性检查；
- 优化问题的规模、约束可行性、图结构和搜索空间检查；
- 简单 baseline；
- 小规模模型可行性实验；
- 候选模型关键假设验证。

探索性研究只用于**理解题目和选路线**，不会提前把探索结果冒充最终结论。

## 📊 建模方案 100 分评分

每个子问题的候选解法和整题路线使用统一评分矩阵：

| 维度 | 分值 |
|---|---:|
| 题意匹配度 | 25 |
| 数据可获得性与数据量匹配 | 15 |
| 可验证性与稳健性 | 15 |
| 可解释性 | 10 |
| 赛时实现可行性 | 10 |
| 有效创新性 | 10 |
| 论文表达与图表呈现潜力 | 10 |
| 风险可控性 | 5 |
| **总分** | **100** |

推荐等级：

- **90–100**：首选路线
- **80–89**：强推荐
- **70–79**：可用，需补强
- **60–69**：备选
- **40–59**：局部可借鉴
- **0–39**：不推荐

评分必须说明理由和置信度。探索结果推翻初判时，必须更新评分。

整题路线通常比较 **2–3 条真正有意义的路线**；如果只有两条值得讨论，就只给两条，不为了数量硬凑第三条。

# 第二阶段：由用户选择解题模式

第一阶段路线明确后，如果用户没有提前指定，**AI 必须让用户选择解题方式，不能自行代选。**

| 模式 | 推荐场景 | 特点 |
|---|---|---|
| **A. 逐题深度求解** | Codex、本地执行、正式比赛深挖 | 一题一题做深，每问都有探索、代码、结果、验证、代码解析和本问资料 |
| **B. 一次性完整求解** | Chat、队伍前期快速参考 | 连续解决整题，不在问题之间暂停，快速拿到完整路线和结果框架 |

---

## A. 逐题深度求解

推荐用于 **Codex / 本地 Python**。

流程：

```text
[问题1]
   ↓
[问题2]
   ↓
[问题3]
   ↓
...
   ↓
[问题n]
   ↓
[原题逐条回查]
   ↓
[全局总结]
   ↓
[编写最终参考论文]
```

但每一问不是简单“算完就走”，而是一个完整研究循环：

```text
原题要求回查
→ 上下关联探索
→ 本问问题级探索
→ 最终模型
→ Python 实现
→ 实际运行结果
→ 结果验证
→ 代码解析
→ 本问资料 / 文献
→ 本问最终答案
→ 向下一问交接
```

### 为什么强调“上下关联探索”？

每进入一个新问题，AI 都会重新检查：

- 上一问真实输出是什么；
- 哪些结果可以直接作为本问输入；
- 本问需要重新估计哪些参数；
- 本问结果将给下一问提供什么；
- 当前新证据是否会改变后续模型选择；
- 是否需要回头修订前面问题的接口、参数或假设。

如果实际结果证明原路线不可行，可以触发：

```text
ROUTE_REOPEN_REQUIRED
```

重新比较路线，而不是为了“已经锁定”继续硬做。

默认每完成一问后可以暂停，让用户确认是否继续；用户也可以要求自动连续执行全部问题。

---

## B. 一次性完整求解

适合 **Chat 模式或队伍比赛前期快速参考**。

特点是：

- 不在每一问之间暂停；
- 沿同一整题路线连续求解；
- 仍然保留每问模型、Python、实际结果、验证和上下问接口；
- 最后统一做原题回查、总结和论文整理。

它适合快速回答：

> “这道题整体应该怎么做？每问怎么衔接？代码和模型大概是什么？”

而逐题模式更适合真正进入正式求解阶段。

---

## ✅ 原题逐条回查

无论选择哪一种模式，全部问题完成后都必须重新读取原题，建立 Requirement Traceability：

| 原题要求 | 对应问题 | 最终答案 / 结果 | 对应代码 / 输出 | 是否完整回答 |
|---|---|---|---|---|

重点重新检查：

- 每一个动作词；
- 每一个子要求；
- 边界条件；
- 单位；
- 输出格式；
- 是否遗漏题面中的附加要求。

**没有完成原题回查，不进入最终论文和最终交付。**

---

## 🔎 文献、数据和参数必须真实

Skill 会主动检索并核验：

- 背景机制；
- 原始模型与权威方法；
- 官方统计数据；
- 参数来源；
- 验证方法；
- 相似应用研究。

参考文献访问状态严格区分：

```text
PAGE_VERIFIED
DOWNLOAD_VERIFIED
METADATA_ONLY
PAYWALLED
DOWNLOAD_UNVERIFIED
BROKEN_LINK
REJECTED
```

只有真实确认存在全文下载入口的来源，才能标记为：

```text
DOWNLOAD_VERIFIED
```

禁止：

- 编造 DOI；
- 猜测或拼接 URL；
- 把搜索结果页当论文链接；
- 没读全文却声称读过全文；
- 页面能打开就声称全文可下载；
- 编造外部数据、参数或实验结论。

重要参考文献如果打不开、下载失败、付费或只能看到摘要，AI 必须继续寻找可靠替代来源；仍无法解决时必须明确反馈用户。

## 📈 图表与图片规则

数学建模图表默认全部由 **Python** 根据真实数据、模型结果或确定结构生成。

包括：

- 预测图；
- 误差图；
- 敏感性 / 鲁棒性图；
- 热力图；
- 路径图；
- 网络图；
- Pareto 前沿；
- 仿真结果图；
- 其他模型结果图。

Python 图表要求：**专业、清晰、论文可用，但不过度堆叠无用信息。**

除非用户明确提出生成、设计或风格化图片需求，否则禁止主动使用 AI 图片生成工具。

## 🎯 设计原则

1. **先深读题，再选模型**
2. **先探索数据，再给方案评分**
3. **模型是分析结果，不是分析起点**
4. **各问必须形成统一问题链**
5. **逐题模式必须强化上下问关联**
6. **简单但正确的模型优于复杂但无法验证的模型**
7. **路线可以锁定，但真实反证可以触发重开**
8. **最终必须重新回查原题要求**
9. **数据、参数、文献和链接必须真实可核验**
10. **代码、图表和结果必须可复现**

## 🧾 比赛合规

本 Skill 是建模分析、代码实现与决策辅助工具，不替代参赛队对模型、代码、论文和最终提交内容的理解与责任。

比赛期间应以当届组委会正式规则为最高优先级，并对 AI 参与内容进行人工复核。仓库中的 AI 使用记录模板可用于记录使用范围和人工检查过程。
