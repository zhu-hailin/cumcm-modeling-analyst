## 摘要与关键词

- 全题主线和关键现实困难：
- 各问的针对性设计、主要结果、解释、取舍与适用条件：
- 最能支持最终判断的数字及其比较对象：

按 `references/abstract-and-argumentation.md` 组织，保留人工摘要的有效表达，不机械逐问套句式。

## 1. 背景与问题重述

- 研究对象、已知条件、信息边界和主要约束。
- 逐问列出动作词、指定对象、单位、时段/样本范围、必须交付的结果及位置要求。
- 必要的总体路线图及其下方说明：展示什么、各环节如何衔接、支持怎样的全题理解。

## 2. 全题分析与路线理由

- 各问共享什么机制/数据，新增什么困难，哪些依赖真实存在。
- 为什么采用当前数学结构，如何处理关键约束与不确定性。
- 已有方法的归属及本题改动；区分模型、算法、求解器和经验策略。
- 实际考虑过的替代方案与关键取舍，引用本问 `decision_id` 的证据；不凑模型数量。

## 3. 假设、数据口径与符号

- 每项关键假设的必要性、依据、使用位置、影响和限制。
- 数据范围、时间键/样本单位、转换、缺失异常处理及版本。
- 共享符号、单位和范围；本问特有符号可在对应章节定义。

## 4. 问题 Q{k} 的模型建立、求解与论证

每问复用以下职责，具体小节名称和顺序按题型调整。

### 4.1 目标、困难与模型选择

直接回答本问要做什么、相对前问增加什么、为什么选这个模型。给出现实机制/数据结构依据、真实备选与取舍，不能只写“采用某算法”。有前问输入时明确正式文件与字段。

### 4.2 变量、关系与关键推导

按“目标 → 变量 → 关系/约束 → 推导 → 可求解形式”组织。关键公式说明引入目的、变量含义、量纲、参数来源以及从前式到后式的必要步骤。区分硬约束、软惩罚与经验规则，不省略影响结论的变换条件。

### 4.3 求解与执行过程

交代输入输出、算法流程、信息可用时点、关键参数、停止条件和可行性处理。说明模型与代码对应关系，软件名称不能代替算法。未执行的工作明确标记。

### 4.4 指定答案与结果解释

将题面要求的表格、数值、方案或规则放在可定位位置；`required_location=BODY` 的项目留正文。图表随当前问使用 Python 生成，统一通过 `references/python-visualization-policy.md` 使用 nature-skills。

**每张图、每张表下都写说明：展示什么 → 反映什么 → 支持什么判断；必要时补适用边界。** 标题不是说明。保持表格可编辑，不逐格念表；正文进一步解释机制和现实含义。

### 4.5 最优性或有效性论证

选择本题适用的证据，不要求每问都证明最优或执行全部检验：

| 题型/方法 | 需要说明的证据与可用表述 |
|---|---|
| 精确优化或松弛 | 原模型可行性、上下界/原始对偶证书、绝对或相对 gap、残差与容差；松弛达到界时还须核查原约束。区分实例数值最优、严格证明和普遍性质。 |
| 启发式优化 | 可行性、已知界或小规模精确基准、相同预算的公平对照与重复运行；证据不足时只称最好已知可行解。 |
| 预测/分类 | 按真实使用场景划分的留出/滚动/分组验证、泄漏排查、基准、误差及不确定性；选型窗口成绩不等于泛化成绩。 |
| 评价/聚类/识别 | 数据与检验前提、权重或距离选择、扰动稳定性、外部/机制核验；相关和分组不自动代表因果或阶段。 |
| 机理/仿真/反演 | 守恒和合理极限、数值收敛、校准与独立观测对照、可识别性或模拟噪声；明确模拟与真实观测的区别。 |

### 4.6 对照、敏感性与取舍

仅安排能影响主要判断的实验，固定可比条件。解释收益、代价及结论何时翻转。有价值的否决方案可进入论证，不能只展示有利指标；未验证机制写为待核验解释。

### 4.7 本问结论、边界与后问接口

归纳直接答案、支持强度、条件及下游读取的成果。区分当前样本/实例结论与普遍保证，不把局部最优、回放有效或对照最优写成全局/部署保证。

## 5. 模型评价、改进与综合结论

- 优点用已验证的机制、约束处理、解释和结果支持，不用平台品牌证明可靠。
- 局限说明影响和适用范围，不吞掉已获得的答案。
- 改进方向区分已完成与未验证设想。
- 综合结论连接全题认识、各问答案和最终取舍，不引入新结果。

## 6. 文献、附录与交付接口

- 文献在实际采用位置引用，元数据与主张已核验。
- 附录放必要推导、完整表和复现说明，不移走正文必答项。
- 文件名、运行入口与当前交付清单一致；实际环境、外部输入及未重跑项明确。
