# 子角色任务单

遵循 [多代理协作](../references/multi-agent-collaboration.md)。已有任务管理方式可沿用，不为模板另建重复台账。`THREE_ROLE` 中复用建模手、代码手、论文手；一份正式文件一个写入者。

## 派发

```yaml
task_id: Q1-modeling-01
role: modeling  # modeling | coding | writing，选择一个
question_id: Q1
goal: 本次目标及停止条件
confirmed_scope: 当前问确认依据、已授权主/备用路线；未确认时仅限研究准备
inputs:
  - path: 题面、审计记录、数据或已有成果的实际路径
    version: Run ID、hash 或可核对版本
    context: 必需字段/单位、关键决策引用或阅读范围
write_scope:
  - path: 本任务可写的具体文件或目录
    owner: 当前唯一写入者；接手时注明原任务已交回
deliverables:
  - 实际产物路径、格式和必需内容
acceptance:
  - 验证方法、关键硬约束、来源与交回标准
dependencies:
  - 上游任务或输入版本依赖，以及变更后的失效条件
```

无依赖时 `dependencies: []`；各路径须替换为实际项目路径。已知预算与中断交接要求补入 `goal`/`acceptance`，不编造截止时间。共同边界：不改原始数据、不覆盖他人产物、不正式求解未确认问题、不编造结果/来源。

三个角色在同一任务单中按职责选用以下输入与交回要求，不另建三份模板：

| role | 关键输入 | 重点交回 |
|---|---|---|
| `modeling` | 题面与约束、数据口径、已有路线/决策、需要检验的机制 | 变量与公式、关键推导、选择与舍弃依据、验证设计、失效边界和代码可实现的规格 |
| `coding` | 已确认模型、字段/单位、输入版本、验证要求和可写目录 | 实际代码与命令、Run/输出、约束与结果核验、Python 图表和数据来源、未完成项 |
| `writing` | 论文主线、队员原稿、已核验模型/结果、证据缺口和允许修改范围 | 保留队员表达的逐问论证/摘要候选、下方解释性图注/表下注、正文分析、每项主张的证据与待补内容 |

代码任务涉及论文图表时，写明按 [绘图规范](../references/python-visualization-policy.md) 使用 Python 随问生成及数据来源；其他建模计算工具依据现有工程，不默认要求 SPSSPRO。论文任务说明需保留的队员摘要/正文表达与允许修改范围。

## 交回

- 实际输入版本及是否与派发一致：
- 改动/新增文件与入口：
- 主要发现、关键决策引用和对应证据：
- 真实 Run/推导、关键验证与未核验项：
- 当前可写入论文的结果、解释、图表及成立条件；每张图表下方的解释性图注/表下注及正文分析：
- 计算 / 核验 / 论文材料 / 交付：分别记录状态与证据或缺口：
- 下游可读取的文件、字段、单位与版本：
- 尚未完成、冲突、风险和下一步：

主代理验收记录：输入版本一致性、任务边界、关键结果核验、文件合入位置及接手人。子角色自报完成不能替代验收，也不能替代下一问方案确认。
