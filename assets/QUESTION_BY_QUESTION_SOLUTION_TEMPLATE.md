# QUESTION_PLAN_CONFIRMATION：先和用户确认

完成上述研究后必须暂停正式实现，用简短、口语化方式和用户沟通。

必须询问的核心含义：

> 这一问的方案我已经梳理到可以正式实现了。你们还有没有论文、参考文献、额外数据、老师建议，或者对模型思路想再调整的地方？如果没有，我就按现在这个方案正式写代码、跑最终结果并整理问题 {k} 详解。

不要机械重复固定句子，但不能跳过这个确认。

## 用户可能的回应

### 用户补充资料

- 先读取 / 核验；
- 判断是否改变数据、参数、假设、模型或验证；
- 更新方案；
- 继续自然讨论；
- 再次等待用户确认。

### 用户提出新的思路

- 不要立刻否定或照单全收；
- 结合题意、数据、计算可行性和验证能力比较；
- 有价值就吸收；
- 不适合就解释为什么；
- 方案稳定后再等确认。

### 用户说“就这样 / 执行 / 按这个做 / 没有补充”

进入正式实现。

## 确认前禁止

- 生成最终生产级 Python；
- 标记 Final Run；
- 生成 A/B 级正式论文图；
- 固化最终结果表；
- 生成问题 {k} 完整教程；
- 直接跳到问题 {k+1}。
