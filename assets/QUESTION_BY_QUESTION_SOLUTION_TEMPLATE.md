### 用户确认边界

```text
QUESTION_PLAN_CONFIRMATION
```

用户确认后，以下技术工作默认由 Agent 自主完成，不需要逐次请示：

- EDA 与诊断实验；
- 参数、初值、容差、求解器和计算预算调整；
- 代码重构和数值稳定处理；
- 验证、敏感性、bootstrap、多 seed 或小规模精确解；
- 满足已确认触发条件后切换到已确认备用路线；
- 生成探索图、验证图和正式论文候选图。

只有改变原题目标/关键约束、改变会影响结论的关键假设、需要未授权新路线，或关键数据缺口存在多种会改变答案的处理时重新询问。

如果缺少论文、队友意见或额外数据**确实会改变当前决策**，再自然询问用户补充；不要每问机械重复询问同一套材料。

## B. 正式实现

### 模型、假设与公式

- 变量、单位与代码映射：
- 实际使用的假设及依据：
- 目标函数 / 状态方程 / 约束：
- 求解方法与为什么适用：
- 关键参数及依据：

不添加代码中未使用的装饰性公式；假设、公式和代码必须一致。

### 正式代码

代码路径继承当前项目约定，例如：

```text
03_code/q{k}/...
```

新建中文赛题项目可以使用清楚的中文语义名；已有英文仓库、包、Notebook 或 CI 直接继承原有命名。只创建实际需要的文件。

记录：

- 主入口：
- 输入数据：
- 输出目录：
- 关键配置：
- 运行命令：

### 真实运行

重要运行进入 `04_results/logs/RUN_LEDGER.md`。本问完成前明确：

```text
FINAL_RUN_ID = Rxxx
```

最终数字只从 Final Run 或明确关联的 Validation Run 读取。随机算法记录 seed / 重复次数 / 停止条件 / 代表结果选择规则，不只挑最好的一次。

### 验证与现实约束

只做与本题风险匹配、能改变结论强度的验证，可包括：

- baseline 或特殊情形对照；
- 留出、分组、滚动或外推验证；
- 残差、误差和不确定性；
- 独立算法、上下界或小规模精确解；
- 参数扰动、情景分析和决策翻转；
- 多 seed / bootstrap；
- 非负、总和、容量、守恒、时间窗、整数性、连通性和单位；
- 泄漏、小样本、相关冒充因果、聚类阶段过度解释等专项风险。

不会改变主答案、证据强度或论文边界的重复验证应停止。

## C. 图表与本问交付

### 探索图

`EXPLORATION_FIGURE` 可以快速生成，用于理解、筛选和调试；要求真实、不误导、基本标签和单位清楚，但无需完整论文证据契约。

### 正式图 / 验证图 / 方法图

只有准备进入正式成果时，才按 `python-visualization-policy.md` 完成：

```text
结论/Requirement
→ 源数据或最终方法
→ Final/Validation Run（数据图）
→ 绘图脚本
→ 图文件
→ 最终尺寸与视觉 QA
```

普通结果表优先 CSV/XLSX + Word 原生表格，不截图冒充表格。

### 本问直接答案

按以下顺序组织：

```text
主答案
→ 关键数字 / 规则
→ 方法摘要
→ 关键验证
→ 不确定性与适用条件
→ 向下一问传递什么
```

内部可记录：

```text
SCIENTIFIC_VALIDITY = PASS | QUALIFIED | FAIL
CONTEST_TASK_COMPLETION = PASS | FAIL
```

内部证据等级和状态不要求机械写进正式论文正文。

### 问题详解

生成或更新 `02_analysis/q{k}_solution.md`，重点确保队员能理解：

- 为什么这样建模；
- 公式和假设怎样进入代码；
- 如何运行；
- 结果为什么可信；
- 哪些条件下可能失效；
- 下一问实际读取哪个正式文件 / 字段 / 参数。
