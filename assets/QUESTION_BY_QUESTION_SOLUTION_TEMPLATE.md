# 逐题深度求解模板

确认、自主范围和停点以 [核心流程](../references/core-workflow.md) 为权威。本模板填写实际内容，不逐项播报或重复审批。
小题/局部验证可以合并为一份紧凑交接，目录规模按核心流程和现有工程决定，不为套模板建立完整赛事项目。

继承 README 的 `agent_mode: SINGLE | THREE_ROLE`；局部任务不追加模式提问。三角色按 [协作规范](../references/multi-agent-collaboration.md) 复用建模手、代码手和论文手，由主代理总控和核验；逐题确认边界不变。

## 问题 {k}：研究与确认

- Requirement / 原题动作、对象、单位、范围：
- 必须给出的直接答案：
- 硬约束、关键假设与尚未解决的歧义：
- 数据结构、正式输入与上游 Final Run：
- 关键困难、当前机制判断和小实验：
- 主路线、baseline/合理参照、必要备用路线及切换条件：
- 选优理由：效果、解释性、稳定性、可行性、成本的实际取舍：
- 关键验证；必要时的灵敏度/创新对照：
- 本问计算、验证、图表与论文材料预算和停止条件（有实际时间约束时）：
- 本问在论文中的主线、必须解释的设计选择与证据缺口：
- 向下一问交付的文件、字段、单位：

确有多条有价值路线时再列表比较；证据不足时不用虚假精确评分。

QUESTION_PLAN_CONFIRMATION：引用本问确认记录；尚未确认时提交本问方案。

## 关键建模决策与推导

在已有 `q{k}_model.md` 或 `q{k}_solution.md` 中维护一份权威记录，论文与蓝图引用其位置；不两份并行维护。

- 决策 ID：`Q{k}-D{nn}`：
- 实际困难与必须回答的问题：
- 合理备选，以及采用/舍弃的依据：
- 题面、数学推导、真实小实验或文献证据位置：
- 关键数学转化、变量/公式含义和使用条件：
- 验证检验了什么失效方式，结果与限制是什么：
- 对主答案、论文论证和下游接口的影响：

只记录影响模型、关键假设或结论的选择，不机械凑备选数量，不把聊天或内部推演逐字转储。失败路线若能解释最终选择，保留其证据与适用边界；无决策价值的调试留在运行工作区。

## 正式实现与验证

- 变量、公式、约束、参数及其代码映射；
- 输入处理规则、运行入口和依赖；
- 真实运行及 FINAL_RUN_ID；必要 Validation Run；
- 直接答案、关键数值/规则、验证结果、不确定性和适用条件；
- 正式下游接口与结果版本。

实现按 [代码规范](../references/python-code-documentation-policy.md)，运行证据按 [运行账本](../references/model-run-ledger.md)，继承项目实际环境。
按 [建模质量门](../references/modeling-quality-gates.md) 分别判断 SCIENTIFIC_VALIDITY 与 CONTEST_TASK_COMPLETION。
灵敏度分析与创新验证采用 [研究 Playbook](../references/modeling-research-playbook.md) 的按需设计。
