# 一次性连续求解模板

**状态：`STAGE_2_ONE_PASS`**

> 用户确认整题路线后即授权连续执行。连续求解不降低真实性和质量要求，但也不把每个调参、绘图或代码修改变成审批步骤。

## 0. 开始条件

- 初始赛题与官方附件安全审计已完成并锁定；
- 影响题意的 `VISUAL_AUDIT_CONFLICT` 已解决；
- 整题主路线、关键假设、重要约束已确认；
- 有价值的备用路线及触发条件尽量提前确认；
- 主 Agent 与子代理复用初始安全审计，不再执行完整或增量安全审计。

---

## 1. 整题模型链

| 问题 | Requirement / 动作 | 核心困难 | 主路线 | 正式输入 | 正式输出 | 向后问接口 |
|---|---|---|---|---|---|---|

同时记录：

- 关键假设及其影响；
- 已确认备用路线和触发条件；
- 尚未解决的数据缺口；
- 可能导致路线重开的风险。

后问从正式文件和上游 Final Run 读取结果，不从聊天或论文文字手抄。

---

## 2. 连续执行中的自主权

在已确认路线和假设边界内，Agent 默认可以自主：

- 做 EDA、诊断实验和 baseline；
- 调整数值算法、初值、容差、超参数和计算预算；
- 修改实现细节、重构代码和处理数值稳定性；
- 进行滚动/分组验证、bootstrap、敏感性、多 seed、上下界或小规模精确解；
- 满足条件后切换到已确认备用路线；
- 生成探索、验证、方法和正式论文候选图；
- 因上游正式结果变化而重跑下游代码、图表和教程。

以下情况才暂停连续执行并与用户沟通：

- 改变原题目标、交付对象或关键现实约束；
- 需要新增/删除会影响结论的关键假设；
- 当前主路线失败且没有已确认备用路线；
- 关键现实数据缺失，不同处理会改变主答案；
- 多条方案证据接近，属于团队偏好或风险偏好决策。

普通技术失败、调参失败、求解器更换或已确认备用路线触发，不单独暂停。

---

## 3. 每个问题的最小闭环

对问题 1 至问题 n 依次完成：

1. 回查 Requirement、对象、单位、边界和指定输出；
2. 识别样本/决策单位与数据结构；
3. 做必要的数据处理、EDA、机制试验和 baseline；
4. 仅在会影响模型/验证/结论时检索现实数据、参数、标准或文献；
5. 定稿变量、公式、假设、目标与现实约束；
6. 按项目现有命名约定实现正式 Python；
7. 真实运行，重要运行登记 Run Ledger；
8. 明确 `FINAL_RUN_ID`；
9. 完成与风险相匹配的独立验证和现实约束检查；
10. 生成必要的结果表和正式图；
11. 直接回答本问；
12. 把正式接口交给后问并继续执行。

如果结果推翻路线且没有可自动触发的已确认备用路线：

```text
ROUTE_REOPEN_REQUIRED
```

---

## 4. 代码与运行

代码入口继承当前项目约定，例如：

```text
03_code/q1/...
03_code/q2/...
03_code/总运行.py  # 或现有稳定入口
```

中文语义名是新建中文项目的可读性偏好；已有英文仓库、CI、包、Notebook 或跨平台工具链保持现有命名。

正式代码至少满足：

- 输入、输出、单位和关键参数清楚；
- 非显然建模逻辑有有效注释；
- 不覆盖 raw 数据；
- 不硬编码个人绝对路径；
- 不含 Skill、聊天、提示词、AI 水印或影响结果的占位；
- 脱离当前会话仍可运行。

每问最终明确：

```text
FINAL_RUN_ID = Rxxx
```

随机或启发式算法记录 seed、重复次数、停止条件和代表结果规则，不只选择最好的一次。

---

## 5. 建模质量门

每问完成前执行 `modeling-quality-gates.md`，重点检查：

- `DATA_STRUCTURE_IDENTIFIED`；
- 数据处理和验证划分是否合理；
- 模型前提与 baseline / 参照；
- 现实约束和单位；
- 关键结论的独立验证；
- 完美指标是否存在泄漏、小样本或挑 seed；
- 聚类/潜状态是否被过度解释；
- 相关是否被误写成因果；
- 启发式解是否被误写成已证明全局最优。

每问分别记录：

```text
SCIENTIFIC_VALIDITY = PASS | QUALIFIED | FAIL
CONTEST_TASK_COMPLETION = PASS | FAIL
```

---

## 6. 图表：探索快，定稿严

`EXPLORATION_FIGURE` 服务于理解、筛选和调试，可以快速生成；不需要完整论文图证据契约，但必须基于真实数据且不误导。

只有进入正式成果的 `PAPER_FIGURE / VALIDATION_FIGURE / METHOD_FIGURE` 才执行完整：

```text
Requirement / 结论
→ 源数据或最终方法
→ Final/Validation Run（数据图）
→ 绘图脚本
→ 图文件
→ A4 最终尺寸 QA
```

普通结果表优先保持可编辑，不截图冒充表格。

---

## 7. 全局收尾

全部问题完成后：

1. 补齐 Requirement / Evidence 骨架；
2. 核对各问 `FINAL_RUN_ID` 与正式跨问接口；
3. 排除 `SUPERSEDED` 结果；
4. 统一数值、舍入、单位、模型名、图表和结论；
5. 冻结 `PAPER_EVIDENCE_BLUEPRINT_READY`；
6. 选编论文核心证据；
7. 生成 AI 内部参考论文；
8. 构建并实际验收内部四包。

连续执行不等于静默吞掉关键风险；也不等于为普通技术细节反复打断用户。
