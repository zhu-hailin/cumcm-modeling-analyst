## 1. 输入完整性检查

确认完整题面、附件、字段说明、单位、输出格式、比赛规则、队伍已有思路、可用软件、时间和成员能力。

缺失内容分阻塞性、可假设、非关键，不得偷偷推测缺失附件。

## 2. 逐句读题

建立题面事实表，识别明确事实、要求动作、输出对象、约束、时间/空间尺度、不确定项和禁止外推范围。

## 3. 建立任务图

对每个子问题记录输入、输出、变量、约束、评价标准、前置问题和后续用途，检查循环依赖、结果泄漏和用后文结论反推前文参数。

## 4. 题型识别

每问可为混合题型：数据描述、评价排序、统计推断、分类聚类、时间序列、数学规划、网络图论、随机过程、机理模型、仿真、多目标、不确定性与风险。

题型识别只用于提出候选方法和可视化计划，不能变成关键词套模板。

## 5. 数据审计

检查样本量、时间跨度、缺失、重复、异常、量纲、编码、时间切分、目标/未来信息泄漏、多源口径、外部数据和参数来源。

## 6. 假设系统

每条假设说明内容、简化对象、合理性、潜在偏差和检查方式。删除与模型无关空话。

## 7. 候选路线

包含真正有差异的低风险基线、推荐主路线和必要增强路线。说明变量、目标、约束、数据、求解、验证、优势、局限和失败条件。

## 8. 首选路线

形成：

`题面事实 → 假设 → 数据 → 变量 → 模型 → 求解 → 结果 → 验证 → 结论`

复杂模型必须有可比较基线。增强方法不贡献结果时应删除。

## 9. 验证系统

### 正确性

单位、量纲、边界、约束、数值范围、小样本人工核算。

### 有效性

基线、留出/滚动验证、历史或外部数据对照、任务匹配指标。

### 稳健性

参数/权重扰动、重采样、场景变化、替代模型、随机算法重复、最坏情况。

正式验证图按 B 级图管理并进入 `VISUALIZATION_MANIFEST.md`。启发式算法依赖最终结论时，应提供真实收敛/重复实验稳定性证据。

## 10. 文献计划

分别检索背景机制、原始模型、参数范围、数据来源、评价指标、验证方法、相似应用和论文表达结构。

正式文献按来源核验政策执行；只有 `DOWNLOAD_VERIFIED` 才能描述为可下载。

## 11. 写作、实现与交接

### Stage 1

只做对理解题目和模型选择有价值的探索。可视化原则上只产生必要 C 级图，不提前生产整套论文图。

### Stage 2

路线确认后：

- 完整 Python 实现并实际运行；
- 每问形成真实可视化计划；
- 生成 A 级核心结果图、必要 B 级验证图和有价值 C 级探索图；
- 中文论文候选图默认中文并执行字体回退；
- 普通结果表输出 CSV/XLSX，论文采用原生表格；
- 维护 `VISUALIZATION_MANIFEST.md`；
- 生成一张真实的整题建模框架图；
- 图表通过 Visual QA 和 A4 尺寸可读性检查；
- 生成逐问 Markdown 教程；
- 基于最终模型、真实结果和 Manifest 选图撰写 `.docx + .pdf` AI 参考论文。

### 内部交付与官方提交

先完成：

```text
INTERNAL_DELIVERY
```

即四个完整内部成果包。队员人工重写论文并完成终稿复审后，正式比赛再读取当年官方最新规则执行：

```text
OFFICIAL_SUBMISSION_EXPORT
```

不得把内部四包直接等同于官方提交格式。
