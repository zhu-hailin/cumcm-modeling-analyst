## 1. 输入完整性检查

确认是否获得完整题面、所有附件、字段说明、单位、输出格式、比赛规则、队伍已有思路、可用软件、时间和成员能力。

缺失内容分为：阻塞性缺失、可假设缺失、非关键缺失。不得偷偷推测缺失附件内容。

## 2. 逐句读题

建立题面事实表，至少识别：明确事实、要求动作、输出对象、约束、时间尺度、空间尺度、不确定项和禁止外推范围。

识别题目动词及验收标准：评价/排序、预测、解释/影响、优化/设计、制定策略、检验、仿真。

## 3. 建立任务图

对每个子问题记录输入、输出、变量、约束、评价标准、前置问题和后续用途。

检查循环依赖、结果泄漏和用后文结论反推前文参数。

## 4. 题型识别

每个子问题可以是混合题型：数据描述与异常识别、综合评价与排序、统计推断与因果解释、分类聚类、时间序列、数学规划、网络图论、随机过程、机理模型、仿真、多目标决策、不确定性与风险。

## 5. 数据审计

检查样本量、时间跨度、缺失、重复、异常、量纲、编码、时间切分、目标泄漏、未来信息泄漏、多源口径、外部数据和参数来源。

输出“数据缺口—影响—替代方案”表。

## 6. 假设系统

每条假设必须说明：假设内容、简化对象、合理性、潜在偏差和检查方式。

删除“假设数据真实可靠”之类与模型无关的空话。

## 7. 候选路线

至少包含：低风险基线、推荐主路线、条件允许时的增强路线。

每条路线说明：对应子问题、核心思想、变量、目标、约束、数据要求、求解步骤、验证、优势、局限、失败条件、推荐指数和置信度。

避免伪候选：不能只换预测器、权重法或求解器就算新路线。

## 8. 首选路线

形成闭环：

`题面事实 → 假设 → 数据 → 变量 → 模型 → 求解 → 结果 → 验证 → 结论`

复杂模型必须有可比较基线。增强模型没有显著贡献时，退回简单模型。

## 9. 验证系统

### 正确性

单位、量纲、边界、约束、数值范围、小样本人工核算。

### 有效性

基线比较、留出或滚动验证、历史案例或外部数据对照、指标与任务一致。

### 稳健性

参数和权重扰动、数据删除或重采样、场景变化、替代模型、随机算法多次运行、最坏情况。

不要只写“结果稳定”，必须给出扰动范围、指标变化和判断阈值。

验证图、误差图、敏感性图、鲁棒性图等默认由 Python 根据真实数据或模型结果生成。用户未明确要求时，不调用 AI 图片生成工具。

## 10. 文献计划

分别检索：背景机制、原始模型、参数范围、数据来源、评价指标、验证方法、相似应用和优秀论文表达结构。

所有正式参考文献链接必须按 [source-verification-policy.md](source-verification-policy.md) 实际核验。只有 `DOWNLOAD_VERIFIED` 才能描述为“可下载”。

## 11. 写作、实现与交接

写作主线应让评阅者沿：

`摘要 → 模型总览图 → 关键结果图表 → 验证 → 结论`

快速复述工作。

### 第一阶段

第一阶段只输出数据输入、清洗规则、模块输入输出、公式、参数范围、算法类别、预期中间结果、图表需求、验收测试和回退方案，不生成最终可执行代码，也不生成最终参考论文。

### 第二阶段

路线确认后：

- 把锁定方案落实为完整 Python 实现；
- 环境允许时实际运行关键入口；
- 生成真实图表、表格和中间结果；
- 修复明显错误；
- 生成逐问 Markdown 教程；
- 基于最终模型、真实 Python 结果、真实图表和已核验参考文献，认真撰写最终数学建模参考论文；
- 最终参考论文实际生成 `.docx + .pdf`，用户提供模板时按模板排版。

“参考论文”是 AI 本次撰写的成果论文；“参考文献”是论文引用的外部证据。二者不得混用。

外部参考文献下载失败不能成为不写最终参考论文的理由。若重要链接有问题，必须按来源核验政策反馈用户并记录。

### 文档格式

普通 AI 文本交付统一使用 UTF-8 Markdown，包括教程、README、AI 使用说明、建模决策、路线变更、文献账本、数据来源、链接核验、问题反馈和环境说明。

**最终参考论文 `.docx/.pdf` 是 Markdown-only 规则的明确例外。**
