# INTERNAL_DELIVERY：内部四包

## 目标

用户要求完整内部交付，且全部问题、Final Run、关键建模质量门、正式图表、公式和一致性检查完成后，生成：

```text
题目详解.zip
参考论文.zip
源码.zip
其他.zip
```

它们用于队内学习、复核、复现、人工写论文和赛后留档，**不等于官方提交文件**。

本地正式目录是主成果，ZIP 是筛选副本。打包后不得删除原文件。
只请求源码、论文或某一问成果时，只组织并验收所请求部分，不强制补齐四包；对应阶段未完成则明确交付范围，不标记全题 INTERNAL_DELIVERY_COMPLETE。已有队员终稿可直接复审和官方导出，四包不是必经步骤。

---

## 1. 题目详解.zip

每问教程重点串起：

```text
题意 / Requirement
→ 数据与结构
→ 为什么选择当前路线
→ 变量、公式和假设
→ 源码入口与运行命令
→ FINAL_RUN_ID
→ 结果与验证
→ 现实约束与限制
→ 向后问正式接口
```

教程帮助队员理解和接手，不要求把所有 Run Ledger、调试过程和内部状态重复抄一遍。

## 2. 参考论文.zip

默认包含：

```text
参考论文/
├─ 数学建模参考论文.docx
└─ 数学建模参考论文.pdf
```

必须：

- 基于冻结的 `PAPER_EVIDENCE_BLUEPRINT_READY`；
- 使用最终模型、Final/Validation Run 和正式图表；
- 图、表、数字、模型名和结论一致；
- Word/PDF 公式正确；
- 文献和数据来源真实可核验；
- 文件真实存在、非空、可打开；
- 通过最终一致性检查。

> AI 参考论文必须由队员理解、核查并人工重写，禁止直接提交。

## 3. 源码.zip

目录结构继承当前项目实际约定，不为了打包强制改中文/英文文件名。推荐职责：

```text
源码/
├─ README.md
├─ requirements.txt
├─ 主运行入口（项目当前约定）
├─ common/            # 实际需要时
├─ q1/
├─ q2/
├─ data/              # 允许分发且复现所需
├─ results/           # 必要结果与正式图表
└─ VISUALIZATION_MANIFEST.md
```

包含：

- 每问真实主入口和实际需要的辅助模块；
- 总入口/复现入口；
- 有效 docstring 与关键建模注释；
- 所有进入论文的绘图脚本；
- 必要验证脚本；
- 复现 Final Run 所需且允许分发的数据、依赖、配置和结果。

默认不包含：

- `99_temp/`；
- 无用旧代码、缓存和过期 Run；
- 无关 Skill 提示词、聊天记录和 AI 水印（必要披露与来源信息按下述例外保留）；
- `AI_COMMUNICATION_ONLY`、`SECURITY_AUDIT_ONLY` 图；
- 许可不允许再分发的外部数据。

清理无关水印/聊天不包括依法或当年规则需要保留的 AI 使用声明、引用、版权和许可证。总复现入口仅包含已完成并获确认的模型链，不启动未经确认的后问。

源码必须能在目标环境真实运行。外部数据不能再分发时，提供正式获取说明和处理脚本。

## 4. 其他.zip

用于内部复核和留档，可以包括：

```text
其他/
├─ AI使用说明/
├─ 建模分析/
├─ 运行与实验/

├─ 数据来源与处理/
```

不要为了目录“完整”复制无用文件。同一运行、来源和蓝图事实尽量保留一个权威版本，其他材料引用它。

## 6. ZIP 完整性：必须真实解压

每个 ZIP 必须：

1. 检查源文件存在且非 0 字节；
2. 执行 ZIP CRC/entry 检查；
3. **实际解压到临时目录**；
4. 从解压副本检查路径、文件数量、大小和可读性；
5. 实际解析 PDF 页数/页面内容及 DOCX 正文，检查 Python 语法和关键结果文件；零字节论文、空正文和伪 PDF 不能通过；
6. 从本次选定源文件生成包外清单（路径、大小、SHA-256），对账关键成果；不能从收到的 ZIP 自己生成清单后声称版本已核验；
7. 验收后再清理临时目录。

可使用：

```bash
python scripts/delivery_check.py 06_submission/internal_delivery/*.zip
```

默认 auto 会把名为“参考论文.zip”的包按 reference-paper 检查，要求非空 DOCX 和 PDF；其他命名应显式使用 --profile reference-paper。
包外 JSON 清单格式为 {"files": [{"path": "参考论文/数学建模参考论文.pdf", "size": 123, "sha256": "实际64位hash"}]}，通过 --manifest 清单.json 对单个 ZIP 检查。关键文件还可用重复的 --require 包内路径指定。
PDF 解析需要 pypdf；依赖缺失明确失败，不回退到文件头判断。空 __init__.py 属于允许的包初始化文件，关键成果为空则失败。

工具输出 MECHANICAL_ONLY：只负责机械完整性，不能代替科学正确性、公式渲染、视觉 QA、源码真实复现或 Final Run 对账。PDF 拒绝没有文字/绘制操作的空页，但有绘制操作仍可能因白色、透明或裁切不可见，必须另做视觉 QA。图表/XLSX 等未被工具实际解析的格式须按对应规范另行验证，不得声称工具已全部验收。

不能只看 ZIP 文件存在、只看源目录，或只跑 `unzip -t` 就声称用户一定能正常使用。

失败标记：

```text
DELIVERY_INTEGRITY_FAILED
```

## 7. 与官方提交的边界

以下是使用内部参考稿时的一种顺序，不是对已有队员终稿补齐四包的要求：

```text
INTERNAL_DELIVERY_COMPLETE
→ 队员理解、核查并人工重写论文
→ FINAL_PAPER_AUDIT
→ 核验当年官方、赛区和提交系统规则
→ OFFICIAL_SUBMISSION_EXPORT
```

内部四包用于比赛协作，不自动等于可以上传的官方材料。
