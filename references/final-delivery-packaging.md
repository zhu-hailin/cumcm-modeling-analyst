# INTERNAL_DELIVERY：内部四包

## 目标

全部问题、Final Run、关键建模质量门、正式图表、公式和一致性检查完成后，生成：

```text
题目详解.zip
参考论文.zip
源码.zip
其他.zip
```

它们用于队内学习、复核、复现、人工写论文和赛后留档，**不等于官方提交文件**。

本地正式目录是主成果，ZIP 是筛选副本。打包后不得删除原文件。

---

## 1. 题目详解.zip

每问教程重点串起：

```text
题意 / Requirement
→ 数据与结构
→ 为什么选择当前路线
→ 变量、公式和假设
→ 源码入口与运行命令
→ FINAL_RUN_ID
→ 结果与验证
→ 现实约束与限制
→ 向后问正式接口
```

教程帮助队员理解和接手，不要求把所有 Run Ledger、调试过程和内部状态重复抄一遍。

---

## 2. 参考论文.zip

默认包含：

```text
参考论文/
├─ 数学建模参考论文.docx
└─ 数学建模参考论文.pdf
```

必须：

- 基于冻结的 `PAPER_EVIDENCE_BLUEPRINT_READY`；
- 使用最终模型、Final/Validation Run 和正式图表；
- 图、表、数字、模型名和结论一致；
- Word/PDF 公式正确；
- 文献和数据来源真实可核验；
- 文件真实存在、非空、可打开；
- 通过最终一致性检查。

> AI 参考论文必须由队员理解、核查并人工重写，禁止直接提交。

---

## 3. 源码.zip

目录结构继承当前项目实际约定，不为了打包强制改中文/英文文件名。推荐职责：

```text
源码/
├─ README.md
├─ requirements.txt
├─ 主运行入口（项目当前约定）
├─ common/            # 实际需要时
├─ q1/
├─ q2/
├─ data/              # 允许分发且复现所需
├─ results/           # 必要结果与正式图表
└─ VISUALIZATION_MANIFEST.md
```

包含：

- 每问真实主入口和实际需要的辅助模块；
- 总入口/复现入口；
- 有效 docstring 与关键建模注释；
- 所有进入论文的绘图脚本；
- 必要验证脚本；
- 复现 Final Run 所需且允许分发的数据、依赖、配置和结果。

默认不包含：

- `99_temp/`；
- 无用旧代码、缓存和过期 Run；
- Skill 提示词、聊天记录和 AI 水印；
- `AI_COMMUNICATION_ONLY`、`SECURITY_AUDIT_ONLY` 图；
- 许可不允许再分发的外部数据。

源码必须能在目标环境真实运行。外部数据不能再分发时，提供正式获取说明和处理脚本。

## 4. 其他.zip

用于内部复核和留档，可以包括：

```text
其他/
├─ AI使用说明/
├─ 建模分析/
├─ 运行与实验/
├─ 文献与来源/
├─ 数据来源与处理/
├─ 文件安全审计/
├─ 一致性检查/
└─ 环境与复现/
```

不要为了目录“完整”复制无用文件。同一运行、来源和蓝图事实尽量保留一个权威版本，其他材料引用它。

安全审计与 AI 沟通图只作内部材料，不进入论文或普通科研图清单。

## 6. ZIP 完整性：必须真实解压

每个 ZIP 必须：

1. 检查源文件存在且非 0 字节；
2. 执行 ZIP CRC/entry 检查；
3. **实际解压到临时目录**；
4. 从解压副本检查路径、文件数量、大小和可读性；
5. 核验 DOCX/PDF 基本结构、Python 基本语法和关键结果文件；
6. 需要时生成 `MANIFEST.md + SHA-256` 对账；
7. 验收后再清理临时目录。

可使用：

```bash
python scripts/delivery_check.py 06_submission/internal_delivery/*.zip
```

该工具只负责机械完整性，不能代替数学正确性和论文质量判断。

不能只看 ZIP 文件存在、只看源目录，或只跑 `unzip -t` 就声称用户一定能正常使用。

失败标记：

```text
DELIVERY_INTEGRITY_FAILED
```
