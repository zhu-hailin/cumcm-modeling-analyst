# 最终交付与 ZIP 打包规范

## 目标

第二阶段完成整题建模、代码实现、运行验证和教学材料后，进入 `FINAL_DELIVERY`。最终交付必须整理为四个独立 ZIP，避免把教程、论文、源码和过程文件混在一起。

最终应优先只交付：

```text
题目详解.zip
参考论文.zip
源码.zip
其他.zip
```

如果当前环境具备文件创建与压缩能力，必须实际生成 ZIP，而不是只描述目录。如果环境确实不能创建 ZIP，才允许按完全相同的目录结构输出待打包文件，并明确说明限制。

子问题数量、赛题编号和目录数量必须按实际题面调整，不固定为三问。

所有视觉与文档产出必须同时遵循 [output-artifact-policy.md](output-artifact-policy.md)。

---

## 1. 题目详解.zip

用途：让没有参与全部建模过程的队员能够结合源码真正学会整道题，而不是只看到最终公式和结论。

推荐结构：

```text
题目详解/
├── 00_赛题总览.md
├── 问题1/
│   └── 问题1_完整教程.md
├── 问题2/
│   └── 问题2_完整教程.md
├── 问题3/
│   └── 问题3_完整教程.md
└── ...按实际子问题继续
```

该 ZIP 中由 AI 创建的文本型内容只允许使用 UTF-8 Markdown（`.md`）。不得额外生成 PDF、DOCX、TXT、HTML 等重复教程版本，除非用户或官方规则明确要求。

每一问的教程必须至少包含：

1. 题目要求翻译成建模任务；
2. 本问输入、输出、变量、单位和约束；
3. 为什么选择当前模型，以及为什么没有采用主要备选方案；
4. 从直觉到数学表达的完整推导；
5. 关键公式及所有符号解释；
6. 数据如何进入模型；
7. 算法完整执行流程；
8. 与前一问、后一问的结果传递；
9. 对应源码路径，例如 `源码.zip/赛题A/问题1/src/main.py`；
10. 关键源码模块、函数或类分别负责什么；
11. 如何运行代码，包括入口、参数、依赖和命令；
12. 程序会生成哪些表格、图片和中间结果；
13. 每张关键图和关键表应该如何解释；
14. 如何检查结果是否合理；
15. 常见错误、调参位置和失败时如何排查；
16. 队员在论文中应如何表达本问。

教程必须和最终源码一致。不得出现“教程说使用模型 A，但源码实际运行模型 B”的情况。代码路径、文件名、参数名和输出名必须可以对应。

`00_赛题总览.md` 应说明整题逻辑链、各问依赖、最终主路线，以及四个 ZIP 之间如何配合使用。

Markdown 必须 AI-friendly：标题层级稳定、公式使用 LaTeX、代码块标注语言、路径和函数名使用反引号，核心模型不能依赖图片才能理解。

## 2. 参考论文.zip

用途：集中保存最终真正使用、重点参考或值得队伍阅读的论文原文件。

### 强制内容限制

该 ZIP 内只允许出现论文文件：

- `.pdf`
- `.doc`
- `.docx`

不得放入 Markdown、TXT、网页快照、图片、代码、数据表、文献账本或 AI 总结。

可按实际子问题建立目录，例如：

```text
参考论文/
├── 公共/
├── 问题1/
├── 问题2/
├── 问题3/
└── ...
```

论文文件名应尽量可辨识，例如：

```text
Q1_01_作者_年份_论文简称.pdf
Q2_02_作者_年份_论文简称.docx
```

### 真实性与版权边界

- 只放实际获得的真实论文原文件；
- 不得伪造 PDF、Word 文件或把摘要文本伪装成论文；
- 只收录用户提供、公开合法可获取、或当前工具环境合法取得的文件；
- 若论文只能核验元数据、摘要或网页信息，不能生成一个假的论文文件；
- 无法取得原文件但仍值得记录的文献，其题名、链接、核验层级和用途应记录到 `其他.zip`，不得破坏“参考论文.zip 只放论文文件”的规则。

---

## 3. 源码.zip

用途：保存最终可运行的 Python 实现、运行所需资料和代码产生的结果文件。

必须按“赛题编号/问题编号”组织；赛题编号按用户最终选择的实际赛题填写，例如 A、B、C，不得固定写 A。

推荐结构：

```text
源码/
├── README.md
├── requirements.txt
├── 公共/
│   ├── src/
│   ├── data/
│   └── utils/
└── 赛题A/
    ├── 问题1/
    │   ├── src/
    │   │   ├── main.py
    │   │   └── ...
    │   ├── data/
    │   └── outputs/
    │       ├── figures/
    │       ├── tables/
    │       └── intermediate/
    ├── 问题2/
    │   └── ...
    ├── 问题3/
    │   └── ...
    └── ...按实际子问题继续
```

### 必须包含

- 最终实际采用方案的全部 Python 代码；
- 公共数据清洗、工具函数和共享模块；
- `requirements.txt` 或等价依赖说明；
- 可复现实验所必需的数据或处理后数据（在许可和文件大小允许的情况下）；
- Python 生成的关键图片；
- Python 生成的关键表格；
- 必要的中间结果和参数文件；
- 根目录 `README.md`，说明环境、入口、运行顺序和各目录用途。

### 图表强制规则

- 用户未明确要求 AI 生成/设计图片时，禁止使用任何 AI 图片生成工具；
- 数学建模统计图、预测图、误差图、热力图、路径图、网络图、敏感性图、Pareto 图、仿真图等默认全部由 Python 生成；
- 图表必须来自真实数据、模型结果或确定结构，不得生成看似“实验结果”的虚构图片；
- 图表必须专业、简洁、论文可用；标题、坐标、单位、图例和必要注释完整；
- 不使用无意义 3D、渐变、发光、装饰背景或过量颜色；
- 不把过多曲线、标记、注释和不相关结论堆在一张图里；
- 每张图必须有明确用途，并能从教程定位到对应 Python 文件和输出文件；
- 当前环境允许时，必须实际检查图像是否存在乱码、截断、遮挡、重叠或空白。

### 代码质量要求

- 第二阶段最终交付代码必须是可运行实现，不得只给伪代码；
- 若当前环境允许执行 Python，必须实际运行关键入口并修复明显错误；
- 每一问应存在明确入口，或在 README 中明确统一入口如何选择问题编号；
- 随机算法必须固定或记录随机种子；
- 图表和数据文件名应稳定、可追踪并与教程对应；
- 不得把无关缓存、虚拟环境、IDE 配置、临时下载文件或重复大文件塞入 ZIP。

## 4. 其他.zip

用途：保存不属于教程、论文原件和源码本体，但对比赛复核、交接和合规有价值的文件。

推荐结构：

```text
其他/
├── AI使用说明/
│   └── AI_USAGE_LOG.md
├── 建模决策/
│   ├── MODELING_DECISION_STATE.md
│   └── 路线变更记录.md
├── 文献与来源/
│   ├── LITERATURE_LEDGER.md
│   ├── 数据来源清单.md
│   └── 未取得原文的参考资料.md
├── 环境与复现/
│   └── 运行环境说明.md
└── 其他必要文件/
```

AI 自行创建的所有文本型文件统一使用 UTF-8 Markdown（`.md`）。除非用户或官方规则明确要求，不生成 PDF、DOCX、DOC、TXT、HTML 等重复说明文件。

可包含但不限于：

- AI 使用说明与人工复核记录；
- 建模决策状态；
- 路线切换或修改记录；
- 文献证据账本；
- 官方数据来源清单；
- 无法取得 PDF/Word 原文但已核验的参考资料信息；
- 软件版本、环境和复现说明；
- 题面要求的辅助说明文件；
- 其他无法合理归入前三个 ZIP 的必要材料。

不得把最终 Python 源码主体放入 `其他.zip`，也不得把论文 PDF/Word 重复复制进该包。

---

## 最终打包前检查

必须逐项检查：

- 是否实际生成四个 ZIP；
- ZIP 名称是否严格为 `题目详解.zip`、`参考论文.zip`、`源码.zip`、`其他.zip`；
- 子问题数量是否按实际题面，而不是机械固定三问；
- 每一问是否都有对应 `.md` 教程；
- 教程是否准确引用最终源码路径和输出文件；
- 源码是否按赛题和问题编号分类；
- Python 代码是否完整、可运行或已明确记录无法运行的客观原因；
- 用户未明确要求时是否完全未调用 AI 图片生成工具；
- 关键图表是否均由 Python 或真实输入图像产生，并进入对应 `outputs`；
- Python 图表是否专业、克制、清晰、可复现；
- 除真实参考论文原件外，AI 创建的文本型文档是否全部为 `.md`；
- `参考论文.zip` 是否只含 `.pdf/.doc/.docx`；
- 是否存在虚构、损坏或只有标题没有正文的“论文文件”；
- AI 使用说明是否进入 `其他.zip`；
- 是否避免重复文件、缓存、临时文件和不必要的大文件；
- 四个 ZIP 解压后是否都能独立理解其用途。

只有通过上述检查后，才能将状态标记为 `FINAL_DELIVERY`。
