# 联网研究模式与旧题盲测防泄漏政策

## 目标

本 Skill 既用于正式数学建模比赛，也经常用于历年旧题测试模型与 Skill 自身能力。

如果旧题测试时允许 AI 直接搜索题名、题号或题面原文，就可能命中历年优秀论文、现成解答、博客、代码仓库或复盘文章，导致 **答案泄漏（answer leakage）**，从而无法判断模型究竟是独立解题，还是在复述已存在答案。

因此，新赛题在第一次外部联网检索前，必须明确当前搜索模式。

---

# 1. 开题时的搜索模式选择

如果用户没有提前说明，在第一次外部联网搜索之前必须询问：

> 这是 **A. 实战赛题**，还是 **B. 旧题盲测**？

只需询问一次。

如果用户已经明确说“正式比赛 / 当前比赛 / 实战”或“旧题测试 / 历年题 / benchmark / 盲测”，直接进入对应模式，不重复询问。

搜索模式与后续“逐题深度求解 / 一次性完整求解”是两个不同维度，不得混淆。

---

# 2. A 模式：实战研究模式

状态：`LIVE_RESEARCH_MODE`。

目标是在正式比赛中最大化正常研究能力，**不得因为防旧题泄漏而削弱 AI 的联网研究能力**。

允许正常搜索：

- 学术论文、教材、综述和原始模型文献；
- 官方统计、政府数据、行业数据、公开数据集；
- 参数来源、标准、政策、技术规范；
- 相似领域案例和应用研究；
- 算法文档、Python 库文档、求解器资料；
- 与题目实体、行业背景、地区、时间、设备、物理过程等直接相关的信息；
- 为理解题意、补充外部数据、建立模型和验证结果所需的其他正常研究资料。

允许搜索包含题目中的实体或具体背景，只要目的是真实研究，而不是寻找别人已经完成的整题答案。

仍然禁止：

- 主动搜索“本题答案 / 本题完整解答 / 本题论文成品 / 本题源码成品”；
- 主动寻找当前比赛期间其他队伍泄露的答案、代码或论文；
- 把搜索到的他人完整解题方案冒充自己的独立建模过程。

如果正常研究中偶然发现疑似当前比赛的他人完整答案，不应以其作为直接解题模板，应回到原题、数据和独立模型证据完成分析。

---

# 3. B 模式：旧题盲测模式

状态：`BLIND_BENCHMARK_MODE`。

目标是尽可能测量：

`模型能力 + Skill 解题流程能力`

而不是测量 AI 搜索和复述历史答案的能力。

## 严禁用于联网搜索的题目标识

在独立求解完成前，不得使用以下信息作为搜索关键词或组合线索：

- 竞赛年份 + 题号；
- 赛题完整题名；
- 题面原句或大段原文；
- 能唯一定位赛题的特殊措辞；
- 附件原始文件名；
- 赛题中特有的实体组合、特殊常数或数据片段，如果它们足以定位该旧题；
- “某年 CUMCM A/B/C/D 题”；
- “历年优秀论文 / 获奖论文 / 解题思路 / 答案 / 源码”等与该题直接绑定的搜索。

## 严禁主动获取

独立求解完成前不得主动读取或下载：

- 该旧题的优秀论文；
- 官方赛后讲评中的完整解法；
- 博客、知乎、CSDN、公众号、小红书等现成解答；
- GitHub / Gitee 上针对该题的完整源码；
- 网盘中的成品论文或答案；
- 任何可以直接暴露该题具体模型路线、最终结果或代码结构的历史材料。

---

# 4. 旧题盲测仍然允许联网研究

盲测模式 **不是断网模式**。

AI 仍可搜索通用研究资料，但查询必须尽量去题目标识化、抽象化。

允许例如：

- 某类预测问题常用时间序列检验；
- 某类车辆路径问题的标准数学模型；
- 某物理过程的机理方程；
- TOPSIS / DEA / ARIMA / MILP / NSGA-II 等原始或权威方法资料；
- Python 库官方文档；
- 某行业的一般参数范围及权威来源；
- 国家统计局、政府、标准组织等公开基础数据；
- 与题目所需外部数据对应的原始官方数据源；
- 与赛题不绑定的同类学术应用研究。

## 查询改写原则

把：

`2023 CUMCM A题 XX问题 解法`

改写成：

`该问题所属的一般领域 + 需要解决的数学任务 + 方法/数据需求`

例如，只搜索：

`多目标车辆路径 时间窗 建模 方法`

而不是搜索：

`2022 数学建模国赛 B题 车辆路径答案`。

---

# 5. 搜索结果意外命中历史答案时

即使查询已经去题目标识化，搜索结果仍可能意外命中同一道旧题。

一旦识别到页面可能是：

- 当前盲测题的历史优秀论文；
- 当前盲测题完整解答；
- 当前盲测题源码；
- 明确给出该题逐问模型和最终结果的复盘；

必须：

1. 立即停止继续读取该页面；
2. 不摘录其模型、数值、公式、路线和代码；
3. 标记 `ANSWER_LEAKAGE_DETECTED`；
4. 明确告知用户本次严格盲测已经存在污染风险；
5. 不得继续把后续结果描述为“完全独立盲测结果”。

如果用户追求严格 benchmark，应建议换一个未暴露答案的新会话/上下文重新测试。

AI 不得声称自己已经“忘记”刚看到的答案后继续当作纯盲测。

---

# 6. 盲测完成后的答案对照模式

只有在以下条件满足后，才能进入：

`POST_SOLUTION_COMPARISON`

条件：

- 全部问题已经独立求解完成；
- 最终模型、代码和主要结果已经固定；
- 用户明确同意进行历史答案对照。

此时允许搜索和阅读：

- 历年优秀论文；
- 官方讲评；
- 公开历史解答；
- 历史代码和复盘资料。

用途只能是比较：

- 我们独立路线与历史路线有哪些相同/不同；
- 哪些地方做得更好；
- 哪些地方存在明显不足；
- 是否遗漏了重要模型或验证；
- Skill 在该旧题上的真实独立表现如何。

必须清楚区分：

- **Blind Solution**：看到历史答案之前独立得到的内容；
- **Post-hoc Comparison**：看到历史答案之后的比较和评价。

不得把答案对照阶段发现的方法、结果或代码回写成“原本就独立想到”的内容。

如果用户要求在对照后继续改进方案，应明确标记这些改进为 `POST_HOC_IMPROVEMENT`，不能再用于评价原始盲测能力。

---

# 7. 与文献核验规则的关系

本政策决定“能搜索什么”。

[source-verification-policy.md](source-verification-policy.md) 决定“搜到后怎样核验和引用”。

在旧题盲测模式中，本政策优先于一般文献检索需求：即使某篇历史优秀论文是真实、高质量、可下载，也不能在独立求解完成前读取，因为它会造成答案泄漏。

正式比赛模式下，继续完整执行文献、数据、参数和链接真实性核验规则。
