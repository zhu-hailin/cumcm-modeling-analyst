# 图表与文档输出规范

本规范适用于赛题分析、第二阶段求解、Python 实现、教程编写、最终论文和四包交付。

## 1. 图片生成工具使用边界

默认禁止使用任何 AI 图片生成工具或文生图工具生成数学建模过程中的图片、图表、流程示意或结果展示。

只有用户明确提出需要 AI 生成、设计、绘制或风格化图片时，才允许使用图片生成工具。

数学建模中的统计图、预测图、误差图、热力图、相关性图、敏感性图、路径图、网络图、Pareto 前沿、仿真图和模型诊断图等，默认必须由 Python 根据真实数据、模型结果或确定结构生成。

不得使用生成式图片替代真实统计结果、实验结果、工程结构或地图结果。

## 2. Python 图表质量标准

Python 图表目标是“比赛论文可直接使用”，但专业不等于复杂。

必须做到：

- 图型与数据关系匹配；
- 标题、坐标轴、单位、图例和必要注释完整；
- 字号、线宽、点大小、留白和画布比例适合论文；
- 输出分辨率满足论文或答辩使用；
- 同类图保持稳定视觉规范；
- 颜色数量克制并考虑打印/投影可读性；
- 必要时使用误差条、置信区间、基线、阈值或关键点标记；
- 文件名稳定、语义明确、可从教程追溯源码；
- 图中数据可由源码与输入/中间结果复现。

禁止：

- 无意义 3D；
- 渐变、发光、装饰背景；
- 过量颜色、曲线、阴影、标记和注释；
- 将多个弱相关结论强塞进一张图；
- 为凑数量生成无用图表。

若一张图无法用一句话说明“它要展示或验证什么”，通常不应生成。

## 3. 图表实现要求

- 当前环境允许时必须实际运行绘图代码；
- 检查乱码、截断、遮挡、重叠和空白图；
- 绘图逻辑应清晰可复现；
- 教程必须说明关键图表源码路径、输入、输出文件名和解读方式；
- 最终参考论文中引用的图表必须来自最终 Python 输出。

## 4. 文档格式总规则

AI 自行创建的普通文本型文档统一使用 UTF-8 Markdown（`.md`），包括：

- 题目总览与逐问教程；
- 源码 README 与运行说明；
- AI 使用说明；
- 人工复核说明；
- 建模决策状态；
- 路线变更记录；
- 文献证据账本；
- 数据来源清单；
- 参考文献链接核验；
- 文献问题反馈；
- 环境与复现说明；
- 其他过程性、教学性、审查性说明文件。

默认不为这些文件生成 PDF/DOCX/TXT/HTML 重复版本。

## 5. 唯一重要例外：最终参考论文

AI 针对本次赛题认真撰写的最终数学建模参考论文，不受 Markdown-only 限制。

最终参考论文默认必须生成：

- `.docx`
- `.pdf`

原因：它属于正式成果论文，而不是普通说明文档。

如果用户提供竞赛论文模板或官方 Word 格式，应按模板生成 Word 并导出一致的 PDF。

注意：

- “参考论文”是 AI 自写的最终成果；
- “参考文献”是论文中引用的外部资料；
- 不得将两者混为一谈；
- 不得因为外部参考文献无法下载，就禁止 AI 生成最终参考论文。

## 6. AI-friendly Markdown 标准

Markdown 应便于人和后续 AI/Coding Agent 使用：

- 稳定的 `# / ## / ###` 层级；
- 开头说明用途、对应问题和源码路径；
- 公式用标准 LaTeX；
- 代码块标明语言；
- 路径、函数、参数和字段使用反引号；
- 表格不过度复杂；
- 长流程优先使用列表或 Mermaid；
- 假设、风险、待核验项分节；
- 核心模型不能依赖图片才能理解；
- 文档中的路径、运行命令和输出必须与最终交付一致。

## 7. 最终检查

进入 `FINAL_DELIVERY` 前检查：

- 用户未要求时是否完全未调用 AI 图片生成工具；
- 建模图表是否由 Python 或真实输入图像产生；
- Python 图表是否专业、清晰、可复现且不过度堆叠；
- 是否清理无价值或重复图表；
- 普通 AI 文档是否均为 `.md`；
- 最终参考论文是否按例外规则生成 `.docx + .pdf`；
- 论文中的图表是否来自真实 Python 输出；
- Markdown 是否具备清晰层级、LaTeX 公式、代码语言标记和稳定路径引用。
