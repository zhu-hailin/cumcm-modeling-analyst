# 图表与文档输出规范

本规范适用于赛题分析、第二阶段求解、Python 实现、教程编写和最终四包交付。

## 1. 图片生成工具使用边界

默认禁止使用任何 AI 图片生成工具或文生图工具生成数学建模过程中的图片、图表、流程示意或结果展示。

只有用户**明确提出需要 AI 生成、设计、绘制或风格化图片**时，才允许使用图片生成工具。用户未明确提出时，即使当前环境提供图片生成能力，也不得主动调用。

数学建模中的下列视觉产物默认必须由 Python 根据真实数据、模型结果或确定的结构生成：

- 折线图、散点图、柱状图、箱线图、直方图；
- 热力图、相关性图、残差图、误差图；
- 时间序列预测图、置信区间图；
- 敏感性分析、鲁棒性分析、参数扫描图；
- 路径图、网络图、调度图、空间分布图；
- 聚类、降维、分类边界和模型诊断图；
- Pareto 前沿、多目标权衡图；
- 仿真结果图、状态变化图；
- 由模型结果形成的流程或结构图，只要 Python 能清晰生成。

不得为了视觉效果使用生成式图片替代真实数据图，也不得生成看起来像统计结果、实验结果、工程结构或地图结果但没有真实数据依据的图片。

## 2. Python 图表质量标准

Python 图表目标是“比赛论文可直接使用”，但专业不等于复杂。每张图必须首先服务于一个明确结论或验证目的。

### 必须做到

- 图表类型与数据关系匹配，不为炫技选择错误图型；
- 标题、坐标轴、单位、图例和必要注释完整；
- 中文或英文命名在同一张图内保持一致；
- 字号、线宽、点大小、留白和画布比例适合论文阅读；
- 输出分辨率足够用于论文或答辩，优先保存高质量 PNG，并在适合时同时保存 SVG/PDF 等矢量格式；
- 同类图保持稳定的视觉规范，便于跨问题比较；
- 颜色数量克制，优先保证打印、投影和色觉差异下仍可区分；
- 必要时使用误差条、置信区间、基线、阈值线或关键点标记；
- 文件名稳定且语义明确，并能从教程定位到生成它的 Python 文件；
- 图中展示的数据必须可以从源码、输入数据或中间结果复现。

### 禁止过度设计

- 不为了“高级感”同时叠加过多曲线、颜色、阴影、标记、注释和辅助线；
- 不使用无意义的 3D 图、渐变、发光、装饰背景或视觉特效；
- 不把多个关系不强的结论强行塞入一张图；
- 不使用无法解释含义的颜色；
- 不让标题、图例、数据标签互相遮挡；
- 不用高信息密度掩盖模型本身解释不足的问题；
- 不生成对论文结论没有帮助的“凑数量”图片。

若一张图不能用一句话说明“它要证明或展示什么”，通常不应生成。

## 3. 图表实现要求

- 视觉结果必须对应实际 Python 代码，而不是仅描述“应绘制某图”；
- 当前环境允许执行 Python 时，应实际运行绘图代码并检查图像是否可读、是否存在截断、乱码、重叠或空白图；
- 图表生成逻辑应尽量封装为可复用函数，但不要为了抽象而制造复杂框架；
- 数据处理和绘图职责应保持清晰，重要绘图数据可以保存为 CSV/XLSX 等结果文件供复核；
- 教程必须说明关键图表的源码路径、输入、输出文件名和如何解读。

## 4. 文本型文档统一使用 Markdown

除真实参考论文原件外，AI 在本 Skill 中自行创建的文本型文档必须统一使用 UTF-8 Markdown（`.md`）。

包括但不限于：

- 题目总览和逐问教程；
- 源码运行说明；
- AI 使用说明；
- 人工复核说明；
- 建模决策状态；
- 路线变更记录；
- 文献证据账本；
- 数据来源清单；
- 未取得原文的参考资料清单；
- 环境与复现说明；
- 其他由 AI 编写的说明性、教学性、审查性或过程性文档。

默认不得为这些内容额外生成 `.pdf`、`.docx`、`.doc`、`.txt`、`.html` 等重复版本。只有用户明确要求某种额外格式，或竞赛官方明确要求该格式时，才允许例外。

`参考论文.zip` 中的真实论文原文件仍按其实际格式保留，可为 `.pdf`、`.doc`、`.docx`；这不属于 AI 自行生成文档。

## 5. AI-friendly Markdown 标准

Markdown 不只是给人阅读，也应便于后续 AI、Coding Agent 和队员检索、引用和继续修改。

必须尽量遵循：

- 使用稳定、语义明确的 `# / ## / ###` 标题层级；
- 每个文件开头说明用途、对应赛题/问题以及相关源码路径；
- 公式使用标准 LaTeX，变量首次出现时解释；
- 代码使用 fenced code block，并标明语言，例如 `python`、`bash`；
- 文件路径、函数名、参数名、字段名使用反引号；
- 表格只用于真正适合二维比较的信息，避免超宽巨表；
- 长流程优先使用有序列表或 Mermaid，而不是大段叙述；
- 结论、假设、风险、待核验项明确分节，不混写；
- 引用其他文件时使用稳定的相对路径或明确文件名；
- 一个文件尽量承担一个清晰职责，避免把无关内容塞在同一文档；
- 不依赖图片才能理解核心模型，关键公式、变量、步骤和结论必须在 Markdown 正文中可独立读取；
- 文档中的源码路径、输出文件和运行命令必须与最终交付实际一致。

## 6. 最终检查

在进入 `FINAL_DELIVERY` 前检查：

- 用户没有明确要求图片生成时，是否完全未调用 AI 图片生成工具；
- 所有建模图表是否来自 Python 或题面/用户提供的真实原图；
- Python 图表是否专业、清晰、可复现且不存在无意义的信息堆叠；
- 是否清理了无价值或重复图表；
- 除参考论文原件外，AI 自行创建的文本型文档是否全部为 `.md`；
- Markdown 是否具备清晰层级、公式、代码语言标记和稳定路径引用；
- 教程是否能脱离对话上下文独立被人和 AI 继续使用。
