# 组员终稿论文复审协议

## 目标

AI 完成建模与内部成果后，队员人工理解、核查并重写最终论文，再交给 AI 做赛前终稿复审。

审核必须重新对齐：

`原题要求 + 最终路线 + Final Run/真实结果 + Visualization Manifest + 组员终稿`

状态：`FINAL_PAPER_AUDIT`。

---

## 1. 审核依据

必须优先读取：

1. 组员最终论文；
2. 原始赛题与附件。

当前工作区存在时同时读取：

- 最终路线与各问方法；
- 最终 Python；
- `RUN_LEDGER.md` 与各问 `FINAL_RUN_ID`；
- 实际运行结果；
- 最终图表/表格；
- `VISUALIZATION_MANIFEST.md`；
- 数据与参数；
- Requirement Traceability；
- 题目详解；
- AI 参考论文；
- 文献账本、数据来源和 AI 使用日志。

缺失材料必须标记“无法核验”，不得凭记忆假装核对。

---

## 2. 审核原则与严重度

每个严重问题都应指出位置、原文/对象、为什么有问题、核验依据和修改建议。无法确定时标记“疑似问题 / 需人工确认”。

- **P0 致命**：答非所问、模型/核心公式/核心结果错误、问题串写、关键结果与 Final Run 相反等；存在 P0 不建议提交。
- **P1 重大**：思路、解释、适用条件、参数、跨问逻辑、验证、关键图表或结果版本明显错误；必须修改后再审。
- **P2 一般**：单位、图表引用、结果精度、表头、表达歧义等。
- **P3 文字格式**：错别字、病句、标点、编号、标题格式等。

默认先报告问题，不整体重写论文；用户明确要求时才制作修订稿。

---

## 3. 先执行最终一致性扫描

复审必须调用 [final-consistency-sweep.md](final-consistency-sweep.md)。

顺序优先为：

1. 原题与问题—解法映射；
2. `FINAL_RUN_ID` 与最终数字；
3. Claim vs Data；
4. 单位和术语；
5. 图表/表格/正文；
6. 摘要—正文—结论；
7. 语言和格式。

重大跨文件冲突未解决时标记：

`CROSS_ARTIFACT_CONSISTENCY_FAILED`

不得因为文字看起来顺畅就判定终稿通过。

---

## 4. 必查：原题与问题—解法映射

重新逐条检查原题动作、子要求、约束、单位、范围和指定输出。

建立：

| 问题 | 最终真实解法 | Final Run | 论文写的解法 | 是否一致 |
|---|---|---|---|---|

重点抓：问题 1 写成问题 2、备用模型写成主模型、模型名与公式不一致、正文与源码实际模型不同。

---

## 5. 必查：思路、公式、参数与结果

检查：

- 逻辑链和假设是否真实成立；
- 公式、下标、求和范围、不等号方向；
- 符号首次定义与全文一致；
- 参数、单位、时间范围、权重、阈值；
- 排名、预测值、误差、最优方案、目标值、路径、敏感性/鲁棒性结果；
- 小数点、百分比、正负号、单位换算；
- 摘要、正文、结论是否来自同一个 Final Run/Validation Run。

所有关键数字优先对照 Final Run 和最终输出文件，而不是 AI 参考论文或聊天记忆。

若发现同一个指标在不同位置出现不同数值，先判断是否统一舍入；若底层值不同，则按版本冲突处理。

---

## 6. 必查：图表与 Visualization Manifest

完整图表审计必须对照：

- [python-visualization-policy.md](python-visualization-policy.md)
- [figure-evidence-contract.md](figure-evidence-contract.md)
- `VISUALIZATION_MANIFEST.md`
- `RUN_LEDGER.md`

### 来源与版本

检查：

- 图是否属于正确问题；
- 是否能从 Manifest 追到 Run ID、Python 文件、输入数据和最终结果；
- 是否误用了 Stage 1 旧探索图；
- 是否误用了 `SUPERSEDED` 运行或已替换模型的旧图；
- 图中的排名、预测值、路线、目标值等是否与 Final Run 一致；
- 图号/表号、文件和正文引用是否一一对应。

### 图前证据逻辑

逐图确认：

- 核心结论是什么；
- Hero evidence 是否清楚；
- 每个 panel 是否有唯一作用；
- 是否存在删掉也不影响论证的重复 panel；
- 是否为了“好看”静默删数据、删类别、删失败种子或只展示有利场景；
- 配对/重复结构是否被错误打散；
- 不确定性定义是否真实且在可比 panel 间一致。

### 中文与视觉质量

中文论文中的正式图重点检查：

- 是否存在无必要英文轴/图例；
- 标题、横轴、纵轴、单位、图例是否完整；
- 中文字体是否正常，有无乱码/方框；
- 负号和数学符号是否正常；
- 是否遮挡、截断、标签重叠；
- 缩放到论文真实尺寸后是否仍可读；
- 颜色是否造成误导或仅依赖红绿区分。

### 图表与正文解释

检查正文声称的趋势是否真的存在、图是否真正支持结论、是否忽略误差/区间、图题是否夸大结论。

图表本身有问题时，应回到 Python/Final Run 修复，不只改正文措辞。

---

## 7. 必查：表格

检查：

- 核心表是否来自 Final Run；
- 表格与正文数字一致；
- 是否把几百行明细无意义塞进正文；
- 普通 DataFrame 是否被无必要截图；
- 表头、单位、精度、排序、表号正确；
- 矩阵热力图与原始矩阵值一致。

---

## 8. 必查：Claim vs Data、解释与结论

重点抓：

- 相关写成因果；
- 模拟结果写成现实事实；
- 假设写成事实；
- 过度外推；
- “稳定”“显著”“始终最好”“最优”等强措辞超过真实证据；
- 启发式算法找到当前最好解，却被写成已证明全局最优；
- 结论没有回答原题。

所有 superlative 和强结论都必须回看最终表格/图/Run 数据。

参考文献检查正文编号、元数据、实际支撑关系和手工抄写错误，不得为了补问题临时编文献。

---

## 9. 修改后的 ripple check

任何 P0/P1 修改后必须判断是否影响：

`模型/参数 → Python 重跑 → Final Run → 图表/表格 → 教程 → 摘要/正文/结论 → 终稿审核`

不能只修局部句子就结束。

---

## 10. 三轮审核

### 第一轮：正确性

`原题 → 问题/解法 → Final Run → 模型/公式 → 结果 → 图表 → 解释 → 结论`

优先找 P0/P1。

### 第二轮：一致性

`摘要 ↔ 正文 ↔ 结论 ↔ 图表 ↔ Manifest ↔ Run Ledger ↔ Python 结果 ↔ 各问`

重点抓复制残留、旧版本、数值精度/单位漂移和串题。

### 第三轮：语言与格式

最后处理错别字、病句、标点、术语、编号、图表/公式引用和格式。

---

## 11. 输出与二审

默认生成：

```text
最终论文审核报告.md
```

使用 [../assets/FINAL_PAPER_AUDIT_TEMPLATE.md](../assets/FINAL_PAPER_AUDIT_TEMPLATE.md)。

结论：

- P0：不建议提交；
- 无 P0 有 P1：必须修改后再审；
- 仅 P2/P3：建议修订后提交；
- 未发现 P0/P1、无 `CROSS_ARTIFACT_CONSISTENCY_FAILED` 且剩余问题可接受：通过终稿复审。

队员修改后再次提交时，输出“已解决 / 未解决 / 新增问题”，并检查修改是否引入新的 ripple conflict。

通过终稿复审不等于保证获奖，也不等于官方提交格式已准备完成；正式比赛还需执行 [official-submission-policy.md](official-submission-policy.md)。
