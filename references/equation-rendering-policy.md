# Word / PDF 公式渲染与验收规范

## 目标

数学建模论文中的公式、符号和变量必须以真正的数学排版呈现。

Markdown / 研究记录中可以使用 LaTeX 作为数学源码，但最终 `.docx` 和 `.pdf` **禁止把 LaTeX 源码直接当普通文本写入正文或表格**。

例如以下内容只能作为源表示：

```latex
x_{icst}
Q_{cst}=\sum_p u_{pcs}x_{pcst}
\Pi_\omega
```

最终 Word/PDF 中必须显示为正确的下标、求和、希腊字母和数学结构，而不是出现 `_`、`{}`、`\sum`、`\omega` 等源码痕迹。

如果最终文件存在未渲染公式，状态标记：

```text
FORMULA_RENDERING_FAILED
```

在修复前不得进入 `FINAL_DELIVERY`。

---

# 1. 覆盖范围

该规则适用于最终论文中所有数学内容，包括：

- 行内变量；
- 独立公式；
- 目标函数；
- 约束条件；
- 求和、积分、极值、概率、期望；
- 分式、根式、上下标；
- 矩阵、向量、分段函数；
- 希腊字母；
- 公式编号；
- 符号说明表中的第一列；
- 图表标题、表头中真正需要数学排版的变量；
- 附录中的数学表达。

特别注意：**符号说明表不是普通文本例外。**

例如应显示数学形式 `A_i`、`x_{icst}`、`z_{cst}`、`\Pi_\omega`，不能显示为普通字符串 `A_i`、`x_{icst}`、`Π_ω` 或带花括号的伪 LaTeX。

---

# 2. Markdown 中的公式源码

研究记录、教程和论文母稿可以继续使用规范 LaTeX：

```markdown
行内：$x_{icst}$

独立：
$$
Q_{cst}=\sum_p u_{pcs}x_{pcst}
$$
```

LaTeX 在这里是**可转换的数学源**，不是最终视觉形式。

必须保证：

- LaTeX 语法本身正确；
- 同一变量全文符号一致；
- 不混用 Unicode 下标、普通下划线和 LaTeX；
- 不用字符串拼凑复杂数学表达。

---

# 3. DOCX：优先使用原生 Office 数学公式

最终 Word 优先使用 **OMML（Office Math Markup Language）** 数学对象。

## 推荐路线 A：Pandoc 转 DOCX

如果论文母稿以 Markdown + LaTeX 数学维护，优先：

```text
Markdown / LaTeX 数学源
        ↓
Pandoc
        ↓
DOCX（OMML 原生公式）
```

当用户提供官方 `.docx` 模板时，优先通过 `--reference-doc` 或等效方式继承模板样式，同时让数学表达转换为 Word 原生公式。

核心原则：**不能把 `$x_{icst}$` 直接写成普通 Word 文本。**

## 推荐路线 B：程序化 DOCX + OMML

如果使用 `python-docx` 等程序化方式生成 Word：

- 禁止 `paragraph.add_run(latex_string)` 直接塞 LaTeX；
- 应把数学源转换为 MathML / OMML，再插入 `m:oMath` 或 `m:oMathPara`；
- 可以使用可靠的 LaTeX → MathML → OMML 转换链；
- 或构造合法 OMML 数学对象。

## 不允许

以下方式不得作为正式公式方案：

- 把 `x_{icst}`、`\frac{a}{b}`、`\sum` 作为普通文字；
- 用手打 `_` 模拟下标；
- 用多个普通字符拼一个复杂公式；
- 公式实际是代码字符串，只靠字体“看起来像数学”。

---

# 4. 公式图片只作为兼容性 fallback

如果当前环境无法可靠生成 OMML，但必须完成 Word，可将公式渲染为高质量**矢量**对象作为 fallback。

优先：

```text
SVG / EMF / 其他可可靠嵌入 Word 的矢量格式
```

最后才考虑高分辨率位图。

公式图片必须：

- 字体清晰；
- 与正文基线和字号协调；
- 白底/透明背景自然；
- 不模糊；
- 不裁切上下标；
- 不出现巨大留白；
- PDF 导出后仍然清晰。

只要环境能够稳定生成 OMML，就不应为了省事把所有公式截图化。

---

# 5. 符号说明表的数学列必须单独处理

符号说明表第一列是本问题最容易出错的位置之一。

例如：

| 数学源 | 最终应呈现的含义 |
|---|---|
| `$t$` | 年份索引 |
| `$A_i$` | 地块面积 |
| `$x_{icst}$` | 种植面积决策变量 |
| `$y_{icst}$` | 0-1 启用变量 |
| `$u_{ics}$` | 基准亩产量 |
| `$Q_{cst}$` | 总产量 |
| `$z_{cst}$` | 正常价格销量 |
| `$\omega$` | 随机场景编号 |
| `$\Pi_\omega$` | 场景总利润 |

在 DOCX 中，这一列中的每个单元格都应插入真正的数学对象或经过验证的数学渲染，不得直接复制 Markdown/LaTeX 字符串。

---

# 6. 独立公式排版

独立公式默认：

- 居中；
- 上下留有适当间距；
- 公式编号统一，例如 `(1)`、`(2)`；
- 正文引用编号与公式实际编号一致；
- 长公式必要时合理换行，但不能拆坏数学结构；
- `max`、`min`、`s.t.`、求和上下限、矩阵和分段函数必须按数学规范排版。

例如：

```latex
\max \Pi_1
=\sum_{c,s,t} P_{cst}z_{cst}
-\sum_{p,c,s,t} C_{pcs}x_{pcst}
```

最终文件中应以完整数学公式呈现，而不是普通正文字符。

---

# 7. PDF 生成规则

PDF 不得只是把错误的 Word 继续导出一遍。

推荐：

```text
已通过公式验收的 DOCX
        ↓
可靠 PDF 导出
        ↓
PDF 二次公式检查
```

如果当前 Word → PDF 工具会破坏 OMML、字体、上下标或公式布局：

- 更换导出方式；
- 或从同一份 Markdown / LaTeX 数学母稿独立生成 PDF；
- 但 Word 和 PDF 的公式内容、编号、符号、正文结果必须一致。

不能接受“Word 有问题，PDF 也一样”作为完成状态。

---

# 8. 自动残留扫描

最终 DOCX/PDF 生成后必须做一次公式源码残留扫描。

重点检查以下高风险模式：

```text
_{
^{
\frac
\sum
\prod
\int
\sqrt
\alpha
\beta
\omega
\Pi
\begin{
\left
\right
$...
\(...\)
\[...\]
```

也检查普通文本中的可疑形式：

```text
x_{...}
A_i
z_{...}
```

注意：扫描结果需要结合上下文判断，不能把文件路径中的下划线等误报成公式问题。

发现正文、表格、标题或公式区域仍有 LaTeX 源码时，必须修复后重新导出。

---

# 9. DOCX 结构验收

如果 Word 采用 OMML，应至少检查：

- DOCX 内存在 `m:oMath` / `m:oMathPara`；
- 数学对象数量与论文中预期公式数量大致一致；
- 符号说明表中的数学变量没有全部退化为普通文本；
- 公式编号和正文引用仍然正确。

可以解压 `.docx` 并检查 `word/document.xml` 等 XML 结构。

只检测“文件能打开”不算验收通过。

---

# 10. 视觉验收

程序检查后还必须进行视觉检查。

至少检查所有含重要公式的页面，重点看：

- 上下标是否正确；
- 求和上下限是否正确；
- 分式是否完整；
- 希腊字母是否正确；
- 公式是否被裁切；
- 表格中的数学符号是否正常；
- 公式字号是否与正文协调；
- Word 与 PDF 是否一致；
- 公式是否与原始数学含义一致。

数学意义正确但视觉排版坏掉，也不能交付。

---

# 11. 最终质量门槛

进入 `FINAL_DELIVERY` 前必须满足：

- [ ] Markdown / LaTeX 数学源语法正确；
- [ ] DOCX 中没有把 LaTeX 源码当普通公式文本；
- [ ] 重要公式使用 OMML 或经过验证的高质量数学渲染；
- [ ] 符号说明表数学列正确；
- [ ] 公式编号正确；
- [ ] 自动残留扫描通过；
- [ ] DOCX 结构检查通过；
- [ ] Word 视觉检查通过；
- [ ] PDF 视觉检查通过；
- [ ] Word 与 PDF 公式含义一致；
- [ ] 公式与源码、模型定义、最终结果一致。

任一关键项失败：

```text
FORMULA_RENDERING_FAILED
```

必须修复，不得把存在明显公式源码残留或错误数学排版的 Word/PDF 放入 `参考论文.zip`。
