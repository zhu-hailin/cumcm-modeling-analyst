# 建模研究 Playbook

## 目标

这不是模型清单，也不是硬性流程。它提供一组**能帮助 Agent 发现更好方案的研究问题**：先问问题、做能区分路线的小实验，再决定模型。

> 不要求每道题逐条执行；只选择能改变当前判断的部分。

---

## 1. 机理 / 数值模型

优先问：

- 题目中的守恒、平衡、几何、动力学、排队、流量或状态转移关系是什么？
- 哪些变量是状态，哪些是控制，哪些是外生输入？
- 方程是否有量纲一致性和合理极限？
- 数值误差与模型结构误差能否区分？

有价值的小实验：

- 特殊情形是否能得到解析/显然答案；
- 网格、步长、容差变化后结论是否收敛；
- 关闭某个机制后结果怎样变化；
- 守恒量、边界条件和单调性是否满足。

不要因为能写复杂微分方程就默认机理正确。

---

## 2. 参数估计 / 反演 / 标定

优先问：

- 现有观测真的能区分这些参数吗，还是多个参数组合产生几乎相同输出？
- 参数是否有现实范围、符号或物理约束？
- 估计误差会不会传到后续结论并导致决策翻转？

有价值的小实验：

- 用已知参数生成模拟数据，再看算法能否恢复；
- 画目标函数/似然在关键参数附近的形状；
- 多初值重复拟合，检查是否落到不同等价解；
- 对最不确定参数做 profile / 扰动 / 区间传播。

如果参数不可识别，不要用更多小数位伪装精确。

---

## 3. 预测 / 分类 / 状态识别

优先问：

- 真正部署/预测时，未来能拿到哪些特征？
- 验证切分是否对应真实使用场景，而不是随机打散制造高分？
- 性能提升来自真实结构，还是泄漏、重复主体、时间穿越或不平衡？
- 题目要的是准确预测、解释、阈值决策，还是风险区间？

有价值的小实验：

- 时间滚动、主体分组或地区外推验证；
- 与简单规则/持久性/均值等合理 baseline 比较；
- 误差按时间、类别、主体或区间分层；
- 校准、阈值敏感性和错误代价检查。

不要把一次随机切分上的高分当成普适能力。

---

## 4. 优化 / 调度 / 路径 / 资源配置

优先问：

- 决策变量、目标、硬约束和软惩罚是否区分清楚？
- 能否先构造一个肯定可行的 baseline 解？
- 真正瓶颈是容量、时间窗、整数性、冲突、连通还是计算规模？
- 题目要求精确最优，还是赛时可执行的高质量方案？

有价值的小实验：

- 小规模实例用精确算法求最优，与启发式结果比较；
- 计算上下界 / 松弛界 / 已知最优基准；
- 约束逐项统计最大违反量；
- 多 seed 报告目标值分布而非只挑最好一次；
- 扰动资源、需求或成本，观察方案是否频繁翻转。

可行性先于漂亮目标值；没有证明时不要写“全局最优”。

---

## 5. 综合评价 / 排名 / 决策

优先问：

- 指标是否重复计量同一信息？方向、尺度和量纲是否合理？
- 权重来自题意、数据、专家偏好还是人为选择？
- 最终排名是否对权重、标准化方法和异常值高度敏感？
- 题目真正需要一个精确名次，还是稳定的优先级/等级/决策区域？

有价值的小实验：

- 权重扰动与排名翻转率；
- 更换合理标准化方法；
- 去掉高相关指标后比较；
- 比较不同合理评价框架是否给出一致头部/尾部结论。

若名次不稳定，论文应报告稳定区间或结论边界，而不是强行给确定排序解释。

---

## 6. 聚类 / 分群 / 无监督结构

优先问：

- 距离由哪些变量和尺度主导？
- 簇数是否稳定，还是算法强行切分连续结构？
- 分群是否真的服务题目后续决策？
- 簇编号有没有被无证据解释成早/中/晚、轻/中/重？

有价值的小实验：

- 标准化/距离选择敏感性；
- bootstrap / 重采样聚类稳定性；
- 不同簇数和不同算法的一致结构；
- 与外部锚点、单调指标或后续任务的关系。

降维图好看不能替代稳定性证据。

---

## 7. 仿真 / 风险 / 随机系统

优先问：

- 随机性来自哪里，分布和参数依据是什么？
- 尾部风险是否比均值更重要？
- 仿真次数是否足以稳定关键分位数/决策？
- 输入不确定性和模型不确定性有没有混在一起？

有价值的小实验：

- 逐步增加仿真次数看统计量是否稳定；
- 报告分位数、超越概率、ECDF，而不只报均值；
- 关键输入做情景/分布替换；
- 极端场景与压力测试。

---

## 8. 多问题赛题的整体设计

每问都问一次：

```text
这一问产出的什么东西，下一问会真实读取？
```

优先复用：

- 清洗后的正式数据；
- 已估参数及其不确定性；
- 分类/分群结果；
- 预测结果；
- 约束、阈值和决策规则；
- 正式模型接口。

下游从文件/字段读取上游 Final Run 产物，不从聊天或论文文字手抄。

如果各问完全独立，先确认这真的是题目结构，而不是建模链断了。

---

## 9. 一个通用研究循环

当不知道下一步做什么时，用这个循环：

```text
当前最大不确定性是什么？
→ 哪两个解释/路线最需要区分？
→ 最便宜的哪个实验能区分它们？
→ 实验结果分别会导致什么行动？
→ 跑实验
→ 更新路线或停止继续研究
```

如果一个实验无论成功失败都不会改变模型、答案、证据强度或论文边界，就没有必要仅为了“显得严谨”去做。

---

## 10. 模型比较：解释为什么选优

存在真实备选时，让比较回答实际取舍，而不是模型名称竞赛：

- 固定相同数据口径、约束、验证划分、评价指标和可比的计算预算；指标由原题任务决定。
- 区分“模型结构不同”和“同一模型换求解器”；后者不能冒充多种现实机制的验证。
- 对照精度/目标值、可行性、稳定性、解释性和运行成本。结论说明收益来自哪里，代价是否值得。
- 验证集用于选模/调参，最终评估使用未参与选择的数据或外层验证；反复查看测试结果后不能继续称其为未接触测试集。
- 小数据无法保留独立测试集时，选择分组/滚动/嵌套验证等适合的办法并说明限制，不机械切三份。
- 优化题采用相同约束和预算，最终交付可以选最好的已验证可行解；评价算法稳定性则报告完整重复实验的分布和失败率。

简单模型已经满足题意且复杂方案无证据收益时，保留简单模型。不要为了“加分”凑模型数量。

## 11. 灵敏度分析：从参数变化到决策变化

只分析可能改变主答案、可行性或结论强度的输入/参数/假设：

1. 选参数：现实不确定性、估计误差、关键假设或瓶颈约束；不是随意挑方便画图的参数。
2. 定范围：依据观测误差、估计区间、官方范围或明确的情景假设；无依据的 ±10% 不能冒充现实波动。
3. 选方法：局部平滑时可做单参数扰动；存在交互、非线性或离散决策时补充联合情景、分层采样或适合的全局方法。
4. 量化影响：结果变化、弹性、约束违反、排名/方案翻转阈值；基准为零时使用有意义的绝对变化或其他尺度，不硬除以零。
5. 解释决策：哪些结论稳定、哪里失效、现实中应重点测量或控制哪个量。

敏感性不是调参曲线，也不等于随机 seed 稳定性。随机系统比较参数效应时控制或报告模拟噪声，避免把噪声误当参数影响。
优化情景中区分“固定已选方案评估可行性/损失”和“每个情景重新优化后的调整收益”，两者回答的问题不同，不能混在同一曲线中不加说明。
上游估计/预测的不确定性可能改变后问方案时，将区间、重采样或情景传到下游；不会改变决策时说明依据即可，不要求每条接口完整传播。

## 12. 创新：小改进也要有机制与证据

有真实改进时，在既有模型计划/问题详解内记录，不额外生成创新台账：

| 原方法的具体不足 | 本题采用的改动 | 为什么有效 | 对比/消融证据 | 代价与适用边界 |
|---|---|---|---|---|

可来自问题专属约束、特征或机理设计、稳健化、求解改进、跨问耦合等；更换模型名、单纯调参或美化图表不能自动算创新。
能消融时保留其他条件比较有/无改动；不能直接消融时给公平基线、理论性质或小规模可核验案例。收益可能是可行性、解释性、稳定性或成本，不限于精度。
尚未验证的点只写“拟议改进”；已实现但无明显收益时如实报告，不强称优越或首创。
