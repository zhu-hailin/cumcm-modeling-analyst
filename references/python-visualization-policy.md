# Python 科学可视化与结果表格系统

## 目标

数学建模中的图不是装饰。每张正式图至少要承担一种作用：

- 直接展示结果；
- 解释模型或机制；
- 验证模型；
- 支持方案选择和决策。

> **先确定结论和证据，再写绘图代码。**

删除某张图或某个 panel 后，如果理解、验证和决策都不受影响，它大概率不该进入论文。

Stage 1 只做影响选模的必要探索；Stage 2 才生成正式结果图、验证图、结果表和论文候选图。

## 2. Figure Contract：正式绘图前先定证据

A/B 级正式图在写代码前，执行 `figure-evidence-contract.md`。

至少明确：

```text
核心结论：
图的角色：结果 / 机制 / 验证 / 鲁棒性 / 决策
Hero evidence：
Supporting evidence：
panel a：
panel b：
panel c：
源数据：
Run ID：
不确定性定义：
评阅风险：
```

禁止从喜欢的模板、某个 DataFrame 或“想画一张高级图”开始。

### Claim-first，不是 Table-first

不要机械执行：

```text
一个 CSV / 一个表 → 一张图
```

多个表可以共同支撑一张 Figure；同一个表也可能支持不同证据视角。两张图只是在重复同一结论时，应合并或删除。

### 数据完整性门

不得为了图更漂亮、模板更好套或结果更有利而静默：

- 删除行、列、类别；
- 只选表现好的时间段；
- 删除失败随机种子；
- 只展示有利模型或场景；
- 隐藏异常结果。

合理排除必须记录：排除前数量、排除后数量、规则、理由和对结论的影响，并保留原始数据。

### 配对与重复结构

同一地区、样本、车辆、模型、参数组、场景或随机种子存在重复比较时，应保留 paired structure。必要时使用配对差值、相连点图或变化量图，不要只看相互独立的边缘分布。

## 3. A/B/C 图表分级

### A 级：核心结果图

回答：**最终得到了什么？**

例如：

- 实际值与预测值；
- 最优路径或调度方案；
- 最终排名；
- 聚类结果；
- Pareto 前沿；
- 系统演化；
- 风险分布。

A 级图优先进入论文。

### B 级：诊断与验证图

回答：**为什么相信这个模型和结果？**

例如：

- 残差；
- 误差比较；
- 预测区间；
- 收敛曲线；
- 权重敏感性；
- 鲁棒性场景；
- 聚类质量；
- 可行性与约束检查。

### C 级：探索图

用于 EDA、模型筛选、参数调试、中间检查和异常定位。

C 级图通常保留在各问结果目录或研究记录，不自动进入论文。

**不规定每问至少几张图。** 数量由信息价值决定。

## 4. 中文论文默认中文图表

最终可能进入中文论文的图表默认使用中文：

- 标题；
- 横纵坐标；
- 图例；
- 分类标签；
- 关键注释；
- 单位。

国际通用模型和指标缩写可以保留，例如 RMSE、MAE、R²、AUC、PCA、ARIMA、TOPSIS、XGBoost。

单位写完整，例如：

```text
时间（h）
距离（km）
成本（元）
温度（℃）
需求量（件）
```

不要无必要保留 `Time / Prediction / Actual / Cost / Distance` 等英文标签。

模型名称保持规范大小写，不得用机械 `.title()` 把 `XGBoost`、`NSGA-II`、`ARIMA` 等改坏。

---

## 5. 中文字体自动适配

禁止只写：

```python
plt.rcParams["font.sans-serif"] = ["SimHei"]
```

公共绘图模块应检测当前系统真实存在的中文字体并回退。候选可包括：

1. Microsoft YaHei
2. Noto Sans CJK SC
3. Source Han Sans SC
4. PingFang SC
5. SimHei
6. WenQuanYi Micro Hei
7. 其他已安装中文字体

同时设置：

```python
plt.rcParams["axes.unicode_minus"] = False
```

正式保存前验证中文、数学符号和负号，不能出现方框或乱码。

失败状态：

```text
CHINESE_FONT_RENDERING_FAILED
```

修复前不得进入论文候选。

## 6. 题型与推荐图表

以下只是候选集合，不是机械清单。

### 预测类

- 原始序列；
- 趋势与季节分解；
- 实际值 vs 预测值；
- 预测区间；
- 残差时序与分布；
- 滚动误差；
- 多模型误差比较。

### 综合评价类

- 最终排名横向条形图；
- 指标权重；
- 标准化指标热力图；
- TOPSIS 得分；
- 权重敏感性；
- 平行坐标。

雷达图只在指标较少、确实有解释价值时使用。

### 优化类

- 决策变量热力图；
- 收敛曲线；
- Gantt 图；
- 路径图；
- 网络图；
- Pareto 前沿；
- Tornado 敏感性图；
- 参数—场景热力图；
- 方案切换图。

### TSP / VRP / 图论类

存在真实坐标、节点关系或路线时，不应只给路径文本。可使用 Matplotlib、NetworkX、GeoPandas 或真实地图工具生成：

- 节点编号；
- 起终点；
- 车辆路线；
- 需求或距离信息；
- 多车辆颜色/线型区分。

禁止虚构地图和坐标。

### 聚类类

- 肘部法；
- Silhouette；
- PCA 投影；
- 合理时使用 t-SNE / UMAP；
- 聚类中心热力图；
- 分组指标比较。

### Monte Carlo / 随机仿真

- 概率分布；
- ECDF；
- 箱线图；
- 小提琴图；
- 置信/分位区间；
- Fan Chart；
- 参数—结果热力图。

### 敏感性 / 鲁棒性

- Tornado；
- Spider；
- 参数扫描；
- 场景热力图；
- 参数变化—目标值曲线；
- 最优方案切换图。

## 7. 启发式算法的收敛证据

GA、SA、PSO、ACO、Tabu Search 等迭代算法若支撑最终结论，应保存真实迭代历史，并在适合时生成收敛曲线。

还应考虑：

- 多随机种子重复运行；
- 最终值分布；
- 最佳、平均、中位数和离散程度；
- baseline 或小规模精确解对照。

不得只选择“最漂亮的一次”作为稳定性证据。种子策略、重复次数和代表结果规则写入 `04_results/logs/RUN_LEDGER.md`。

缺失必要证据时：

```text
OPTIMIZATION_CONVERGENCE_EVIDENCE_MISSING
```

---

## 8. 专业复合 Figure

允许并鼓励有真实信息密度的：

- 多子图 Figure；
- shared axis；
- inset；
- 主图 + 局部放大；
- 主结果 + 误差；
- 主结果 + 分布；
- 多场景对比。

复合图应有一个清楚的 Hero panel，其余 panel 提供验证或背景。不要把所有 panel 机械做成同样大小和同样视觉权重。

禁止为了“高级”滥用：

- 3D；
- 渐变和发光；
- 装饰背景；
- 彩虹色；
- 无意义雷达图、桑基图和网络图。

## 9. 公共绘图模块

优先建立：

```text
03_code/common/
├─ visualization.py
└─ table_export.py
```

`visualization.py` 负责：

- 字体检测；
- 画布与字号；
- 坐标轴和图例；
- 语义配色；
- panel label；
- DPI 和保存；
- 中文和负号；
- 通用 QA。

`table_export.py` 负责：

- DataFrame 导出；
- CSV/XLSX；
- 统一精度；
- 单位和字段名；
- 论文原生表格所需数据。

不同问题不要各自复制一套互相冲突的 Matplotlib 配置。

同一个模型、方案、地区、车辆和场景跨图出现时，名称、颜色、marker 和 line style 尽量保持一致。

## 10. 图表格式与保存

正式论文候选图建议同时保存：

```text
PNG + SVG
```

必要时增加 PDF。

要求：

- PNG 默认不少于 300 DPI；
- 关键线图和路径图可使用 450–600 DPI；
- SVG/PDF 尽量保留可编辑文字；
- 使用合理的紧致边界；
- 文件非空；
- 标题、图例、坐标轴和注释不被裁切。

每问输出到 `04_results/figures/qN/`，整题论文候选复制或汇总到 `04_results/figures/final/`。

不照搬某个期刊固定宽度；最终尺寸以当年 CUMCM 模板、A4 页面和实际排版为准。

---

## 11. 最终尺寸可读性

所有论文候选图必须按论文中的真实插图尺寸检查，而不是只看大屏。

检查：

- 坐标轴和 tick label；
- 图例；
- 注释；
- marker 与线宽；
- panel label；
- 误差棒和区间；
- 长中文标签；
- 复合图中的子图间距。

失败状态：

```text
PAPER_FIGURE_READABILITY_FAILED
```

---

## 12. 颜色与视觉层级

默认避免 `jet`、`rainbow` 等容易误导的色图。

- 连续数据使用感知均匀 colormap；
- 正负变化使用合理 diverging colormap；
- 分类使用有限离散颜色；
- 关键类别不只依赖红/绿；
- 必要时结合 marker 和 line style；
- 尽量保证黑白打印和色觉缺陷情况下仍能区分；
- baseline 和辅助证据不应比最终方案或 Hero evidence 更抢眼。

颜色可区分不等于层级正确，仍需检查实际渲染效果。

## 13. 结果表格系统

普通 DataFrame 不应默认截图成 PNG。

优先链路：

```text
Python
→ pandas DataFrame
→ CSV / XLSX
→ Word 原生表格
```

适用于：

- 排名；
- 参数；
- 预测值；
- 最优方案；
- 模型误差；
- 车辆路径摘要。

真正具有二维结构意义的数据才优先做 annotated heatmap，例如相关矩阵、混淆矩阵、指标矩阵、敏感性矩阵、场景矩阵和分配矩阵。

每问表格放 `04_results/tables/qN/`，整题汇总放 `04_results/tables/final/`。

## 15. Visualization Manifest

Codex 默认维护：

```text
04_results/VISUALIZATION_MANIFEST.md
```

至少记录：

| 图号 | 文件 | 问题 | Run ID | 等级 | 数据源 | 生成代码 | 支撑结论 | 是否进入论文 |
|---|---|---|---|---|---|---|---|---|

论文和终稿复审通过 Manifest 检查：

- 错图；
- 旧图；
- 被替代模型的图；
- 不同 Run 混用；
- 图号和文件错配；
- 图中数字与正文不一致。

## 16. Panel-by-panel Visual QA

正式 Figure 先逐 panel 检查，再检查整图。

每个 panel 至少核对：

- 唯一证据作用；
- 是否属于 Hero / supporting evidence；
- 数据是否完整；
- 排除是否有记录；
- 配对结构是否保留；
- 不确定性是否真实且定义一致；
- 中文、单位、图例是否正确；
- 标签是否碰撞；
- 是否裁切；
- 最终尺寸是否可读；
- 是否来自对应 Run 和数据；
- 是否真的支持正文主张。

整图再检查：

- 视觉层级；
- panel 顺序；
- 重复信息；
- 颜色语义；
- 共享图例和坐标轴；
- 论文插入后的清晰度。

严重失败：

```text
VISUALIZATION_QA_FAILED
```

## 17. 整题模型框架图

最终参考论文原则上有一张整题建模框架图，真实表示各问之间的串行、并行和汇合关系。

优先使用：

- Graphviz；
- Mermaid；
- Matplotlib patches；
- NetworkX。

禁止用生成式图片代替模型流程图。

---

## 18. Stage 1 克制原则

Stage 1 只保留“会不会改变模型选择或风险判断”这一标准。

可以生成必要 C 级探索图，但不要为了建立可视化系统一次生成几十张图。聊天只展示少数真正影响路线的证据。
