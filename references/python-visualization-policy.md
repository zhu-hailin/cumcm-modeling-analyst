# Python 科研图片生成与验收规范

## 目标

图表用于理解和证据表达，不用于装饰。**探索阶段追求快而真实，正式阶段追求严而可追溯。**

正式科研结果图、验证图和方法图由 Python 驱动的确定性链生成。Matplotlib、NetworkX、GeoPandas、Pillow、Graphviz 等均可使用；Graphviz 等外部工具由 Python 调用并保留源码。生成式图片不能伪造、补画、修复或重绘科学证据。

---

## 1. 两级工作模式

### 1.1 QUICK_EXPLORATION

适用于 `EXPLORATION_FIGURE`：EDA、异常检查、变量关系、调试、候选筛选、快速机制判断。

最低要求：

- 基于真实数据/真实计算，不改点、不删不利样本；
- 坐标含义、单位和分类基本清楚；
- 截轴、对数轴、归一化等可能误导的操作显式说明；
- 临时图进入 exploration 目录，不冒充论文图；
- 图本身没有决策价值时可以不保存。

**探索图无需填写完整论文证据契约、A4 尺寸 QA、SVG/PDF 三格式或论文图注。**

### 1.2 FORMAL_EVIDENCE

适用于：

```text
PAPER_FIGURE
VALIDATION_FIGURE
METHOD_FIGURE
```

这些图准备进入论文、正式验证或最终队内成果时，再执行完整的来源、Run/方法版本、脚本、尺寸、字体、误差、不确定性和视觉 QA。

原则：先自由探索，后把真正有证据价值的图升级为正式图；不要把 Stage 1 所有临时图直接“洗白”成论文图。


```text

├─ method/
├─ validation/
├─ exploration/
└─ ai_communication/
```

安全审计图留在 `02_analysis/security_audit/`。

## 3. 正式图的最小证据契约

### 3.1 数据结果图 / 验证图

每张准备进入正式成果的图记录：

```text
核心结论：
Requirement ID：
用途：PAPER_FIGURE | VALIDATION_FIGURE
源数据：
Final / Validation Run ID：
绘图脚本：
不确定性 / 误差定义：
评阅者最可能质疑什么：
删除此图会损失什么：
```

若图不能比文字或可编辑表格增加理解：

```text
FIGURE_NOT_NEEDED
```

### 3.2 方法与流程图

方法与流程图不伪造不存在的 Run。契约：

```text
Requirement ID：
用途：METHOD_FIGURE
角色：总体路线 / 数据流 / 模型链 / 算法结构 / 跨问接口
已确认模型计划与关键假设：
对应代码模块 / 算法步骤：
上游 / 下游接口：
Python 绘图脚本：
方法版本：CURRENT | SUPERSEDED
Run ID：N/A（方法结构图）
```

模型链、算法步骤或跨问接口变化后，旧方法图标记 `SUPERSEDED` 并重新生成。

## 4. 总体学术技术路线图

满足以下情况之一时评估是否需要总体路线图：

- 三个以上相互依赖步骤；
- 多问共享数据、参数、模型或中间结果；
- 多层数据变换、训练、验证或迁移；
- 优化包含多个决策环节；
- 不画图会使跨问接口明显难懂。

需要时只保留：输入、关键预处理、各问核心模型/计算、验证分支、正式跨问接口和最终输出。

禁止：KPI 卡片、状态徽章、PASS/FAIL 状态墙、巨型页眉、圆角卡片墙、App/网页 UI、发光、阴影、渐变背景和装饰性图标。

技术路线图优先 SVG/PDF 矢量，并生成 PNG 预览；白底、紧凑、清楚，图内不放论文式巨型标题。

## 5. 正式绘图脚本

正式图脚本必须：

- 从 Final/Validation Run 结果文件或最终方法计划读取，不手抄最终数字；
- 继承当前项目命名约定；
- 保留准确 docstring 和必要建模注释；
- 不夹带 Skill、聊天、内部提示或 AI 水印；
- 脚本与输出图、Manifest 可相互定位。

可以复用 `scripts/figure_utils.py` 中的字体选择和多格式保存辅助函数，但它只是工具，不替代“应该画什么”的判断。

---

## 6. 正式图技术基线

优先服从当年竞赛官方模板和用户要求。没有明确要求时使用保守基线：

- 折线、散点、柱状、路径、网络、流程等优先保留 SVG/PDF；
- 常规统计图 PNG 至少 300 dpi，同时保留矢量源；
- 必须位图化的混合图可提高到约 600 dpi，纯线稿可更高；
- 最终验收看实际插入尺寸，不靠修改 DPI 元数据伪装高清；
- 最终尺寸下普通文字通常约 8–10 pt，非必要不低于约 7 pt；
- 线条、marker、误差条和箭头在 A4 正常阅读倍率下可辨。

这些是默认值，不是竞赛官方硬规定。

---

## 7. 图题、坐标、统计与不确定性

正式图至少确保：

- 横纵轴、分类顺序、时间口径和单位明确；
- 对数轴、双轴、归一化、截断轴显式说明；
- 柱状图通常从零开始，不从零开始必须有理由并明显提示；
- 误差条说明 SD、SE、CI、分位区间还是多 seed 波动；
- 样本量、重复次数和验证单位在需要时给出；
- 多 panel 只有在共同回答同一科学问题或共享明确比较逻辑时合并；
- 显著性标记只在真实检验完成后使用，并说明检验与多重比较。

普通结果表保持可编辑，不把 DataFrame 截图当表格。

---

## 8. 颜色与可访问性

- 同一对象跨图保持颜色/线型语义一致；
- 不只依赖红绿区分关键结论；
- 必要时同时使用线型、marker、纹理或直接标签；
- 顺序数据用感知均匀 sequential colormap；
- 正负偏差用以零为中心的 diverging colormap；
- 类别使用离散 palette；
- 禁止 `jet/rainbow`、装饰性 3D、发光和无意义渐变；
- 文本与背景保持足够对比。

不固定某一套颜色值，让 Agent 根据科学内容和可读性选择。

---

## 9. 数据与视觉完整性

严禁：

- 静默删除样本、类别、时间段、场景或失败 seed；
- 只展示最好的一次随机运行；
- 隐藏 baseline 更优或明显不利场景；
- 用不同缩放、不同误差定义制造优势；
- 截轴夸大差异而不提示；
- 修改数据点位置、数量、趋势或不确定性；
- 把插值、平滑、估计冒充原始观测；
- 用生成式图片替代统计结果、路径、网络、流程或实验图。

合理排除必须在数据处理或问题详解中记录规则、依据和影响。

---

## 10. 图型由问题决定

常见候选但不强制：

| 任务 | 可能有用的图 | 最重要的风险 |
|---|---|---|
| 时序预测 | 实际-预测、区间、残差、滚动误差 | 时间泄漏、外推范围 |
| 分类 | 混淆矩阵、PR/ROC、校准、决策边距 | 验证单位、类别不平衡 |
| 聚类 | 谱系、轮廓、中心、降维辅助 | 距离、簇数、稳定性、过度解释 |
| 综合评价 | 排名、权重、敏感性、排名变化 | 权重依据、排名稳定 |
| 优化 | 路径、Gantt、Pareto、收敛、约束违反量 | 可行性、上下界、多 seed |
| 风险/仿真 | 分布、ECDF、分位区间、fan chart | 重复数、尾部风险 |
| 高维关联 | 热力图、网络、区间图 | 多重比较、相关不等于因果 |

图型是候选，不是固定模板。

| 图号 | 文件 | 用途 | Requirement | 问题 | Run/方法版本 | 数据/方法 | 脚本 | 支撑结论 | 进入论文 |

## 13. 正式图 QA

自动或人工检查：

- 文件存在、非空、可解析；
- 脚本、图、Manifest、Run/方法版本一致；
- 没有引用 `SUPERSEDED` 结果；
- 标签、误差条、箭头没有被裁掉；
- 中文字体、负号、数学符号正常；
- PNG 像素/DPI 满足目标尺寸，SVG/PDF 可打开；
- A4 实际插入大小下文字、线条、图例和 panel 可读；
- 图紧裁剪、图题紧随、没有大面积无信息空白；
- 普通图无必要时不独占整页。

发现问题从脚本重生，不在 Word 中粗暴拉伸或手工改数据。

---

## 14. 停止条件

新增图或 panel 前问：

```text
它会增加哪项理解、验证或决策价值？
删除它会损失什么？
是否已有更清楚的表或图表达同一信息？
```

没有新增价值时停止，不为“看起来丰富”制造图。

正式图 QA 失败统一标记：

```text
SCIENTIFIC_FIGURE_QA_FAILED
```
