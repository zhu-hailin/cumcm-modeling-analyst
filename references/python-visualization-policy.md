# Python 科学可视化与结果表格系统

## 目标

本规范把“Python 画图”定义为完整的科学可视化系统。目标不是图多、图花，而是让每一张正式图都承担至少一个明确作用：

- 展示结果；
- 解释机制；
- 验证模型；
- 支持决策。

核心原则：

> **先确定结论与证据，再写绘图代码。**

> **删除某张图或某个 panel 不影响理解、验证或最终决策时，它大概率只是装饰。**

Stage 1 仍只做影响模型选择的必要探索；Stage 2 才形成正式结果图、验证图、论文图和结果表。

---

## 0. Figure Contract：正式绘图前先建立证据契约

A/B 级正式图在写绘图代码前，必须先执行 [figure-evidence-contract.md](figure-evidence-contract.md)。

至少明确：

```text
核心结论：
图的角色：结果 / 机制解释 / 验证 / 鲁棒性 / 决策
Hero evidence：
Supporting evidence：
panel a：
panel b：
panel c：
源数据：
Run ID：
不确定性定义：
评阅风险：
```

不得从喜欢的模板、某个 DataFrame 或“想画一个高级图”开始。

### Claim-first，不是 Table-first

禁止机械执行：

`一个 CSV / 一个表 → 一张图`

应先判断多个数据表、指标和实验共同支撑什么结论，再决定最少需要哪些 panel。

### 数据完整性门

不得为了图更漂亮、模板更容易适配或结果更好看而静默：

- 删除行、列、类别；
- 只取表现好的时间段；
- 排除失败随机种子；
- 只展示有利模型/场景；
- 隐藏异常结果。

若有科学/数学上合理的排除，必须记录排除前后数量、规则、理由和对结论的影响，并保留原始数据。

### 保留配对/重复结构

如果同一地区、样本、模型、随机种子、车辆、参数组或场景存在成对/重复比较，应避免仅展示彼此独立的边缘分布而丢失配对信息。必要时使用 paired difference、变化量或相连点图。

## 1. 可视化三级体系

### A 级：核心结果图

回答：**最终得到了什么？**

有可视化结果的问题原则上应有最能直接回答本问的核心图，例如预测结果、最优路径、最终排名、聚类结果、Pareto 前沿、系统演化、风险结果等。

A 级图优先进入正式论文。

### B 级：诊断与验证图

回答：**为什么相信这个模型和结果？**

根据模型结构主动生成，例如残差图、误差比较、预测区间、收敛曲线、权重敏感性、鲁棒性场景、聚类质量、可行性检查等。

B 级图按论文篇幅进入正文或支撑材料。

### C 级：探索性图

用于 EDA、模型筛选、参数调试、中间检查和异常定位。

C 级图通常保留在 `outputs/figures/exploration/`、研究记录或源码中，不自动进入正文。

禁止规定“每问至少 N 张图”。图的数量由真实信息价值决定。

## 2. 中文论文默认中文图表

最终可能进入中文论文的图表默认使用中文：

- 标题；
- 横纵坐标；
- 图例；
- 关键注释；
- 分类标签；
- 必要说明。

国际通用模型缩写和指标可保留，例如 RMSE、MAE、R²、AUC、PCA、ARIMA、TOPSIS。

单位必须完整，例如：`时间（h）`、`距离（km）`、`成本（元）`、`温度（℃）`、`需求量（件）`。

中文论文中禁止无必要保留 `Time / Prediction / Actual / Distance / Cost` 等英文轴标签。

模型、算法和实体名称应保留规范大小写，不得用机械 `.title()` 等方式把 `XGBoost`、`NSGA-II`、`ARIMA` 等改坏。

---

## 3. 中文字体自动适配

禁止只硬编码：

```python
plt.rcParams["font.sans-serif"] = ["SimHei"]
```

公共绘图模块必须检查当前系统实际存在字体，并按可用性回退。建议候选优先级：

1. Microsoft YaHei
2. Noto Sans CJK SC
3. Source Han Sans SC
4. PingFang SC
5. SimHei
6. WenQuanYi Micro Hei
7. 其他真实存在的中文字体

同时设置：

```python
plt.rcParams["axes.unicode_minus"] = False
```

正式保存前至少验证：中文、数学符号和负号正常；不能出现方框或乱码。

出现明显中文字体问题：

```text
CHINESE_FONT_RENDERING_FAILED
```

修复前不得把该图作为论文候选。

## 4. 题型 → 推荐图表映射

以下是推荐集合，不是机械清单。

### 预测类

可选：原始序列、趋势/季节分解、实际值 vs 预测值、预测区间、残差时序、残差分布、滚动误差、多模型误差比较。

### 综合评价类

可选：排名横向条形图、指标权重图、标准化指标热力图、TOPSIS 得分、权重敏感性、平行坐标图。雷达图仅在指标较少且确实有解释价值时使用。

### 优化类

可选：决策变量热力图、收敛曲线、最优值变化、Gantt 图、路径图、网络图、Pareto 前沿、Tornado 敏感性图、参数场景热力图。

### TSP / VRP / 图论类

若存在真实空间坐标、节点关系或路线，不能只给路径文本或表格。应优先生成路径网络图、车辆路线、起终点、节点编号和必要的距离/需求信息。

可使用 Matplotlib、NetworkX、GeoPandas 或真实地图工具；禁止虚构地图。

### 聚类类

可选：肘部法、Silhouette、PCA 投影；t-SNE / UMAP 仅在合理时使用；聚类中心热力图、分组指标比较。

### Monte Carlo / 随机仿真

可选：概率分布、ECDF、箱线图、小提琴图、置信区间、Fan Chart、参数—结果热力图。

### 敏感性 / 鲁棒性

可选：Tornado、Spider、参数扫描、场景热力图、参数变化—目标值曲线、最优方案切换图。

---

## 5. 启发式算法的收敛证据

GA、SA、PSO、ACO、Tabu Search 等迭代启发式算法若支撑最终结论，应保存真实迭代历史，并在适合时生成收敛曲线。

同时优先考虑：

- 不同随机种子重复运行；
- 最终值分布；
- 最佳/平均/中位数与离散程度中真正有意义的指标；
- 基线或小规模精确解对照。

随机算法不得只选“最漂亮的一次”作为稳定性证据。重复实验及代表结果选择规则应写入 Run Ledger。

如果论文声称算法稳定，但没有任何收敛、重复实验或稳定性证据，应标记：

```text
OPTIMIZATION_CONVERGENCE_EVIDENCE_MISSING
```

## 6. 鼓励信息密度高的专业复合图

允许并鼓励合理使用：

- 多子图 Figure；
- shared axis；
- inset；
- 主图 + 局部放大；
- 主结果 + 误差；
- 主结果 + 分布；
- 多场景对比。

复合图应优先形成“一个 Hero panel + 若干 supporting panels”的层级，而不是把所有 panel 机械做成同样大小、同样视觉权重。

例如同一预测模型的“预测结果 + 误差 + 残差分布 + 残差时序”可以组成一张复合图，但只有在四个 panel 分别承担不同证据任务时才值得保留。

禁止为了“高级”滥用 3D、渐变、发光、装饰背景、彩虹色、无意义雷达图、桑基图和网络图。

## 7. 公共绘图模块

最终源码应优先建立统一工具层，例如：

```text
源码/
└── 公共/
    └── utils/
        ├── visualization.py
        └── table_export.py
```

`visualization.py` 负责：字体、字号、画布、标题、坐标轴、图例、DPI、布局、保存、中文、语义配色和 QA 共用逻辑。

`table_export.py` 负责：DataFrame 到 CSV / XLSX / 论文原生表格所需的数据导出，以及统一数值格式、单位和字段名。

不同问题不要各自复制一套互相冲突的 matplotlib 配置。

同一个模型、方案、地区、车辆、场景等在跨图出现时，应尽量保持名称、颜色、marker、line style 语义一致。

## 8. 图表输出格式与目录

推荐输出：

```text
outputs/
├── figures/
│   ├── paper/
│   ├── validation/
│   └── exploration/
├── tables/
│   ├── paper/
│   └── full/
└── intermediate/
```

正式论文候选图建议同时保存：

```text
xxx.png
xxx.svg
```

必要时增加 `xxx.pdf`。

要求：

- PNG 默认不少于 300 DPI；
- 关键线图、路径图等可使用 450–600 DPI；
- SVG/PDF 作为矢量备份；
- 能保持可编辑文字时优先保持可编辑文本，而不是无必要转成路径；
- 使用 `bbox_inches="tight"` 或等价机制；
- 检查文件不是空白图；
- 标题、图例、坐标轴、注释不被裁切。

不照搬某个期刊固定宽度；最终尺寸以当年 CUMCM 论文模板、A4 页面和实际排版为准。

## 9. 论文尺寸可读性

所有论文候选图必须以最终论文中的真实插图尺寸检查，而不是只看大屏效果。

检查：

- 缩放后坐标轴仍清楚；
- 图例不拥挤；
- tick label 不重叠；
- 注释可读；
- marker 和线宽在打印尺寸下明显；
- panel label 不遮挡数据；
- 误差棒/区间加入后标签仍有足够间距。

失败状态：

```text
PAPER_FIGURE_READABILITY_FAILED
```

---

## 10. 颜色与视觉层级规范

默认避免 `jet`、`rainbow` 等容易造成视觉误导的色图。

- 连续数据：感知均匀 colormap；
- 正负变化：合理 diverging colormap；
- 分类：有限离散颜色；
- 不只依赖红/绿色表达关键类别；
- 必要时结合 marker、line style；
- 尽量保证黑白打印和色觉缺陷情况下仍能区分主要信息；
- baseline / 辅助证据不应比最终方案或 Hero evidence 更抢眼。

颜色区分通过不等于视觉层级通过。最终仍需看实际渲染图是否让最重要证据最清楚。

## 11. Python 结果表格系统

普通 DataFrame 不应默认截图成 PNG。

优先链路：

```text
Python
→ pandas DataFrame
→ CSV / XLSX
→ Word 原生表格
```

适用于排名、参数、预测值、最优方案、模型误差、车辆路径摘要等。

真正具有二维结构意义的数据才优先使用 annotated heatmap，例如：相关矩阵、混淆矩阵、指标矩阵、敏感性矩阵、场景矩阵、分配矩阵。

结果表格分级：核心结果表、模型参数表、验证表、完整明细表。论文正文只放关键表，长明细进入 `outputs/tables/full/`。

## 12. 可视化计划

Stage 2 每个问题开始正式求解时，应根据实际需要形成简短计划：

```text
A 级核心结果图
B 级诊断/验证图
C 级探索图
核心结果表
完整明细表
```

不得机械填写；没有某一级需求时明确写“无”。

A/B 级图进入绘图代码前必须先有 Figure Contract。

## 13. Visualization Manifest：绑定真实运行

第二阶段应维护：

```text
VISUALIZATION_MANIFEST.md
```

至少记录：

| 图号 | 文件 | 问题 | Run ID | 等级 | 数据源 | 生成代码 | 目的/支撑结论 | 是否进入论文 |
|---|---|---|---|---|---|---|---|---|

图表使用的数据若由 Final/Validation Run 生成，必须记录对应 Run ID。

论文阶段通过 Manifest 选择最终图；终稿复审也通过 Manifest + Run Ledger 检查错图、旧图、结果版本错误和选择性展示。

## 14. Panel-by-panel Visual QA

所有进入论文或正式交付的图表必须先逐 panel 检查，再检查整张 Figure。

建议至少记录：

| Panel | 唯一任务/结论 | 数据/Run | 不确定性 | 标签/图例 | 碰撞/裁切 | 最终尺寸可读 | 通过 |
|---|---|---|---|---|---|---|---|

必须检查：

- 文件存在且非 0 字节；
- 由真实 Python 运行生成；
- 每个 panel 有唯一证据作用；
- Hero evidence 视觉层级正确；
- 数据没有无记录的删减/筛选；
- 配对/重复结构没有被错误打散；
- 同类 panel 的误差棒、置信区间或随机波动定义一致；
- 中文正常；
- 标题、坐标轴、单位、图例完整；
- 无遮挡、截断、重叠、空图；
- 比例合理；
- 论文尺寸可读；
- 图中数据与源数据及 Run ID 一致；
- 图表说明与真实结果一致；
- 图表确实支撑某个结果、验证或决策。

自动检查、文件存在性和源码审查都不能替代最终渲染图的人眼逐 panel 检查。

严重失败：

```text
VISUALIZATION_QA_FAILED
```

---

## 15. 模型总览图

最终参考论文原则上应有一张整题建模框架图，真实表现问题之间的串行、并行和汇合关系。

优先使用 Graphviz、Mermaid、Matplotlib patches 或 NetworkX 等确定性绘图方式。

禁止用生成式 AI 图片代替模型流程图。

---

## 16. Stage 1 克制原则

强化可视化后，Stage 1 仍然只保留“会不会改变模型选择”这一判断标准。

可以保存探索图，但聊天窗口只展示少数真正影响路线的证据；不得为了建立 Visualization System 在第一阶段一次生成几十张图。
