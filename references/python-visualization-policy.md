# Python 科研图片生成与验收规范

## 目标

数学建模论文中的图不是装饰，也不是为了证明“做过很多实验”。每张正式图都应承担一个明确任务：展示结果、解释机制、验证模型、比较方案或支持决策。

核心原则：

> **先确定结论和证据，再写绘图代码；先保证真实和可读，再追求美观。**

本规范整合原 Figure Contract、Python 可视化、图像用途、绘图脚本命名与图片输出规则，避免同一要求散落在多个文件中。

---

## 1. 适用范围与优先级

适用于：

- Matplotlib / NetworkX / GeoPandas / Graphviz 等确定性工具生成的图；
- 预测、评价、优化、聚类、仿真、敏感性、路径和网络图；
- 论文核心图、诊断图、探索图、AI 沟通图；
- Word/PDF 中使用的图；
- `VISUALIZATION_MANIFEST.md` 和最终图表审核。

规则优先级：

```text
当年竞赛官方模板与提交要求
→ 用户明确要求
→ 本规范的跨期刊保守基线
```

国内编排基线参考现行 `GB/T 7713.2-2022《学术论文编写规则》`；国际技术基线参考 Nature Portfolio、IEEE、Elsevier 与 PLOS 的官方图形指南。不同期刊对字体、色彩空间和文件格式存在差异，因此本 Skill 不把某一家期刊的细节永久写死。

## 2. 图前证据契约

每张准备进入论文或承担关键验证任务的图，在写绘图代码前先记录：

```text
图的核心结论：
图的角色：结果 / 机制 / 比较 / 验证 / 鲁棒性 / 决策
主证据：
辅助证据：
每个 panel 的唯一任务：
源数据文件：
Final / Validation Run ID：
不确定性定义：
需要保留的样本或场景：
评阅者最可能质疑什么：
```

要求：

- 不从“我想画一张高级图”或“有一个 DataFrame”开始；
- 多个 panel 应共同支撑一个主题，不把无关图硬拼在一起；
- 同一结论被多张图重复表达时，优先合并或删除；
- 删除某图不影响理解、验证或决策时，该图通常不应进入论文；
- 核心结论原则上同时有主结果图和至少一种独立验证证据。

图前契约可以写入本问教程、建模计划或 Manifest，不再单独维护一份重复 policy。

## 3. 图像用途分类

所有图片至少标记一种用途：

```text
PAPER_FIGURE             # 论文核心结果图或正式候选图
VALIDATION_FIGURE        # 诊断、收敛、敏感性、鲁棒性等验证图
EXPLORATION_FIGURE       # EDA、筛选和调试图
AI_COMMUNICATION_ONLY    # AI/Agent/队员内部沟通图
SECURITY_AUDIT_ONLY      # 文件安全和隐藏对象审计图
```

推荐目录：

```text
04_results/figures/q1/
├─ paper/
├─ validation/
├─ exploration/
└─ ai_communication/
```

文件安全审计图继续留在：

```text
02_analysis/security_audit/
```

不得把安全审计图、OCR 对照图或隐藏对象恢复图当作建模结果图。

## 4. 国内与国际通用技术基线

### 4.1 矢量优先

折线图、散点图、柱状图、流程图、网络图、路径图、决策树、公式示意和其他线稿，优先保存：

```text
SVG + PDF
```

并按需要额外保存 PNG 供 Word 插入与快速预览。

矢量文件应：

- 保留可编辑文字和路径；
- 嵌入字体或使用目标环境可稳定替代的字体；
- 不把低分辨率位图简单包进矢量外壳冒充高清图；
- 不含画布外无关对象、隐藏数据或裁切残留。

目标系统明确要求 EPS/TIFF 等格式时，再生成兼容副本。

### 4.2 位图分辨率

以**最终插入尺寸**为基准，不通过后期改 DPI 数字伪造清晰度。

保守默认：

| 图像类型 | 默认要求 |
|---|---|
| 彩色/灰度照片、连续色调图 | 300–450 dpi |
| 线稿与连续色调混合图 | 600 dpi |
| 必须位图化的纯线稿 | 1000–1200 dpi |
| 普通论文统计图 PNG 预览 | 至少 300 dpi，同时保留矢量源 |

如果最低分辨率元素只有 72 dpi，把整张图导出为 600 dpi 也不能修复原始模糊，应从源码重新生成。

### 4.3 最终尺寸

优先从官方 Word/LaTeX 模板测量正文可用宽度，再决定画布尺寸。

模板无法测量时，可使用跨期刊常见尺寸作为起点：

- 单栏图：约 80–90 mm；
- 通栏图：约 160–180 mm；
- 高度按内容控制，避免一张图挤满整页却信息稀少。

必须在最终 A4 插入尺寸下检查，而不是只在 100% 大图窗口中看起来清楚。

### 4.4 字体与字号

中文论文候选图默认使用清晰的中文无衬线字体，并根据系统实际字体回退，例如：

```text
思源黑体 / Noto Sans CJK SC
微软雅黑
苹方
黑体
文泉驿微米黑
```

英文、数字和数学符号优先使用 Arial、Helvetica、DejaVu Sans 或与正文兼容的字体。

比赛论文的保守默认：

- 最终插入尺寸下普通图中文字约 8–10 pt；
- panel 标签约 9–10 pt、加粗；
- 非必要不低于 7 pt；
- 同一项目字号层级稳定，避免坐标 7 pt、图例 14 pt 的剧烈跳变。

国际期刊的具体字号范围不同，目标期刊或竞赛模板优先。

### 4.5 线宽与标记

最终尺寸下：

- 坐标轴和辅助线通常 0.5–0.8 pt；
- 主要数据线通常 0.9–1.5 pt；
- 任何关键线条不应细到打印后消失；
- marker 大小与数据密度匹配，不遮盖误差条和相邻点；
- 网格线只在帮助读数时保留，并降低视觉权重。

## 5. 图题、编号与 panel

国内数学建模论文默认：

- 图按正文出现顺序编号；
- 正文先引用，再出现或紧随其后出现图；
- 图题置于图下，由论文排版系统生成，不在图片内部重复放大标题；
- 表题置于表上，普通结果表保持可编辑，不截图成图片；
- 图注解释缩写、符号、误差和必要统计信息；
- 多 panel 使用小写 `(a) (b) (c)`，位置、字号和样式统一；
- 每个 panel 在最终尺寸下仍可辨识。

图内部可以有简短的 panel 标题、坐标标签和必要注释，但不塞入完整段落。

---

## 6. 坐标轴、单位与统计信息

每张正式图检查：

- 横纵轴含义明确；
- 单位完整，单位写在轴标签或图注中；
- 分类顺序有题意依据；
- 时间轴顺序和时区/日期口径正确；
- 对数轴、双轴、归一化和截断轴明确标记；
- 柱状图通常从零开始，若不从零开始必须有充分理由并清楚提示；
- 不通过改变纵轴范围夸大微小差异；
- 样本量、重复次数或分组单位在需要时给出；
- 误差条必须说明是 SD、SE、CI、分位区间还是多随机种子波动；
- 不同可比 panel 的不确定性定义保持一致，例外必须解释；
- 显著性标记只在实际检验完成后使用，并说明检验方法和多重比较处理。

图中数值必须来自 Final/Validation Run，不从聊天、旧截图或已替代 CSV 手抄。

## 7. 颜色与可访问性

颜色承担语义，不只是装饰。

要求：

- 同一模型、类别、场景在不同图中使用一致颜色；
- 不只依赖红绿差异表达结论；
- 关键曲线同时使用线型、marker、填充纹理或直接标签；
- 检查灰度打印后是否仍可区分；
- 顺序数据使用感知均匀的 sequential colormap；
- 正负偏差使用以零为中心的 diverging colormap；
- 类别数据使用离散 palette；
- 避免 `jet`、彩虹色、无意义渐变、荧光发光和 3D 透视；
- 文本与背景尽量保持足够对比，尤其是图例、标注和浅色区域；
- 不使用彩色文字代替清楚的引线与标签。

除非用户或官方模板指定，不固定某一套颜色值。

## 8. 数据与图像完整性

严禁为了图更漂亮或结论更有利而：

- 静默删除样本、类别、时间段、场景或失败随机种子；
- 只展示表现最好的某一次运行；
- 隐藏 baseline 优于主模型的场景；
- 对不同组采用不同缩放或不同误差定义却不说明；
- 修改数据点位置、数量、趋势或不确定性；
- 用生成式图片替代真实统计结果、路径、网络、流程或实验图；
- 用图片编辑软件补画缺失数据；
- 把平滑、插值、裁剪或异常处理结果伪装成原始观测。

合理排除必须记录：

```text
排除前数量
→ 排除规则
→ 排除后数量
→ 题意/统计依据
→ 对结论的影响
```

配对、时间、空间、重复测量或层级结构应在图中尽量保留，不能只画边缘均值掩盖真实差异。

## 9. 图型与任务匹配

图型由要证明的结论决定，不机械套模板。

| 任务 | 常用图 | 必须警惕 |
|---|---|---|
| 时间序列预测 | 实际-预测、预测区间、残差、滚动误差 | 随机切分、时间泄漏、区间定义不明 |
| 分类 | 混淆矩阵、ROC/PR、校准图、特征作用 | 只报准确率、类别不平衡、测试泄漏 |
| 聚类 | PCA/UMAP 辅助图、谱系图、轮廓系数、中心热力图 | 把可视化投影当完整证据、簇编号冒充阶段 |
| 综合评价 | 排名图、权重图、敏感性、排名变化 | 雷达图过载、权重扰动缺失 |
| 优化 | 方案结构、路径、Gantt、Pareto、收敛、约束违反量 | 只展示最好一次、启发式冒充全局最优 |
| Monte Carlo / 风险 | 分布、ECDF、分位区间、fan chart、场景比较 | 只报均值、随机种子与重复数缺失 |
| 敏感性 | tornado、参数扫描、方案切换边界 | 扰动范围无现实依据 |
| 高维关联 | 相关/偏相关热力图、网络图 | 把关联写成因果、颜色范围误导 |
| 组间分布 | 箱线、小提琴、ECDF、散点+区间 | 只画均值柱状图、掩盖样本量 |

复合 Figure 适合把“主结果 + 诊断/鲁棒性”放在同一主题下。主证据占更大视觉权重，辅助 panel 不喧宾夺主。

## 10. Python 实现与中文命名

正式绘图脚本使用中文语义名，并与输出图使用相同主干：

```text
03_code/q1/论文图/第一题_实际值与预测值对比图.py
04_results/figures/q1/paper/第一题_实际值与预测值对比图.png
04_results/figures/q1/paper/第一题_实际值与预测值对比图.svg
```

要求：

- 从 Final/Validation Run 结果文件读取数据；
- 不在脚本中手抄最终结果；
- 公共字体、布局、保存和检查逻辑进入 `03_code/common/绘图工具.py`；
- 使用 `constrained_layout`、`tight_layout` 或手工布局时仍要检查实际裁切结果；
- 保存前明确画布物理尺寸；
- PNG 与矢量版本来自同一次绘图；
- 脚本注释解释证据和不确定性，不逐行解释 Matplotlib API；
- 一张复合图可由一个脚本生成多个 panel，不为形式制造大量文件。

技术性文件名因工具链必须保留英文时，应在源码 README 中说明。

## 11. AI 沟通图

用于 Agent 之间、AI 与队员之间解释方案、候选比较、调试或中间理解的图，必须同时满足：

```text
文件名前缀：AI沟通图_
图面标记：AI内部沟通图｜非论文材料
Manifest：AI_COMMUNICATION_ONLY
进入论文：否
进入官方提交：否
```

推荐：

```text
03_code/q1/AI沟通图/AI沟通图_第一题_候选模型比较.py
04_results/figures/q1/ai_communication/AI沟通图_第一题_候选模型比较.png
```

若内部图后来值得进入论文，不能只删除角标并改名。必须重新建立图前证据契约，绑定 Final/Validation Run，新建正式中文绘图脚本，重新生成并通过 QA。

## 12. Visualization Manifest

统一维护：

```text
04_results/VISUALIZATION_MANIFEST.md
```

推荐字段：

| 图号 | 文件 | 用途类型 | 问题 | Run ID | 数据源 | 中文生成脚本 | 核心结论 | 不确定性 | 图面标记 | 进入论文 | 进入官方提交 |
|---|---|---|---|---|---|---|---|---|---|---|---|

Manifest 用于确认：

```text
论文结论
↔ 图号与图注
↔ 图文件
↔ 中文绘图脚本
↔ Run ID
↔ 数据与模型结果
```

旧 Run 被替代时，关联图必须重新生成或明确标记过期。

## 13. 自动与视觉 QA

### 自动检查

- 文件存在且非 0 字节；
- PNG 像素、DPI 和物理尺寸合理；
- SVG/PDF 可以解析，字体没有明显缺失；
- 没有空白图、全透明图或严重裁切；
- 中文字符和负号能正确显示；
- 轴标签、单位、图例和 panel 标签存在；
- 数据点数量与输入记录一致；
- 图来自当前 Final/Validation Run；
- 文件名、用途目录和 Manifest 一致；
- AI 沟通图标记完整。

### 视觉检查

在最终 Word/PDF 插入尺寸下逐图检查：

- 核心结论能否在几秒内识别；
- 字体、线宽、marker 和误差条是否可读；
- 标签是否碰撞、遮挡或裁切；
- 图例是否遮挡数据；
- 颜色在灰度与常见色觉缺陷下是否仍可区分；
- 复合 Figure 每个 panel 是否有唯一任务；
- 视觉层级是否突出主证据；
- 图注能否解释误差、缩写和样本量；
- Word 与 PDF 中图像是否一致、清晰。

只检查“图片能打开”不算验收通过。

## 14. 失败状态

为避免状态名膨胀，科研图片统一使用四类：

```text
FIGURE_EVIDENCE_FAILED          # 图与结论、数据或 Run 无法对应
FIGURE_QA_FAILED                # 分辨率、字体、尺寸、裁切、标注或可读性不合格
FIGURE_INTEGRITY_FAILED         # 选择性展示、伪造、误导性处理或数据不完整
AI_COMMUNICATION_FIGURE_LEAKED  # 内部沟通图进入论文或官方提交
```

修复前不得把相关图放入参考论文、队员终稿或官方提交候选。
