# Python 科研图片生成与验收规范

## 目标

论文图是证据，不是装饰。图表多少由原题交付项和论文证据蓝图决定，不按每问固定数量生成。

> **先确定要证明什么，再决定是否画、画什么和放在哪里。**

正式论文科研图只允许由 Python 驱动的确定性绘图链生成。Matplotlib、NetworkX、GeoPandas、Pillow、Graphviz 等可以使用，但 Graphviz 等外部工具必须由 Python 脚本调用并保留源码。图像模型只能做视觉复核，不能生成、补画、修复或重绘科研图。

---

## 1. 优先级与适用范围

```text
当年竞赛官方模板/提交要求
→ 用户明确要求
→ 本规范的国内外保守基线
```

本规范适用于：

- 论文核心结果图；
- 诊断、验证、收敛、敏感性和鲁棒性图；
- EDA 与调试图；
- 学术总体技术路线图和方法结构图；
- AI 内部沟通图；
- `VISUALIZATION_MANIFEST.md`；
- Word/PDF 最终尺寸与逐页视觉检查。

技术默认参考国内学术论文编排习惯，以及 Nature、IEEE、Elsevier、PLOS 等主流出版机构的保守交集，但不把任何单一期刊细节冒充竞赛官方规则。

## 2. 图前证据契约

### 2.1 数据结果图

每张论文候选图或关键验证图先记录：

```text
核心结论：
原题 Requirement ID：
图的角色：结果 / 机制 / 比较 / 验证 / 鲁棒性 / 决策
主证据：
辅助证据：
每个 panel 的唯一任务：
源数据文件：
Final / Validation Run ID：
不确定性定义：
必须保留的样本/场景：
评阅者最可能质疑什么：
删除此图会损失什么：
```

如果图不能比文字或表格增加理解，在论文证据蓝图中标记：

```text
FIGURE_NOT_NEEDED
```

并说明理由。

### 2.2 方法与流程图

方法图不能伪造不存在的数据源或 Run ID。它的契约为：

```text
原题 Requirement ID：
图的角色：总体路线 / 数据流 / 模型链 / 算法结构 / 跨问接口
已确认模型计划与假设：
对应代码模块或算法步骤：
上游/下游接口：
Python 绘图脚本：
方法版本状态：CURRENT / SUPERSEDED
Run ID：N/A（方法结构图）
```

最终模型、算法步骤或跨问接口变化后，该图自动失效，必须重新生成。

## 3. 图像用途分类

```text
PAPER_FIGURE             # 正文核心结果或正式候选图
METHOD_FIGURE            # 总体技术路线、数据流或算法结构图
VALIDATION_FIGURE        # 诊断、收敛、敏感性和鲁棒性
EXPLORATION_FIGURE       # EDA、筛选和调试图
AI_COMMUNICATION_ONLY    # AI/Agent/队员内部沟通图
SECURITY_AUDIT_ONLY      # 文件安全与隐藏对象审计图
```

推荐目录：

```text
04_results/figures/q1/
├─ paper/
├─ method/
├─ validation/
├─ exploration/
└─ ai_communication/
```

安全审计图留在 `02_analysis/security_audit/`，不能进入科研图目录或论文。

## 4. 总体学术技术路线图

在 `PAPER_EVIDENCE_BLUEPRINT` 阶段评估是否需要总体路线图。以下任一情况出现时通常需要：

- 方法链含三个以上相互依赖步骤；
- 多个问题共享数据、参数、模型或中间结果；
- 数据经过多层变换、训练、验证和迁移；
- 优化包含多个决策环节；
- 不画图会让跨问接口难以快速理解。

图中只保留：

- 输入数据；
- 关键预处理；
- 每问核心模型或计算；
- Final/Validation 分支；
- 问题间正式接口；
- 最终交付结果。

明确禁止：

- 仪表盘、KPI 卡片和状态徽章；
- “PASS/FAIL”大标签和内部审计状态墙；
- 巨型页眉、宣传副标题和圆角卡片墙；
- App/网页 UI 风格；
- 发光、阴影、渐变背景和装饰性图标；
- 在流程图中重复整段论文文字；
- 图像生成模型绘制方法或流程图。

默认技术规格：

- Python 脚本确定性生成；复杂有向图可由 Python 调用 Graphviz；
- 优先 SVG/PDF 矢量，同时导出 PNG 预览；
- 白底、深色文字、有限强调色；
- 紧裁剪，无大面积空白；
- 图内不放论文式大标题，图题由正文管理；
- 最终插入尺寸下文字约 7.5–9 pt，线宽和箭头可辨；
- 一般独立成图，不与无关结果图硬拼。

若旧流程图因海报化被驳回，应学术化重画，而不是直接删除总体路线这一证据角色。

## 5. 中文绘图脚本与项目兼容

新建的独立中文赛题项目，推荐使用清楚的中文语义脚本名：

```text
03_code/q1/论文图/第一题_实际值与预测值对比图.py
04_results/figures/q1/paper/第一题_实际值与预测值对比图.png
04_results/figures/q1/paper/第一题_实际值与预测值对比图.svg
04_results/figures/q1/paper/第一题_实际值与预测值对比图.pdf
```

脚本与输出图使用同一语义主干。

已有英文仓库、CI、包模块、Notebook 或跨平台工具链存在稳定约定时，优先继承现有命名。无论中英文，文件名必须说明职责，Manifest、运行命令和源码索引必须一致。

绘图脚本：

- 从 Final/Validation Run 的结果文件读取数据；
- 不手抄最终数字；
- 复用统一字体、保存和 QA 函数；
- 有准确 docstring 和必要注释；
- 不夹带 Skill、聊天或内部提示。

## 6. 国内与国际通用技术基线

### 6.1 矢量与位图

折线、散点、柱状、路径、网络、流程、决策树和其他线稿优先保存：

```text
SVG + PDF
```

并按需要生成 PNG 供 Word 和预览使用。

位图按最终插入尺寸检查：

| 图像类型 | 默认基线 |
|---|---:|
| 彩色/灰度连续色调图 | 300–450 dpi |
| 线条与连续色调混合图 | 600 dpi |
| 必须位图化的纯线稿 | 1000–1200 dpi |
| 常规统计图 PNG | 至少 300 dpi，同时保留矢量源 |

不能通过事后修改 DPI 元数据把模糊原图变成“高清”。

### 6.2 物理尺寸

优先实测官方模板正文宽度。无法测量时可暂用：

- 单栏/半栏：约 80–90 mm；
- 通栏：约 160–180 mm；
- 中文 A4 单栏正文常见整栏宽度可约 130–150 mm，但必须以实际模板为准。

最终验收看物理尺寸，不只看像素或大图窗口。

### 6.3 字体、线宽和标记

- 中文使用当前系统真实可用的清晰字体，并设置回退；
- 英文、数字和数学符号使用与正文兼容的字体；
- 最终尺寸下普通文字通常约 8–10 pt，非必要不低于 7 pt；
- panel 标签约 9–10 pt，样式统一；
- 主要数据线通常约 0.9–1.5 pt；
- 坐标轴和辅助线通常约 0.5–0.8 pt；
- marker 不遮挡误差条和相邻点；
- 网格线只在帮助读数时保留并降低权重。

这些是保守默认值，不替代官方模板和用户要求。

## 7. 图题、panel、坐标与统计信息

- 正文先引用图，图紧随或在合理位置出现；
- 图题置于图下，表题置于表上；
- 图内不重复放巨大论文标题；
- 多 panel 使用统一 `(a)(b)(c)`；
- 默认独立成图；只有多个 panel 共同回答同一科学问题、共享坐标或明确比较逻辑时才合并；
- 横纵轴、分类顺序、时间口径和单位明确；
- 对数轴、双轴、归一化和截断轴必须显式说明；
- 柱状图通常从零开始；不从零开始时必须有充分理由和明显提示；
- 样本量、重复次数和验证单位在需要时给出；
- 误差条说明 SD、SE、CI、分位区间还是多 seed 波动；
- 可比 panel 的不确定性定义保持一致；
- 显著性标记只在真实检验完成后使用，并说明检验和多重比较。

普通结果表保持可编辑，不把 DataFrame 截图成图片。

---

## 8. 颜色、灰度与可访问性

- 同一模型、类别、场景跨图保持颜色语义一致；
- 不只依赖红绿区分关键结论；
- 关键曲线同时使用线型、marker、纹理或直接标签；
- 检查灰度打印和常见色觉缺陷；
- 顺序数据用感知均匀 sequential colormap；
- 正负偏差用以零为中心的 diverging colormap；
- 类别数据使用离散 palette；
- 禁止 `jet/rainbow`、装饰性 3D、发光和无意义渐变；
- 文本与背景保持足够对比。

除非官方或用户指定，不固定某一套颜色值。

---

## 9. 数据与视觉完整性

严禁：

- 静默删除样本、类别、时间段、场景或失败 seed；
- 只展示最好的一次运行；
- 隐藏 baseline 更优或不利场景；
- 用不同缩放或不同误差定义制造优势；
- 截轴夸大差异而不提示；
- 修改数据点位置、数量、趋势或不确定性；
- 用生成式图片替代统计结果、路径、网络、流程或实验图；
- 通过图像编辑补画、擦除或改变结论；
- 把插值、平滑或估计冒充原始观测。

合理排除必须记录处理前后数量、规则、依据和对结论的影响。配对、时序、空间、重复测量和层级结构应尽量保留。

## 10. 图型与证据角色

| 任务 | 常用图 | 关键审计 |
|---|---|---|
| 时序预测 | 实际-预测、区间、残差、滚动误差 | 时间泄漏、区间定义、外推范围 |
| 分类 | 混淆矩阵、PR/ROC、校准、决策边距 | 验证单位、类别不平衡、完美指标 |
| 聚类 | 谱系、轮廓、中心、降维辅助图 | 距离、簇数、稳定性、阶段过度解释 |
| 综合评价 | 排名、权重、敏感性、排名变化 | 权重依据、方法替换、排名稳定 |
| 优化 | 路径、Gantt、Pareto、收敛、约束违反量 | 可行性、上下界、多 seed、全局最优措辞 |
| 风险/仿真 | 分布、ECDF、分位区间、fan chart | 重复数、seed、尾部风险、只报均值 |
| 高维关联 | 热力图、网络图、区间图 | 关联不等于因果、多重比较 |
| 组间分布 | 箱线、小提琴、ECDF、原始点 | 样本量、离群点、尺度、伪重复 |

图型是候选，不是强制清单。

## 11. AI 沟通图

内部解释、候选比较、调试或 Agent 沟通图必须同时满足：

```text
文件名前缀：AI沟通图_
图面标记：AI内部沟通图｜非论文材料
Manifest：AI_COMMUNICATION_ONLY
进入论文：否
进入官方提交：否
```

若后来确有论文价值，必须重新建立正式证据契约、绑定 Final/Validation Run 或最终方法计划、新建论文图脚本、重新生成并 QA，不能只删角标和改名。

## 12. Visualization Manifest

至少记录：

| 图号 | 文件 | 用途类型 | Requirement ID | 问题 | Run ID/方法版本 | 数据或模型计划 | 生成脚本 | 支撑结论 | 最终尺寸 | 进入论文 | 进入提交 |
|---|---|---|---|---|---|---|---|---|---|---|---|

数据图填写真实 Run ID；方法图允许 `N/A（方法结构图）`，但必须填写方法版本和代码模块。

## 13. 自动与视觉 QA

### 自动检查

- 文件存在且非空；
- PNG 像素与 DPI 对应目标物理尺寸；
- SVG/PDF 可解析；
- 边界没有裁掉标签、误差条或箭头；
- 中文字体可用、负号和数学符号正常；
- 脚本、图片、Manifest 和 Run/方法版本一致；
- AI 沟通图标记完整；
- 论文图没有引用 `SUPERSEDED` 结果。

### 最终 A4 视觉检查

将图放入实际 Word/PDF 模板，按最终大小检查：

- 普通阅读倍率下是否可读；
- 线条、箭头、marker、图例和 panel 是否清楚；
- 紧裁剪且无大面积空白；
- 图题紧随且分页合理；
- 普通结果图接近独占一页是否科学必要；
- 两张互补独立图同排时字号是否仍可读；
- 连续页面是否只有免责声明和稀疏图件而缺少主结果接力；
- 大矩阵和长名单是否采用正文摘要 + 附录完整表。

发现问题重新调整 `figsize`、布局和文字密度后从脚本生成，不在 Word 中粗暴拉伸修补。

## 14. 成本—决策价值

额外图、额外 panel 或额外视觉复核继续前，问：

```text
它可能改变哪个主答案、证据等级或论文边界？
删除它会损失什么？
是否已经有更清楚的表/图表达同一信息？
```

不会增加理解、验证或决策价值时停止，不为了“论文丰富”制造图片。
