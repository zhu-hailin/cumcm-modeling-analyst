# 两阶段赛题工作流

## 目标

先形成可审查的路线决策，再沿确认路线一次性完成整题建模、Python 实现、真实运行结果、专业图表、逐问 Markdown 教程、AI 自写参考论文和四包交付。

必须同时遵循：

- [source-verification-policy.md](source-verification-policy.md)
- [output-artifact-policy.md](output-artifact-policy.md)
- [reference-paper-writing.md](reference-paper-writing.md)
- [final-delivery-packaging.md](final-delivery-packaging.md)

## 第一阶段：赛题预分析与路线决策

### 必须完成

1. 题目背景与现实场景；
2. 题面事实、输出、约束、单位和范围；
3. 子问题拆解与依赖；
4. 每问核心思路；
5. 每问 2–3 条实质不同候选解法；
6. 每条方案统一 100 分制评分；
7. 每问首选、备用和切换条件；
8. 各问推荐总览；
9. 至少三条整题候选路线；
10. 主路线与备用路线；
11. AI 主动检索真实参考文献、数据和参数来源；
12. 参考文献页面/下载核验状态；
13. 证据缺口和风险；
14. 最后再请用户确认。

默认展示顺序：

`核心思路 → 候选解法评分 → 本问首选/备用/切换条件 → 下一问`

所有问题完成后：

`各问总览 → 整体路线 → 主路线推荐 → 文献/数据证据 → 待确认`

第一阶段不生成最终 Python，不生成最终参考论文。

状态：`WAITING_FOR_CONFIRMATION`

## 参考文献核验在第一阶段就开始

AI 应主动核验外部参考文献：

- 页面能否实际打开；
- 题名/作者/年份是否对应；
- 是否为正式来源；
- 是否只能看到元数据/摘要；
- 是否存在全文下载；
- 若声称可下载，是否达到 `DOWNLOAD_VERIFIED`。

禁止猜 URL、编 DOI、拿搜索结果页充当论文地址。

若重要链接有问题，应尽早反馈用户，而不是等最终论文写完才发现。

## 路线确认

记录：各问最终方法、整体问题链、关键变量和约束、已采纳参考文献、暂定参数、验证方法、备用路线和明确不采用方案。

确认后进入 `STAGE_2_LOCKED`。

## 第二阶段：完整求解与实现

执行顺序：

`数据准备 → 公共变量/假设 → 各问求解 → 全局验证 → Python 实现 → Python 图表 → 运行产物 → Markdown 教程 → 最终参考论文 → 四包交付`

### 每问完整结构

1. 目标；
2. 前置问题传入结果；
3. 输入、输出和符号；
4. 假设；
5. 模型定义；
6. 目标函数/核心关系；
7. 约束；
8. 参数来源；
9. 算法步骤；
10. Python 实现映射；
11. 实际结果与 Python 图表；
12. 验证；
13. 向下一问传递什么。

### Python 实现

- 完成最终可运行代码；
- 按实际赛题/问题编号组织；
- 当前环境允许时实际执行并修复明显错误；
- 保存图表、表格和必要中间结果；
- 记录依赖、运行顺序、参数和随机种子；
- 不用伪代码冒充最终源码。

### 图表

用户未明确要求时禁止 AI 图片生成工具。建模图表默认全部由 Python 根据真实数据、模型输出或确定结构生成，专业但克制。

### 教程

按实际子问题生成 `.md` 教程，与源码逐项一致。

## 最终参考论文

这里的“参考论文”是 **AI 针对本次赛题自行撰写的最终成果论文**。

它不是外部论文原文合集。

AI 必须基于：

- 锁定路线；
- 实际 Python 结果；
- Python 图表和表格；
- 已核验参考文献；

重新组织成正式数学建模论文，并实际生成：

- `.docx`
- `.pdf`

用户提供官方模板时按模板排版。

不得因为外部参考文献无法下载而跳过论文撰写或让 `参考论文.zip` 为空。

## 参考文献链接问题处理

如果发现：页面打不开、DOI 不匹配、下载失效、只能看摘要、需要权限、文件不匹配或下载状态无法确认：

1. 尝试可靠替代来源；
2. 无法解决时明确反馈用户；
3. 写入 `其他.zip/文献与来源/文献问题反馈.md`；
4. 关键依据缺失时标记证据缺口。

只有 `DOWNLOAD_VERIFIED` 才能在最终论文或清单中描述为“可下载”。

## 路线锁定规则

- 不为写作方便临时换模型；
- 小调整必须记录；
- 新证据只改善参数/验证时保持路线；
- 新证据推翻核心假设时输出 `ROUTE_REOPEN_REQUIRED`；
- 重开路线时比较新旧路线分数和代价。

## 最终交付阶段

完成模型、代码、运行验证、教程、论文和文献核验后，进入四包交付：

```text
题目详解.zip
参考论文.zip
源码.zip
其他.zip
```

### 题目详解.zip

逐问 `.md` 教程。

### 参考论文.zip

AI 本次撰写的最终论文，至少 `.docx + .pdf`，不得为空。

### 源码.zip

全部 Python、必要数据、依赖、图表、表格和中间结果。

### 其他.zip

AI 使用说明、建模决策、路线变更、文献账本、数据来源、参考文献链接核验、文献问题反馈和运行环境等 Markdown 文档。

四包通过自检后状态：`FINAL_DELIVERY`。
