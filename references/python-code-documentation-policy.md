# Python 源码命名、注释与复现规范

目标：让队员能快速定位模型、理解关键处理、修改参数并复现结果。规范针对正式建模源码；探索脚本不必先做完整工程化。

## 1. 简体中文优先，兼容现有工程

新建中文赛题项目优先使用简体中文 Python 文件名、docstring、人工注释、结果列名/Sheet 名及说明，例如：

```text
03_code/q1/第一题.py
03_code/q1/第一题_结果验证.py
03_code/总运行.py
客户编号、实际需求量、预测需求量、总成本_元、是否满足约束
```

- raw 官方字段不改写；转换为中文字段时保留映射，语义与单位明确。
- 现有 main.py、包模块、Notebook、CI、库/API 或官方固定格式保持原约定，不为中文化破坏接口。
- Windows/Excel 人工打开的 CSV 可使用 utf-8-sig；程序明确要求标准 UTF-8 时服从实际工具链。
- 库名、模型名、数学符号和固定技术标识可保留英文；内部变量不必机械中文化。
- 不用 new.py、final_final.py 等模糊临时名作正式入口；改名同步导入、命令和索引。
- 中文命名是可读性偏好，不是科学正确性的单独否决条件。

## 2. 注释负责“做什么”和“为什么”

除合法空 __init__.py、生成文件或简单配置外，正式模块开头用简短中文 docstring 说明本问/职责、关键输入、输出和入口。关键函数解释非显然的参数形状/单位、返回值、假设及副作用；不给显然的短函数堆长说明。

多阶段脚本用中文区域级注释分开数据、建模、求解、验证和导出。例如：

```python
# ==================== 数据读取 ====================
# 读取官方附件，不修改原件。

# ==================== 数据清洗 ====================
# 缺失值处理仅在训练窗口拟合，避免未来信息泄漏。

# ==================== 核心建模：多目标资源配置模型 ====================
# 定义决策变量、成本/服务目标和容量等硬约束。

# ==================== 求解算法：NSGA-II ====================
# 记录 seed、预算和约束处理方式；算法不等于现实模型。

# ==================== 结果验证 ====================
# 从导出方案独立复算目标和硬约束。

# ==================== 结果导出 ====================
# 输出可追溯的正式表格及下游接口。
```

区域按真实职责选择，不要求固定数量/格式。核心建模区写实际模型名，求解算法另行标明；不同模型别用一个笼统“模型部分”包住。

行内注释解释单位/口径、样本处理依据、泄漏防范、复杂索引、数值稳定、现实边界和容易误改的业务规则，不逐行翻译 Python。不以注释比例评价质量，模型替换后要同步注释。

## 3. 公式、数据与代码可对应

- 目标函数、关键约束、参数和指标能定位到 qN_solution.md 的解释及源码实现。
- 数学名与工程变量名不同则给映射；公式编号和公共符号只维护一个权威说明。
- 数据处理记录规则、处理前后数量和不可逆变化；公式/单位/字段/接口变化同步说明。
- 不把整段 LaTeX 或内部提示词复制进源码。

随机/迭代算法说明 seed 策略、停止条件、关键参数、可行性修复及重复实验选择规则。优化题可选择最好的已验证可行方案，但不能用它冒充典型性能；声称稳定时保留分布与失败情况。

把求解器状态与进程状态分开记录：求解器达到时限仍可能有可行候选，需要独立验证；运行进程失败或被强制终止不能直接成为 Final Run。

## 4. 路径、入口与真实运行

- 相对项目根目录定位文件，不硬编码私人绝对路径；不覆盖官方原件/raw。
- 清洗数据写 processed，外部原文件写 external，正式成果写 04_results，临时探索写 99_temp，尊重现有等价布局。
- 入口明确输入、输出、依赖和调用方式；需要时支持输出目录参数，使每次重要运行使用新产物路径。
- 只实现当前已确认问题；总复现入口用于已完成且获确认的模型链，不是跳过后问确认的入口。
- 正式记录必须来自实际执行；依赖/环境说明以实际用到的包和版本为准，不抄整份无关环境。
- 不强制把成熟 Notebook 重构成包；提供可按顺序运行的入口，消除隐藏状态。
- 科研图从正式结果/方法版本生成，注释写明来源、单位与误差定义；图型、独立图号和视觉 QA 以 [绘图规范](python-visualization-policy.md) 为准。

## 5. 源码纯净度与必要声明

源码只保留求解、运行、复现和解释所需内容。清理无关 Skill 宣传、聊天/系统提示词、审计注入原文、推荐评分、无用旧代码、影响结果的 TODO/伪实现和吞异常。

不添加无关 AI 水印，但不得删除依法或当年竞赛规则要求的 AI 使用声明、引用、版权/许可证及作者信息；需要匿名时按官方规则处理。完整 AI 使用日志保留，不能把“源码纯净”当成隐藏来源。

不把 QUESTION_PLAN_CONFIRMATION 等内部协作状态写进模型源码。旧路线保存在版本历史或独立备用模块，不掩盖失败实验。

## 6. 按影响验收

核对中文可读性/兼容性、模块和区域职责、模型/算法名称、数据与公式映射、实际入口/依赖、正式运行来源和交付副本。

- 数值代码、数据或关键配置变更：重新执行受影响计算并验证。
- 仅修注释/错别字：核对未改变逻辑，保留对应的已验证计算版本，不因纯文字改动重跑全部模型。
- 绘图样式调整：只重生成受影响图并验证，不重复训练模型。
- 源码包交付：从解压副本真实验证入口及依赖，未实测的环境不声称通过。

代码问题使用 PYTHON_CODE_QA_FAILED；源码混入无关提示词等使用 SOURCE_CODE_CONTAMINATION_DETECTED。修复影响计算的错误并真实验证后，才能把对应结果作为正式证据；不让纯风格项把科学判断判为失败。
