# Python 源码命名、注释与纯净度规范

## 目标

正式 Python 不只要能运行，还要让队员在比赛时间内看懂、修改、复现和解释。

核心原则：

> **文件名说明职责，注释解释建模意图，代码本身表达实现。**

修复前不得固化 Final Run 或进入源码包：

```text
PYTHON_CODE_QA_FAILED
SOURCE_CODE_CONTAMINATION_DETECTED
```

---

## 1. 中文语义文件名

每问至少有一个主入口：

```text
03_code/q1/第一题.py
03_code/q2/第二题.py
03_code/q3/第三题.py
03_code/总运行.py
```

复杂问题按职责拆分：

```text
第一题_数据处理.py
第一题_特征构造.py
第一题_模型求解.py
第一题_结果验证.py
第一题_敏感性分析.py
第一题_结果导出.py
```

公共模块可以使用：

```text
数据读取.py
数据清洗.py
评价指标.py
结果导出.py
绘图工具.py
路径工具.py
```

规则：

- 默认用下划线连接语义，不使用空格；
- 不把 `main.py`、`final.py`、`new.py`、`test.py`、`code.py` 当正式成果名；
- `__init__.py`、`conftest.py`、`pyproject.toml`、`requirements.txt` 等工具链固定名可以保留；
- 官方提交系统不支持中文名时，只在 `06_submission/` 生成兼容副本，并记录映射与实际运行结果；
- 用户明确指定其他命名时，以用户为准。

论文图脚本和图片命名由 `python-visualization-policy.md` 统一管理。

## 2. 模块说明

除空 `__init__.py`、自动生成文件和极简单配置外，每个正式 `.py` 开头写简短模块 docstring，说明：

- 对应哪一问；
- 主要职责；
- 关键输入；
- 关键输出；
- 直接运行命令或由哪个入口调用。

示例：

```python
"""问题二：机场运行状态预测。

读取 ``01_data/processed/第二题_特征.csv``，完成滚动训练、预测与误差评估，
结果写入 ``04_results/data/q2/`` 和 ``04_results/tables/q2/``。

运行：python "03_code/q2/第二题.py"
"""
```

不在文件头写 AI 身份、Skill 名称、推荐分或宣传语。

---

## 3. 关键函数与类

以下非平凡对象应有准确 docstring：

- 数据读取、清洗和特征构造；
- 目标函数和约束构造；
- 模型训练、求解、预测和仿真入口；
- 评价指标；
- 敏感性、鲁棒性和重复实验；
- 正式绘图和结果导出；
- 跨问题接口。

至少说明：

- 做什么；
- 参数含义、形状和单位；
- 返回值；
- 重要假设、边界和副作用；
- 与教程公式的对应关系（适用时）。

简单 getter、明显的短函数不需要长篇注释。

---

## 4. 行内注释解释“为什么”

优先注释：

- 单位换算和统计口径；
- 缺失、异常、零值和样本剔除理由；
- 边界条件和现实约束；
- 数值稳定处理；
- 复杂索引、矩阵形状和跨问映射；
- 随机种子、重复实验和停止条件；
- fallback 和异常分支；
- 容易被队员误改的业务规则。

好的注释：

```python
# 原始附件以“万人次”为单位，模型统一换算为“人次”，
# 避免与单人票价相乘时出现量纲错误。
passenger_count = passenger_10k * 10_000

# 填补器仅在训练窗口拟合，防止未来统计量泄漏到历史预测。
train_x = imputer.fit_transform(train_x)
test_x = imputer.transform(test_x)
```

无效注释：

```python
# 创建模型
model = RandomForestRegressor()

# i 加一
i += 1
```

不使用“注释行占比”作为质量标准。注释很多但没有信息，或与代码不一致，仍然不合格。

## 5. 模型、公式与数据处理对应

目标函数、主要约束、关键中间量和评价指标要能映射到 `02_analysis/qN_solution.md`。

推荐：

```python
# 对应公式（5）：固定启用成本 + 里程成本 + 超时惩罚。
total_cost = fixed_cost + distance_cost + delay_penalty
```

不要把整段 LaTeX 论文复制进源码。

数据处理代码必须说明不可逆变化和口径：

```python
# 仅删除计划时间缺失的记录；该字段无法从其他列可靠恢复。
# 删除数量写入清洗日志，01_data/raw/ 中的原文件保持不变。
cleaned = raw.dropna(subset=["scheduled_time"])
```

如果模型、公式编号、单位、字段、输入输出路径或返回值改变，相关 docstring 和注释必须同步更新。

## 6. 随机与迭代算法

GA、PSO、SA、ACO、Monte Carlo、Bootstrap 等应解释：

- seed 或种子生成策略；
- 重复次数；
- 代表结果选择规则；
- 停止条件；
- 可行解修复或惩罚机制；
- 关键参数为什么这样设；
- 哪些结果写入 Run Ledger。

禁止只挑最好的一次结果，也不能用一句“经验参数”代替证据。

---

## 7. 绘图代码注释

绘图脚本的注释重点说明：

- 图支撑什么结论；
- 数据来自哪个 Final/Validation Run；
- 误差条或区间如何定义；
- 为什么需要某个 panel 或局部放大；
- 哪些颜色、线型或排序有固定语义。

不逐行解释 `set_xlabel`、`legend`、`savefig` 等常规 Matplotlib API。

---

## 8. 源码纯净度

正式源码、Notebook 和源码 README 只能保留求解、运行、复现和解释所需内容。

禁止混入：

- Skill 名称和仓库宣传；
- 系统提示词、开发者指令和聊天记录；
- `QUESTION_PLAN_CONFIRMATION` 等内部状态；
- 文件安全审计提示词或疑似注入原文；
- “由 ChatGPT / Codex 生成”等水印；
- 模型推荐打分过程；
- 大段注释掉的旧代码；
- 影响结果的 `TODO`、`FIXME`、`pass`、伪实现和吞异常。

旧路线由 Git、Run Ledger 或独立备用模块保存，不靠注释掉几百行代码留档。

## 9. 入口与路径

- 使用项目相对路径；
- 不硬编码个人绝对路径；
- 不覆盖 `01_data/raw/`；
- 清洗结果进入 `01_data/processed/`；
- 外部数据进入 `01_data/external/`；
- 正式结果进入 `04_results/`；
- 临时测试进入 `99_temp/`；
- `总运行.py` 能按问题依赖顺序执行最终流程；
- 文件重命名后同步更新导入、命令、Run Ledger、教程和 README。
