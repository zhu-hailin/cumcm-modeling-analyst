# Python 源码命名、注释与纯净度规范

## 目标

正式 Python 不只要能运行，还要让队员在比赛时间内看懂、修改、复现和解释。

核心原则：

> **职责清楚、入口稳定、区域可辨、注释有效、脱离会话仍能运行。**

普通质量问题统一标记：

```text
PYTHON_CODE_QA_FAILED
```

源码混入 Skill/提示词/聊天等内容时标记：

```text
SOURCE_CODE_CONTAMINATION_DETECTED
```

修复并真实运行前不得固化 Final Run 或进入源码包。

---

## 1. 文件名：可读性偏好，不是统计正确性的硬门

### 新建的独立中文赛题项目

可以优先使用清楚的中文语义名：

```text
03_code/q1/第一题.py
03_code/q2/第二题.py
03_code/总运行.py
第一题_数据处理.py
第一题_模型求解.py
第一题_结果验证.py
```

### 已有工程或工具链

已有仓库、跨平台环境、CI、Python 包模块、Notebook、测试框架或官方提交系统已有稳定约定时，优先继承项目命名，例如：

```text
main.py
run_all.py
src/q1/solver.py
notebooks/q2_analysis.ipynb
```

无论中文还是英文，都必须：

- 从文件名或项目索引看出职责；
- 主入口稳定；
- 不使用 `new.py`、`final_final.py`、`test2.py` 等含义不明的临时名作为正式成果；
- 文件改名后同步更新导入、命令、Run Ledger、教程和 README；
- 在目标系统和 ZIP 解压后真实运行。

中文论文、图题、表题和面向队员的说明保持中文。中文文件名不再作为科学有效性或交付完整性的单独否决门。

## 2. 模块说明

除空 `__init__.py`、自动生成文件和极简单配置外，每个正式 `.py` 开头写简短模块 docstring，说明：

- 对应问题或公共职责；
- 关键输入；
- 关键输出；
- 直接运行命令或调用入口。

示例：

```python
"""问题二：机场运行状态预测。

读取清洗后的特征数据，执行滚动训练与误差评估，结果写入
``04_results/data/q2/`` 和 ``04_results/tables/q2/``。
"""
```

不写 AI 身份、Skill 名称、推荐分或宣传语。

---

## 3. 关键函数与类

数据读取/清洗、特征构造、目标函数、约束、训练/求解/仿真、评价指标、敏感性/鲁棒性、正式绘图、结果导出和跨问接口等非平凡对象，应有准确 docstring。

至少说明：

- 做什么；
- 参数含义、形状和单位；
- 返回值；
- 重要假设、边界和副作用；
- 与教程公式/约束的对应关系（适用时）。

简单 getter 和含义显然的短函数不需要长篇注释。

## 4. 区域级注释：先让人一眼看懂“这一段在做什么”

正式建模脚本如果包含多个连续处理阶段，应使用清楚的**区域级注释**标出主要职责。目的不是装饰，而是让队员快速定位数据处理、核心模型、求解、验证和输出。

推荐风格：

```python
# ==================== 1. 数据读取 ====================
# 读取官方附件并统一字段类型，不修改原始文件。

# ==================== 2. 数据清洗 ====================
# 处理缺失值、异常值、重复记录和单位换算。

# ==================== 3. 特征构造 ====================
# 构造模型实际使用的解释变量/状态量。

# ==================== 4. 核心建模：XGBoost 回归 ====================
# 使用滚动训练预测未来需求，避免时间泄漏。

# ==================== 5. 模型求解与参数设置 ====================
# 设置关键超参数、seed、停止条件并执行训练/优化。

# ==================== 6. 结果验证 ====================
# 进行滚动验证、误差分析和现实约束检查。

# ==================== 7. 结果导出 ====================
# 保存 Final Run 使用的表格、数据和必要日志。
```

区域名称根据题型调整，不要求所有脚本机械包含上述七段。可以使用：

- 数据读取 / 数据清洗 / 数据预处理；
- 特征构造 / 指标计算 / 参数标定；
- 核心建模：`<模型或算法名称>`；
- 目标函数 / 约束构造；
- 模型训练 / 数值求解 / 优化搜索 / 仿真；
- 验证 / 敏感性 / 鲁棒性 / 现实约束检查；
- 结果整理 / 图表数据准备 / 结果导出；
- 跨问接口。

要求：

- **核心建模区域必须尽量写明实际模型/算法名称**，例如 `核心建模：ARIMA 时间序列模型`、`核心建模：NSGA-II 多目标优化`；
- 同一文件存在多个模型时，应分别标出，不用一个笼统“模型部分”包住所有代码；
- 数据清洗区域应能与后续建模区域明显区分，避免队员不知道哪些代码改变了原始数据口径；
- 区域注释应覆盖真正有意义的连续职责块，不要求给每个 import、变量赋值或两三行简单代码单独分区；
- 区域名称必须与实际代码一致，模型替换后同步修改注释；
- 拆分成多个职责清楚的模块后，每个文件可以减少区域数量，但仍应让核心逻辑位置一眼可辨。

这条规则用于提升**可读性和赛时接手效率**，不以区域数量评价代码质量，也不要求固定编号格式。

## 5. 行内注释解释“为什么”

区域级注释回答“这一段做什么”；行内注释继续重点回答“为什么这样做”。

优先注释：

- 单位换算和统计口径；
- 缺失、异常、零值和样本剔除理由；
- 边界与现实约束；
- 数值稳定处理；
- 复杂索引、矩阵形状和跨问映射；
- seed、重复实验、代表结果和停止条件；
- fallback、异常分支与容易误改的业务规则。

有效示例：

```python
# 填补器只在训练窗口拟合，避免未来统计量泄漏到历史预测。
train_x = imputer.fit_transform(train_x)
test_x = imputer.transform(test_x)
```

无效示例：

```python
# 创建模型
model = RandomForestRegressor()
```

不以注释行占比评价质量。注释很多但没有信息，或与代码不一致，仍然失败。

## 6. 模型、公式与数据处理对应

目标函数、主要约束、关键中间量和评价指标要能映射到 `02_analysis/qN_solution.md`。

```python
# 对应公式（5）：固定启用成本、里程成本与超时惩罚之和。
total_cost = fixed_cost + distance_cost + delay_penalty
```

不要把整段 LaTeX 复制进源码。模型、公式编号、单位、字段、输入输出路径或返回值改变时，相关 docstring、区域注释和行内注释必须同步更新。

数据处理代码要说明处理前后数量、规则、不可逆变化和输出位置；原始数据不得被覆盖。

---

## 7. 随机与迭代算法

GA、PSO、SA、ACO、Monte Carlo、Bootstrap 等应说明：

- seed 或种子策略；
- 重复次数；
- 代表结果选择规则；
- 停止条件；
- 可行解修复/惩罚机制；
- 关键参数依据；
- 哪些结果进入 Run Ledger。

禁止只挑最好的一次，也不能用“经验参数”替代证据。

---

## 8. 绘图代码

绘图脚本注释重点说明：

- 图支撑的 Requirement/结论；
- 数据或方法版本来源；
- Final/Validation Run（数据图适用）；
- 误差、区间和 panel 的含义；
- 固定的颜色、线型和排序语义。

不逐行解释常规 Matplotlib API。论文图命名、溯源和用途遵循 `python-visualization-policy.md`。

## 9. 源码纯净度

正式源码、Notebook 和源码 README 只能保留求解、运行、复现和解释所需内容。

禁止混入：

- Skill 名称与仓库宣传；
- 系统/开发者提示词和聊天记录；
- `QUESTION_PLAN_CONFIRMATION` 等内部状态；
- 文件安全审计提示词或疑似注入原文；
- “由 ChatGPT/Codex 生成”等水印；
- 模型推荐评分过程；
- 大段注释掉的旧代码；
- 影响结果的 `TODO`、`FIXME`、`pass`、伪实现和吞异常。

旧路线由 Git、Run Ledger 或独立备用模块保存。

---

## 10. 路径与入口

- 优先项目相对路径；
- 不硬编码私人绝对路径；
- 不覆盖 `01_data/raw/`；
- 清洗结果进入 `01_data/processed/`；
- 外部数据进入 `01_data/external/`；
- 正式结果进入 `04_results/`；
- 临时测试进入 `99_temp/`；
- 总入口按问题依赖顺序运行最终流程；
- 入口命名与现有项目约定兼容；
- 运行说明明确环境、依赖和命令。
