# Python 中文命名与图像用途标记规范

## 目标

数学建模比赛中的正式 Python 文件应让队员只看文件名就知道它属于哪一问、负责什么。正式论文图与 AI 内部沟通图也必须从文件名、目录和图面标记上明确区分，避免把内部分析图、调试图或 Agent 沟通图误放进论文。

核心原则：

> **正式 Python 使用中文语义命名；论文图脚本与输出图同名；AI 沟通图必须显式标记，绝不能悄悄混入论文。**

本规范与以下规则同时生效：

- `python-code-documentation-policy.md`
- `python-visualization-policy.md`
- `figure-evidence-contract.md`
- `local-workspace-policy.md`
- `final-delivery-packaging.md`

---

# 1. 正式 Python 默认使用中文文件名

Codex / Claude Code 等本地 Agent 生成的正式 Python，默认使用简洁、明确的中文语义文件名。

每个问题至少有一个清楚的主入口：

```text
03_code/q1/第一题.py
03_code/q2/第二题.py
03_code/q3/第三题.py
03_code/q4/第四题.py
```

问题数量按实际题面调整。没有第四问就不创建 `第四题.py`；超过四问则继续使用 `第五题.py`、`第六题.py` 等。

整题总运行入口默认使用：

```text
03_code/总运行.py
```

不再默认使用含义宽泛的：

```text
main.py
run_all.py
final.py
new.py
test.py
code.py
```

# 2. 一个问题拆成多个模块时怎么命名

如果某一问代码较多，可以在问题编号后增加中文职责：

```text
03_code/q1/
├─ 第一题.py                 # 本问主入口
├─ 第一题_数据处理.py
├─ 第一题_特征构造.py
├─ 第一题_模型求解.py
├─ 第一题_结果验证.py
├─ 第一题_敏感性分析.py
└─ 第一题_结果导出.py
```

公共模块同样使用中文语义命名：

```text
03_code/common/
├─ 数据读取.py
├─ 数据清洗.py
├─ 绘图工具.py
├─ 评价指标.py
├─ 结果导出.py
└─ 路径工具.py
```

文件名应描述职责，不使用“最终版”“最新版”“真的最终版”等无法长期维护的名称。

默认使用下划线连接语义，不使用空格：

```text
第一题_预测结果图.py
```

优于：

```text
第一题 预测结果图.py
```

这样在 Windows、PowerShell、终端命令和 Python 导入中更稳定。用户明确要求空格时，以用户要求为准。

---

# 3. 技术性文件名例外

以下名称可以保留 Python / 工具链约定，不强行翻译：

```text
__init__.py
conftest.py
setup.py
pyproject.toml
requirements.txt
```

只有确实受到 Python、测试框架、打包工具或官方提交系统限制时才使用英文技术名。

普通建模脚本、绘图脚本和结果处理脚本不属于例外。

如果当年官方提交系统明确不支持中文文件名，可在 `06_submission/` 中生成一份经过验证的兼容副本，并在 `checklist.md` 中保存中文名到兼容名的映射；工作区内的正式源码仍保留中文语义命名，除非用户另有要求。

# 4. 每张论文图必须有对应的中文绘图脚本

凡是进入论文或作为论文候选的 A/B 级图，都必须能追到一个明确的 Python 绘图入口。

推荐结构：

```text
03_code/q1/
├─ 第一题.py
└─ 论文图/
   ├─ 第一题_预测结果图.py
   ├─ 第一题_残差诊断图.py
   └─ 第一题_敏感性分析图.py
```

对应输出：

```text
04_results/figures/q1/paper/
├─ 第一题_预测结果图.png
├─ 第一题_预测结果图.svg
├─ 第一题_残差诊断图.png
├─ 第一题_残差诊断图.svg
├─ 第一题_敏感性分析图.png
└─ 第一题_敏感性分析图.svg
```

要求：

- 绘图脚本与输出图使用同一语义主干；
- 脚本名必须说明图展示什么，不能只写 `第一题_图1.py`；
- 一张复合 Figure 可以由一个脚本生成多个 panel，不要求每个 panel 单独一个 `.py`；
- 绘图脚本从 Final Run / Validation Run 对应的真实结果文件读取数据；
- 不在绘图脚本里重新手抄最终数值；
- 可复用字体、配色、保存和 QA 逻辑应调用 `03_code/common/绘图工具.py`；
- 输出图通过 Figure Contract、Visualization Manifest 和 Visual QA 后才能进入论文。

论文正文中的图名不必与文件名逐字相同，但必须能在 `VISUALIZATION_MANIFEST.md` 中一一对应。

---

# 5. 图像用途必须分类

所有由 Python 或其他确定性工具生成的图片，至少属于以下一种用途：

```text
PAPER_FIGURE             # 论文核心结果图或正式候选图
VALIDATION_FIGURE        # 验证、诊断、收敛、鲁棒性证据
EXPLORATION_FIGURE       # EDA、筛选、调试图
AI_COMMUNICATION_ONLY    # AI / Agent 之间或 AI 与队员沟通使用的内部图
SECURITY_AUDIT_ONLY      # 文件安全与隐藏对象审计图
```

推荐目录：

```text
04_results/figures/q1/
├─ paper/
├─ validation/
├─ exploration/
└─ ai_communication/
```

文件安全审计图继续放在：

```text
02_analysis/security_audit/
```

不能把 `SECURITY_AUDIT_ONLY` 图片当成模型结果图。

---

# 6. AI 沟通图必须同时满足三种标记

凡是主要用于以下用途的图片，都属于 AI 沟通图：

- Agent 之间传递中间理解；
- AI 向队员快速解释候选方案；
- 内部比较模型或参数，但尚未通过正式验证；
- 调试图、草图、简化示意图；
- 不准备直接放入论文的临时视觉材料。

AI 沟通图必须同时满足：

## 文件名标记

绘图脚本和输出图都使用 `AI沟通图_` 前缀：

```text
03_code/q1/AI沟通图/
└─ AI沟通图_第一题_候选模型比较.py

04_results/figures/q1/ai_communication/
├─ AI沟通图_第一题_候选模型比较.png
└─ AI沟通图_第一题_候选模型比较.svg
```

## 图面可见标记

图中应在不遮挡数据的位置显示：

```text
AI内部沟通图｜非论文材料
```

推荐放在画布底部或右上角的边缘区域，例如使用：

```python
fig.text(
    0.99,
    0.01,
    "AI内部沟通图｜非论文材料",
    ha="right",
    va="bottom",
    fontsize=8,
    alpha=0.7,
)
```

该标记只用于内部图。论文图不得带此标记。

## Manifest 标记

`VISUALIZATION_MANIFEST.md` 中必须记录：

```text
用途类型 = AI_COMMUNICATION_ONLY
进入论文 = 否
进入官方提交 = 否
```

只改文件名而不做图面与 Manifest 标记，视为标记不完整。

---

# 7. AI 沟通图不能直接“改名升级”为论文图

如果一张 AI 沟通图后来确实值得进入论文，不能简单执行：

```text
删除“AI内部沟通图”角标
→ 改个文件名
→ 直接放进论文
```

必须重新走正式流程：

```text
确认它支撑的论文结论
→ 建立 Figure Contract
→ 使用 Final / Validation Run 数据
→ 新建中文论文图脚本
→ 重新生成 PNG + SVG
→ 逐 panel Visual QA
→ 新增 Manifest 记录
→ 再决定是否进入论文
```

例如：

```text
AI沟通图_第一题_模型比较.py
```

若升级为论文图，应另建：

```text
第一题_模型精度与稳定性比较图.py
```

两个文件和两条 Manifest 记录都应保持用途清楚，不能覆盖证据链。

# 8. 论文图、验证图和探索图的命名示例

## 预测类

```text
第一题_原始序列与趋势图.py
第一题_实际值与预测值对比图.py
第一题_预测区间图.py
第一题_残差诊断图.py
```

## 评价类

```text
第二题_综合得分排序图.py
第二题_指标权重图.py
第二题_权重敏感性图.py
```

## 优化类

```text
第三题_最优路径图.py
第三题_算法收敛图.py
第三题_帕累托前沿图.py
第三题_参数敏感性图.py
```

## 仿真与风险类

```text
第四题_结果分布图.py
第四题_风险区间图.py
第四题_场景比较图.py
```

命名以实际图意为准，不机械套模板，也不为了显得丰富强行生成多张图。

# 9. 中文文件名与运行方式

所有正式源码保存为 UTF-8。

推荐运行：

```bash
python "03_code/q1/第一题.py"
python "03_code/q1/论文图/第一题_预测结果图.py"
python "03_code/总运行.py"
```

默认文件名不含空格时，引号可以省略；文档中保留引号有助于兼容路径中的其他空格。

中文模块可以正常使用 Python 3 导入，但应保持项目编码统一，并在交付前真实执行总入口验证。不要因为中文文件名存在就跳过复现测试。

---

# 10. Visualization Manifest 增加用途字段

推荐字段：

| 图号 | 文件 | 用途类型 | 问题 | Run ID | 等级 | 数据源 | 生成脚本 | 图面标记 | 进入论文 | 进入官方提交 |
|---|---|---|---|---|---|---|---|---|---|---|

约束：

- `PAPER_FIGURE` 才可作为论文核心候选；
- `VALIDATION_FIGURE` 是否进入论文取决于价值和篇幅；
- `EXPLORATION_FIGURE` 默认不进入论文；
- `AI_COMMUNICATION_ONLY` 永远默认不进入论文和官方提交；
- `SECURITY_AUDIT_ONLY` 只能进入内部审计材料。

---

# 11. 源码包与官方提交

`源码.zip` 应保留中文语义文件名，并包含：

- `第一题.py`、`第二题.py` 等问题主入口；
- `总运行.py`；
- 有实际用途的中文公共模块；
- 所有进入论文的中文绘图脚本；
- 必要的验证图脚本；
- 运行说明和文件名索引。

默认不把 AI 沟通图及其脚本放入官方源码候选。它们如果对队伍内部复盘有价值，可以进入内部“其他”材料或源码包的明确内部目录，但必须保留 `AI沟通图_` 标记。

正式提交前仍按当年官方规则检查中文文件名兼容性。如果需要兼容副本，必须记录映射并验证可运行，不能偷偷替换后让论文和 Run Ledger 指向失效路径。

---

# 12. 失败状态

发现正式 Python 使用无语义英文/临时名，或未按中文规则命名时：

```text
PYTHON_FILENAME_POLICY_FAILED
```

AI 沟通图缺少文件名、图面或 Manifest 任一标记时：

```text
FIGURE_PURPOSE_MARKING_FAILED
```

AI 沟通图进入论文、参考论文或官方提交候选时：

```text
AI_COMMUNICATION_FIGURE_LEAKED
```

修复前不得完成本问、生成最终参考论文或通过内部交付。

---

# 13. 最终检查

每问完成前检查：

- [ ] 本问主入口使用 `第一题.py / 第二题.py / ...`；
- [ ] 多模块文件使用“问题编号 + 中文职责”命名；
- [ ] 整题入口使用 `总运行.py`；
- [ ] 没有 `main.py / final.py / new.py / test.py` 等模糊正式文件名；
- [ ] 每张论文候选图有独立、可追溯的中文绘图脚本；
- [ ] 绘图脚本与输出图语义主干一致；
- [ ] 论文图从 Final/Validation Run 读取真实数据；
- [ ] AI 沟通图位于独立目录；
- [ ] AI 沟通图文件名含 `AI沟通图_`；
- [ ] AI 沟通图画布有“AI内部沟通图｜非论文材料”；
- [ ] Manifest 正确记录用途和论文/提交状态；
- [ ] AI 沟通图没有混入论文和官方提交；
- [ ] 中文文件名已在实际运行、ZIP 解压和目标环境中验证；
- [ ] 技术性英文文件名都有真实工具链理由。

一句话：**队员看文件名就知道它解决哪一问；评阅材料看图名就知道它能不能进论文。**
