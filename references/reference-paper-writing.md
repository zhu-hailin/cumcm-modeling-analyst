# AI 参考论文撰写规范

## 1. 边界

AI 参考论文是基于最终模型、Final/Validation Run、真实图表和已核验文献认真撰写的完整内部参考稿。

它不是网上论文合集，也不是官方参赛终稿。队员必须理解、核查并人工重写，之后再进入终稿复审。

Codex 默认保存：

```text
05_paper/
├─ outline.md
├─ draft.docx
└─ 参考论文.pdf
```

`final.docx/final.pdf` 只用于队员已经人工重写并确认的版本。

---

## 2. 写作前置条件

只有以下条件通过后才开始写：

- 文件安全审计与题意边界清楚；
- 原题 Requirement Traceability 完成；
- 每问 `FINAL_RUN_ID` 已冻结；
- 数据结构、模型前提、baseline、独立验证和现实约束通过；
- 最终数字、表格和图表来自 Final/Validation Run；
- 论文图通过 `python-visualization-policy.md`；
- Markdown 和 Word/PDF 公式方案可执行；
- 文献、外部数据、参数和链接已核验；
- 重大跨成果冲突已解决。

缺少实际运行或可靠数据时，应报告缺口，不得用编造内容补成“完整论文”。

---

## 3. 论文主线

整篇论文应形成统一模型链，而不是每问各做各的：

```text
题目背景与数据结构
→ 问题拆解
→ 各问模型及前后依赖
→ 实际结果
→ 独立验证与现实约束
→ 结论、限制与可执行建议
```

前问结果被后问复用时，明确写出复用的数据、参数、模型、阈值或结论，以及对应文件和 Final Run。

---

## 4. 摘要

摘要不是模型名称清单。每一问至少说明：

1. 处理了什么核心困难；
2. 为什么采用该方法；
3. 得到什么明确结果；
4. 如何验证及在哪些条件下成立。

推荐句式：

```text
针对问题 i，首先……以处理……；随后建立……模型，得到……。
结果表明……（给出最关键的定量结果或规则）；
通过……验证，结论在……范围内保持稳定。
```

“效果良好”“模型可靠”等空话必须由误差、准确率、区间、稳定率、目标函数改进、约束违反量或其他真实指标支撑。

---

## 5. 问题分析

每问建模前用简短文字解释：

```text
题目要求什么
→ 数据是什么结构
→ 主要困难是什么
→ 为什么当前模型能处理
→ 本问输出如何服务后问
```

不要重复摘要，不提前堆公式，也不要只写“因此采用某模型”。

---

## 6. 每问章节结构

按实际需要组织，通常包含：

```markdown
### 任务与结论目标
### 数据、结构和预处理
### 模型选择与适用前提
### 变量、公式、约束和参数
### 求解过程与最终结果
### 独立验证、敏感性和现实约束
### 本问结论、限制与向后问传递
```

每问必须直接回答原题，不能只写模型过程。

---

## 7. 结果解释

图表后的正文按证据组织：

```text
观察：图表中可核验的现象
→ 比较：与 baseline、组别或场景的差异
→ 解释：证据支持的原因或机制
→ 结论：回答原题哪一项
→ 限制：结论在哪些条件下成立
```

禁止：

- 逐格念表；
- 把不显著写成“完全独立”；
- 把相关写成因果；
- 把启发式当前最好解写成已证明全局最优；
- 把聚类簇编号直接命名为时间阶段；
- 只展示对主模型有利的场景。

---

## 8. 图表

论文图统一从 `04_results/VISUALIZATION_MANIFEST.md` 选择。

每张图必须能追到：

```text
论文图号与图注
↔ 图文件
↔ 中文绘图脚本
↔ Final/Validation Run
↔ 源数据
↔ 支撑的结论
```

图表要求：

- 使用最终数据和模型；
- 线图等保留矢量版本；
- 在最终 A4 插入尺寸下可读；
- 图题置于图下、表题置于表上；
- 坐标、单位、误差和样本量清楚；
- 色彩、线型和类别语义全文一致；
- 不使用 `AI_COMMUNICATION_ONLY`、`SECURITY_AUDIT_ONLY`、Stage 1 旧图或 `SUPERSEDED` Run 的图。

普通结果表使用可编辑表格，不把 DataFrame 截图成图片。

---

## 9. 公式与符号

- 符号、单位、上下标和代码映射全文一致；
- Markdown 母稿使用规范 LaTeX；
- DOCX 优先使用 OMML/Office 原生公式；
- PDF 中上下标、分式、求和和希腊字母正确显示；
- 公式名称、数学形式、代码函数和逆变换一致；
- 关键公式解释用途、变量、单位、前提和对应源码；
- 不为“显得高级”加入代码没有使用的公式。

失败时按 `equation-rendering-policy.md` 修复，不把裸 LaTeX 源码交付。

---

## 10. 文献与数据来源

严格区分：

- 题面给定数据；
- 官方/对象公开观测数据；
- 插值、外推和模型估计；
- 明确假设与仿真数据；
- 学术参考文献。

禁止编造作者、题名、年份、DOI、URL、下载状态和参数范围。

中国现实场景优先使用中国官方统计、对象官网、国内标准和本土应用研究；经典模型和原始算法可引用高质量国际文献。文献结构服务证据，不设置机械中外比例。

只有实际核验过的全文入口才能标为可下载。受限或仅有元数据时如实说明。

---

## 11. 优缺点与限制

优点必须具体到当前方案，例如：

- 保留时序/配对/成分结构；
- 满足容量、总和或守恒约束；
- 相比 baseline 的真实改进；
- 对关键参数扰动稳定；
- 结果可解释且能服务后问。

缺点说明：

- 数据、样本和外部口径限制；
- 模型前提；
- 计算规模；
- 对参数、初值或随机性的敏感性；
- 未验证的外推范围；
- 不能支持的因果或全局最优结论。

不写通用套话式“优点是简单，缺点是精度有限”。

---

## 12. 生成与验收

生成 `.docx + .pdf` 后检查：

- 文档真实存在、非 0 字节、可打开；
- 正文不是占位文本；
- 公式和中文字体正常；
- 图表没有模糊、裁切、乱码和旧版本；
- 摘要、正文、结论、表格和图注使用同一 Final Run；
- 引用与参考文献一一对应；
- 原题所有动作词和指定输出得到回答；
- AI 沟通图、安全审计图和内部提示没有混入；
- `final-consistency-sweep.md` 通过。

任何失败都应修复或向用户说明，不能因为需要交付就伪造完整状态。
