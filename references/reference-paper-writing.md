# AI 参考论文撰写与参考文献核验规范

## 1. 先区分两个概念

本 Skill 中以下两个概念必须严格区分，禁止混用。

### 参考论文

指 **AI 基于最终锁定建模路线、真实 Python 运行结果、最终图表和已核验参考文献，认真撰写的完整数学建模参考论文**。

它是最终交付成果的一部分，由 AI 自行编写，不是从互联网下载的他人论文，也不是“参考文献原文合集”。

最终放入：`参考论文.zip`。

### 参考文献

指论文中用于支撑背景、方法、参数、数据、模型定义和验证方式的真实外部资料，例如期刊论文、学位论文、官方报告、标准、教材和权威数据来源。

参考文献的元数据、链接和用途必须真实核验；不得把它们与“AI 自己写的参考论文”混为一谈。

---

## 2. 参考论文.zip 的目标

`参考论文.zip` 必须包含 AI 自行撰写的最终参考论文，不得因为无法下载外部论文全文而留空。

默认至少生成：

```text
参考论文/
├── 数学建模参考论文.docx
└── 数学建模参考论文.pdf
```

如果用户提供官方论文模板、格式文件或排版要求，应优先基于该模板生成 Word 与 PDF，并使用更贴合题目的文件名，例如：

```text
A题_参考论文.docx
A题_参考论文.pdf
```

如果当前环境可以创建 DOCX/PDF，必须实际生成；不得只输出论文结构或空占位文件。

如果当前环境确实缺少某种文件生成能力，应先尽可能完成论文正文并明确反馈缺失能力，不能以“外部参考文献无法下载”为理由拒绝撰写论文。

---

## 3. 参考论文必须认真编写

参考论文不能只是把 `题目详解.zip` 中的教程复制粘贴，也不能只是第二阶段分析报告改一个标题。

它必须按照正式数学建模论文的叙事方式重新组织，做到：

- 问题导向明确；
- 模型链统一；
- 公式、变量、数据和结果互相对应；
- 每个关键结论都有实际计算或验证依据；
- 图表来自最终 Python 运行产物；
- 参考文献真实且链接经过严格下载核验；
- 不虚构任何数值、实验、图表、参数来源或引用。

论文正文至少应根据实际赛题包含：

1. 论文题目；
2. 摘要；
3. 关键词；
4. 问题重述；
5. 问题分析；
6. 模型假设；
7. 符号说明；
8. 数据说明与预处理；
9. 总体建模路线；
10. 各实际子问题的模型建立与求解；
11. 关键结果与图表解释；
12. 模型检验、误差分析、敏感性或鲁棒性分析；
13. 模型优点、局限与改进方向；
14. 最终结论；
15. 参考文献；
16. 必要附录或源码说明。

子问题数量按题面实际情况调整，不固定三问。

---

## 4. 论文必须与源码和结果一致

参考论文中的以下内容必须可以在最终交付中追溯：

- 使用的模型与 `源码.zip` 实际代码一致；
- 参数与实际运行参数一致；
- 数值结果与 Python 输出一致；
- 图表与 `源码.zip/.../outputs/figures/` 中的实际图表一致；
- 表格与实际输出表一致；
- 敏感性、鲁棒性或验证结论来自真实执行结果；
- 不得出现“论文写模型 A、源码跑模型 B”；
- 不得为了论文看起来完整而补造结果。

若论文写作阶段发现源码或结果存在冲突，应先修正模型、代码或结果，再生成最终论文。

---

## 5. Word / PDF 公式必须真正渲染

最终论文中的公式排版必须完整遵循 [equation-rendering-policy.md](equation-rendering-policy.md)。

Markdown / 研究母稿可以使用 LaTeX 作为数学源，但 `.docx` 和 `.pdf` 中禁止把 LaTeX 字符串直接当普通文本输出。

例如：

```text
x_{icst}
Q_{cst}=\sum_p u_{pcs}x_{pcst}
\Pi_\omega
```

只能作为数学源，最终 Word/PDF 中必须显示为真正的上下标、求和符号和希腊字母。

特别要求：

- Word 优先使用 OMML / Office 原生公式对象；
- 使用 `python-docx` 时不得通过普通 `add_run()` 直接写入 LaTeX 字符串；
- 符号说明表第一列也必须正确渲染数学变量；
- 独立公式、行内公式、表格公式、附录公式都属于检查范围；
- PDF 不能只是把公式错误的 Word 原样导出；
- 生成后必须扫描 `_ {`（实际形式为 `_{`）、`\frac`、`\sum`、`\omega`、`$...$` 等 LaTeX 残留；
- 如果采用 OMML，应检查 DOCX 内存在 `m:oMath` / `m:oMathPara` 等数学对象；
- Word 和 PDF 都必须进行公式视觉检查。

只要发现最终文件仍存在未经渲染的 LaTeX / 伪公式，标记：

```text
FORMULA_RENDERING_FAILED
```

修复前不得进入 `FINAL_DELIVERY`。

---

## 6. 最终论文参考文献链接：必须能打开且能下载

这是强制要求。

最终参考论文中如果给出参考文献链接，该链接必须同时满足：

1. 页面或文件实际可打开；
2. 题名、作者、年份与目标文献一致；
3. 来源真实可靠；
4. 能实际取得对应全文，或明确进入真实、可用的全文下载入口；
5. 下载到的文件与目标文献一致；
6. 链接稳定，不依赖猜测参数、临时 Token 或不可复现会话。

也就是说，**最终论文中出现的参考文献链接必须达到 `DOWNLOAD_VERIFIED`**。

仅 `PAGE_VERIFIED`、`METADATA_ONLY`、`PAYWALLED`、`DOWNLOAD_UNVERIFIED` 的来源，不得把其链接写进最终参考论文冒充“可下载链接”。

如果某篇文献学术上很重要但找不到可靠可下载全文：

- 优先寻找同一文献的官方仓储、作者公开版本、机构仓储或可靠开放获取版本；
- 若仍找不到，必须反馈用户；
- 不得伪造下载地址；
- 在用户未决定前，不要把一个不可下载链接硬塞进最终论文。

---

## 7. 严禁伪造链接

禁止：

- 猜测或拼接 URL；
- 编造 DOI；
- 把搜索结果页地址伪装成论文地址；
- 把无法打开的链接写入论文；
- 声称“可下载”但实际没有验证下载入口；
- 用 AI 生成一个看似合理的链接；
- 因为论文题名真实，就自动认为某个链接真实；
- 把需要登录后临时生成的不可复现地址当稳定下载链接。

优先使用：

- 出版社/期刊/会议/高校/机构官方全文页面；
- DOI 对应正式页面中的合法全文入口；
- 作者或机构公开仓储；
- 学位论文官方库；
- 可靠开放获取仓储。

---

## 8. 核验状态必须分开记录

文献账本至少区分：

- `PAGE_VERIFIED`：页面已实际打开并确认元数据；
- `DOWNLOAD_VERIFIED`：已确认真实、可用全文下载入口；
- `METADATA_ONLY`：只核验到元数据；
- `PAYWALLED`：真实但受付费墙/机构权限限制；
- `BROKEN_LINK`：链接失效；
- `DOWNLOAD_UNVERIFIED`：页面存在，但未能可靠确认全文下载；
- `REJECTED`：来源不可靠或信息不一致。

只有 `DOWNLOAD_VERIFIED` 才允许出现在最终论文的“可下载参考文献链接”中。

---

## 9. 文献链接有问题时必须反馈用户

如果发现某条重要参考文献存在以下情况：

- 找不到稳定链接；
- 页面打不开；
- DOI 与题名不匹配；
- 下载链接失效；
- 只能查看摘要；
- 需要付费或机构权限；
- 下载文件与论文不匹配；
- 无法确认下载是否合法或稳定；

不得伪造替代链接，也不得静默跳过。

应：

1. 尽量继续寻找可靠替代来源；
2. 若找到等价且可下载的高质量来源，可替换并记录替换原因；
3. 若仍无法解决，明确向用户反馈具体问题；
4. 同时记录到 `其他.zip/文献与来源/文献问题反馈.md`；
5. 若该文献是模型关键依据且没有可靠替代来源，应标记为证据缺口，并提醒用户决定是否提供原文或更换依据。

严格核验不能成为 `参考论文.zip` 为空的理由。即使外部参考文献存在缺口，AI 仍应基于已完成模型和已核验证据认真撰写参考论文，同时对证据缺口做诚实说明。

---

## 10. 最终论文参考文献最低要求

最终参考文献列表优先只选择能够取得全文并完成 `DOWNLOAD_VERIFIED` 的高质量来源。

每条文献尽量记录：

- 作者；
- 题名；
- 期刊/会议/学校/机构；
- 年份；
- 卷期页码（真实核验后才写）；
- DOI（存在且已核验时）；
- `DOWNLOAD_VERIFIED` 链接；
- 核验日期。

如果某条文献无法取得可靠下载链接，必须先反馈用户并寻找替代来源，绝不能编造。

---

## 11. 最终论文质量检查

生成并交付 Word/PDF 前检查：

- 是否真的由 AI 基于本次赛题重新撰写，而不是外部论文合集；
- 是否覆盖所有实际子问题；
- 是否使用最终锁定路线；
- 结果是否来自实际 Python 执行；
- 图表是否来自最终 Python 输出；
- 公式和符号是否一致；
- DOCX/PDF 公式是否完成真正数学渲染；
- 符号说明表的数学变量是否正确渲染；
- 是否存在 `FORMULA_RENDERING_FAILED`；
- 是否存在编造的数值、模型效果或实验结论；
- 是否存在编造题名、作者、DOI 或 URL；
- 最终论文中出现的参考文献链接是否全部达到 `DOWNLOAD_VERIFIED`；
- 下载文件是否与文献元数据一致；
- 发现链接问题时是否已反馈用户并记录；
- Word 与 PDF 内容、公式和编号是否一致；
- 用户提供论文模板时是否按模板排版。

只有论文内容、公式渲染和参考文献核验均达到要求后，才进入 `FINAL_DELIVERY`。
