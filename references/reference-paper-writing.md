# AI 内部参考论文写作规范

## 1. 边界

AI 参考论文是基于冻结的 Final/Validation Run、论文证据蓝图、真实图表/表格和已核验文献写成的内部参考稿。

它不是网上论文合集，也不是可直接提交的参赛终稿。队员必须理解、核查并人工重写，之后再进入终稿复审。

Codex 默认保存：

```text
05_paper/
├─ outline.md
├─ PAPER_EVIDENCE_BLUEPRINT.md
├─ draft.docx
└─ 参考论文.pdf
```

`final.docx/final.pdf` 只用于队员已经人工重写并确认的版本。

涉及字号、页数、匿名、文件命名、参考文献格式等具体提交要求时，始终以当年竞赛官方规则、模板和 `official-submission-policy.md` 为最高优先级；本规范只固定长期有效的竞赛论文写作原则，不锁死到历史格式标准。

---

## 2. 写作前置条件

只有以下条件满足后才开始完整参考论文：

- 文件安全审计与题意边界清楚；
- Requirement Traceability 完成；
- 每问 Final Run 已冻结，必要 Validation Run 已完成；
- 每问分别记录 `SCIENTIFIC_VALIDITY` 和 `CONTEST_TASK_COMPLETION`；
- 数据、模型前提、baseline、独立验证和现实约束已审计；
- `02_analysis/PAPER_EVIDENCE_BLUEPRINT.md` 达到 `PAPER_EVIDENCE_BLUEPRINT_READY`；
- 总体学术技术路线图已经评估；
- 最终图表通过 `python-visualization-policy.md`；
- 公式、文献、外部数据、参数和链接可核验；
- 重大跨成果冲突已解决。

缺少真实运行或可靠数据时，应把对应蓝图项标记 `BLOCKED` 或 `NOT_IDENTIFIABLE`，不能用编造内容补成完整论文。

论文作者不得重新计算核心结果，也不得从聊天记录手抄数字；只从蓝图登记的 Final/Validation 成果读取。

---

## 3. 竞赛论文总原则：答案优先，但不能“问答式”

论文同时接受四个视角的检查：

```text
假设是否合理且确有必要
→ 模型是否针对实际问题并具有有效创造性
→ 结果是否正确、可信且与现实相符
→ 表述是否清楚、自明、连贯
```

创新只奖励解决真实困难的设计，不奖励复杂模型名称或“高大上”方法。简单模型若针对性更强、验证更充分，可以优于复杂模型。

每问正文开头仍优先使用：

```text
主答案
→ 关键数字/规则
→ 证据等级 A/B/C
→ 方法摘要
→ 独立验证
→ 限制与适用条件
```

但答案优先不等于写成“简答题”。正文必须继续回答：为什么这样处理、为什么这样假设、为什么选这个模型、如何求解、结果为什么可信、如何服务后续问题。

禁止把每问机械写成：

```text
根据问题分析
→ 利用 XX 方法建立模型
→ 使用 XX 软件求解
→ 结果如下图/表
```

整篇论文应围绕解决实际问题的主线逐步深入，而不是把各子问题视为互不相关的独立问答。

证据有限时仍给出当前最佳支持答案、证据等级和不确定范围。只有目标确实不可识别时使用 `NOT_IDENTIFIABLE`，并给出最强替代结论与补充数据需求。

整篇论文形成统一模型链：

```text
题目与数据结构
→ 数据处理与审计
→ 问题分析、假设与总体技术路线
→ 各问主答案和模型
→ Final/Validation 证据
→ 跨问接口
→ 结论、评价、限制与改进方向
```

---

## 4. 摘要

摘要不是模型名称清单，也不是正文目录的压缩版。应让评委不翻正文也能知道每问“做了什么、怎么做、得到什么、为什么可信”。

每问至少说明：

1. 处理了什么核心困难；
2. 采用什么方法或模型，以及最关键的选择理由；
3. 如何求解或验证；
4. 得到什么直接答案与关键定量结果；
5. 主要验证、不确定性和成立条件；
6. 有真实贡献时，再指出特色、创新或额外完成的有意义工作。

“效果良好”“模型可靠”等空话必须由真实误差、准确率、区间、稳定率、目标函数改进、约束违反量或其他指标替代。

摘要中的数字必须能在蓝图中定位到 Final/Validation Run 和正文位置。原则上不放复杂公式、图表、参考文献序号或无法自明的符号；篇幅服从当年官方模板，以信息完整、文字精练为目标。

---

## 5. 总体技术路线图

按论文证据蓝图的评估结果处理：

- `REQUIRED`：在问题分析之后、各问建模之前放置一张学术总体路线图；
- `NOT_NEEDED`：蓝图记录理由，不为形式强行画图。

路线图只展示输入数据、关键预处理、各问核心方法、Final/Validation 分支、正式跨问接口和最终输出。

必须由 Python 驱动的确定性脚本生成；复杂有向图可由 Python 调用 Graphviz。禁止海报、仪表盘、KPI 卡片、状态徽章、圆角卡片墙、App/网页 UI、发光、阴影和渐变背景。

若原流程图因海报化被淘汰，应按学术风格重画，不能直接删除这一证据角色。

---

## 6. 数据处理必须可见

论文不能只说“完成数据清洗”。至少用正文或一张集中审计表说明：

- 样本单位和数量；
- 原始、有效和排除数量；
- 缺失、异常、零值、重复和单位处理；
- 处理规则及题意/统计依据；
- 处理对结论的潜在影响；
- 最终建模数据版本。

完整长表可放附录，但关键口径必须在正文可见。

---

## 7. 问题重述、问题分析、假设与符号

### 7.1 问题重述

问题重述是对题意正确解读后的重新表达，不得简单复制题面。应明确：实际背景、已知条件、数据口径、目标、约束、交付对象与单位；对可能歧义的概念和边界给出必要澄清。

不要为了“结构完整”机械增加与题面同义的长段落。重述的价值是让后续模型对象和约束变得更清楚。

### 7.2 问题分析

问题分析回答“为什么这样解决”，而不是提前重复摘要或堆模型名。应说明：

- 关键困难和数据结构；
- 各因素之间的逻辑关系；
- 可能的建模切入点；
- 选择当前路线的适用性依据；
- 各问之间如何递进、复用或传递结果。

### 7.3 模型假设

假设是实际问题的必要简化，不能草率罗列。每条关键假设至少应能回答：

```text
为什么需要这个假设？
依据或合理性是什么？
它在哪个模型/公式/约束中真正被使用？
它可能怎样影响结果或适用范围？
```

不被后文使用的假设删除；只为方便求解但可能影响结论的强假设必须显式说明影响，并在必要时进入敏感性或情景检验。

### 7.4 符号

常用符号可集中说明，个别符号可在首次出现时解释。符号宜简不宜繁，优先采用常见、直观、单字母或规范上下标表达；同一符号不得跨章节改变含义，变量、单位、公式与代码命名必须一致。

---

## 8. 每问章节：先讲理，再给模型和结果

按实际需要组织，通常包含：

```markdown
### 主答案与证据等级
### 数据、结构和预处理
### 模型选择与适用前提
### 变量、公式、约束和参数
### Final Run 与主要结果
### 独立验证、敏感性和现实约束
### 模型评价、限制与向后问传递
```

标题应尽量体现“解决了什么问题”或“使用了什么关键方法/机制”，避免全文机械使用“问题 1 的模型建立与求解”“问题 2 的模型建立与求解”等模板标题。

### 8.1 模型选择与建立

数学模型是解决问题的手段，不是目的。给出模型表达式之前，先说明：

- 为什么当前问题需要这种建模方式；
- 为什么它比明显可选的替代方法更适用；
- 它利用了题目中的什么结构、约束或数据特征；
- 关键假设如何进入变量、目标函数、约束或状态转移。

随后再给出建模过程、公式和模型内涵。禁止无解释地直接抛出公式，也不要为了创新同时罗列多个模型却不比较主次、适用条件和差别。

### 8.2 模型求解

在给出结果前说明求解方法的依据、关键步骤和必要算法设置。若采用启发式、数值优化、仿真或机器学习，应解释为什么适合当前模型，并记录足以复现结论的核心参数、seed、停止条件或验证方式。

禁止只写“用软件编程计算得到如下结果”。软件只是求解工具，不是论证。

### 8.3 结果分析

结果段落优先按：

```text
观察 → 比较 → 解释 → 结论 → 限制
```

组织。结果不能停在“如图/表所示”，必须解释其数值意义、现实意义、约束满足情况以及与原题目标的对应关系。

禁止逐格念表、把不显著写成完全独立、把相关写成因果、把启发式当前最好解写成已证明全局最优，或把聚类簇编号直接写成确定阶段。

### 8.4 检验、敏感性与可靠性

关键模型和关键结论必须有与风险相匹配的检验证据。可根据题型选择：误差分析、独立验证、留出/外推、仿真核验、小规模精确解、现实数据对照、参数扰动、情景分析或决策翻转率。

不可缺少的是“结果为什么可信”的证据，而不是机械地每问都做同一种敏感性分析。若输入参数本身存在测量、统计或估计误差，并且这种误差可能传播到结论，应优先做敏感性或稳健性分析。

### 8.5 模型评价与改进方向

对模型的评价必须客观：优点不过度夸张，缺点不回避，创新点只写已经真实实现且确有作用的内容。

改进部分写“根据当前缺陷，下一步可以怎样改”，而不是在没有重新实现、运行和验证的情况下把设想写成已经完成的改进模型。

## 9. 后台成果选编

严格执行蓝图分类：

- `PAPER_CORE`：直接回答原题或支撑 A 级结论，必须进入正文；
- `PAPER_SUPPORT`：正文概述，完整敏感性、消融、参数或长名单进入附录；
- `RUN_ONLY`：调试、被否决候选和重复运行只留日志。

规则：

- 主答案和关键名单不能只存在 CSV/JSON；
- 不把所有后台表塞进论文；
- 图与表高度重复时保留更能支持判断的一种；
- 大矩阵和长名单采用“正文摘要 + 附录完整可编辑表”；
- 论文图不按数量配额生成；
- 图不能增加理解时使用 `FIGURE_NOT_NEEDED`。

## 10. 图表、公式与证据链

论文图从 `VISUALIZATION_MANIFEST.md` 选择。

数据结果图：

```text
论文结论
↔ 图号与图注
↔ 图片文件
↔ 绘图脚本
↔ Final/Validation Run
↔ 源数据
```

方法/流程图：

```text
Requirement ID
↔ 最终模型计划/假设
↔ 代码模块/算法步骤
↔ 绘图脚本
↔ 方法版本
```

不使用 AI 沟通图、安全审计图、Stage 1 旧图或 `SUPERSEDED` Run 图。

普通结果表保持可编辑。图、表应具有自明性，但不能与正文机械重复；正文先说明需要观察或比较什么，再出现对应图表。公式名称、数学形式、代码函数和逆变换一致；Word/PDF 中不能残留裸 LaTeX。

---

## 11. 系统性、连贯性与快速阅读链

论文不是多个子问题答案的拼接。问题与问题、章节与章节、模型与模型之间应有明确的前因后果：上游得到什么、为什么能交给下游、下游实际读取什么。

全文尽量形成：

```text
为什么这样做
→ 怎么做
→ 得到什么
→ 为什么可信
→ 对下一步有什么作用
```

避免同一种“套话段落”在每问重复出现。建模方法、公式、软件和图表都必须服务于当前问题，不允许“换数字不换叙事”的模板化写作。

论文初稿生成后，先自检以下位置是否形成连贯链条：

1. 摘要；
2. 总体路线图（若需要）；
3. 每问首段；
4. 主结果表与图题；
5. 结论。

仅阅读这些位置，应能回答：每问做了什么、采用什么模型、得到什么关键结果、哪里不确定、前后问如何连接。

页面级检查：

- 普通结果图是否无必要独占一页；
- 两张互补独立图同排时字号是否仍可读；
- 图是否紧裁剪、图题紧随、空白是否过大；
- 连续页面是否只有限制文字和稀疏图件；
- 长名单和大矩阵是否进入附录而不被隐藏；
- 主答案的视觉优先级是否高于免责声明。

---

## 12. 文献与外部数据

严格区分题面数据、真实外部观测、插值/外推/估计、假设/仿真和学术文献。

禁止编造作者、题名、年份、DOI、URL、下载状态和参数范围。中国现实场景优先查中国官方统计、对象官网、国内标准和本土应用研究；经典模型和原始算法可以引用高质量国际文献。

引用已有思想、方法、模型、算法、数据或经验公式时，应在正文实际使用处标注，并与文末参考文献对应。没有标注的内容会被理解为作者自己的工作。

正确引用不等于可以整段、整页照抄。即使给出引文标注，也不得大段复制文字、公式、图表或完整算法；应把文献中的思想和方法重新适配到当前题的数据、变量、约束和证据链中。

参考论文只能提供抽象研究设计和组织经验，当前题的变量、阈值、参数、结果、图表和结论必须重新运行验证。

---

## 13. 结论

结论不是摘要原文重复，也不是只写“模型具有较好效果”。应围绕原题交付项归纳：

- 每问最终主答案和关键数字/规则；
- 最重要的模型机制或决策依据；
- 主要验证与可靠性边界；
- 前后问形成的整体认识；
- 仍然存在的关键限制和改进方向。

结论中的数字、强度和范围必须与正文及同一 Final/Validation Run 一致，不新增正文未证明的新结论。

---

## 14. 生成与验收

生成 DOCX/PDF 后检查：

- 文件真实存在、非 0 字节且可打开；
- 正文不是占位文本；
- 每个原题交付项有可定位主答案；
- 科学有效性与竞赛完成度没有混淆；
- 蓝图中的 `PAPER_CORE` 已进入正文；
- 问题重述不是题面复制，问题分析能够解释建模路线；
- 关键假设有必要性、合理性、正文用途和影响说明；
- 关键模型在公式前说明选择依据和适用性；
- 求解部分不以“软件算得”代替方法与过程；
- 关键结果有解释、验证以及必要的敏感性/稳健性证据；
- 各问不是互相独立的问答，跨问接口和全文主线连贯；
- 模型评价客观，改进设想没有冒充已完成结果；
- 总体路线图结论已落实；
- 图表在最终 A4 尺寸下清晰且没有海报风；
- 公式和中文字体正常；
- 摘要、正文、图表和结论使用同一 Final Run；
- 引用与参考文献对应，不存在大段照搬；
- AI 沟通图、安全审计图和内部提示未混入；
- 快速阅读链可复述每问核心结论；
- `final-consistency-sweep.md` 通过。

失败应修复或向用户说明，不能因为需要交付就伪造完成状态。
