# 论文协作与论证写作规范

## 1. 边界

论文工作稿基于已核验的逐问分析、真实图表/可编辑表格和已核验文献持续形成；已有跨问证据蓝图时引用它，章节写作不以新建完整蓝图为前提。定稿中的核心结论使用冻结的 Final/Validation Run。

队员应理解、核查、参与表达并确认。已有人工摘要、术语和有意采用的排版是修订基准，不默认整体重写；适用规则另有重写、披露或提交要求时按规则处理。

默认：

```text
02_analysis/PAPER_EVIDENCE_BLUEPRINT.md   # 需要跨问证据管理时维护
05_paper/
├─ outline.md
├─ draft.docx
└─ 参考论文.pdf
```

`final.docx/final.pdf` 只用于证据、正文和版面已验收并经队员确认的版本。文件名本身不证明可以提交。

字号、页数、匿名、文件命名和提交格式以当年官方规则/模板为最高优先级。

Word 与 LaTeX 均可用于专业排版，按团队熟练度、协作需求和官方交付要求选择。格式验收看公式、字体、层级、图表和跨页一致性，不给软件工具排优劣；不为换工具而增加赛时迁移风险。

新稿可从[论文骨架模板](../assets/PAPER_OUTLINE_TEMPLATE.md)开始：摘要 → 背景与重述 → 全题分析 → 假设与符号 → 各问建立、求解和验证 → 模型评价 → 改进与综合结论 → 文献及支撑材料接口。该骨架提炼论证职责，不固定问题数量、章号或必须使用同一模型。

---

## 2. 从提纲到章节，再到定稿

只整理早期主线时使用[提纲模板](../assets/PAPER_OUTLINE_TEMPLATE.md)的早期部分，无需加载本文件、证据冻结或终稿验收细则。开始写已有结果的章节时再使用本规范，按当前章节需要阅读相关小节；未完成部分标记缺口，未验证结果不能写成确定结论。

随题补入模型理由、推导、结果解释与摘要素材。整题证据冻结按[证据架构](paper-evidence-architecture.md)，`PAPER_EVIDENCE_BLUEPRINT_READY` 不限制何时开始工作稿。核心数字引用[运行账本](model-run-ledger.md)中的有效成果；缺少运行或可靠数据时保留缺口，不靠文笔补出答案。

文档渲染时按[公式排版](equation-rendering-policy.md)检查实际页面；终稿验收再加载[最终审查](final-paper-audit.md)与[一致性扫描](final-consistency-sweep.md)。章节写作不顺带执行完整终稿或打包验收。

---

## 3. 总原则：问题驱动，不写成 Agent 日志

论文的核心评价逻辑可以概括为：

```text
题意理解是否准确
→ 假设是否必要、合理且真正被使用
→ 模型是否针对实际问题
→ 求解是否正确、可复现
→ 结果是否可信并满足现实约束
→ 表述是否清楚、连贯、自明
```

复杂模型名不是创新。创新只写真实实现并解决了实际困难的设计。

内部项目可以使用 `FINAL_RUN_ID`、A/B/C 证据等级、PASS/FAIL 等状态；**正式论文正文不机械展示内部 Agent 状态。** 正文用实际验证、误差、稳定性、适用范围和限制来表达证据强度。

每问开头优先让评委看到：

```text
直接答案 / 关键发现
→ 关键数字或规则
→ 方法概要
→ 最重要验证
→ 适用条件与限制
```

随后完整解释“为什么、怎么做、为什么可信”，避免写成简答题。

---

## 4. 摘要

各问随题积累摘要素材，开始组织或审改摘要时按[摘要与论证协作](abstract-and-argumentation.md)。摘要需自明地连接困难、设计、关键证据与最终判断，省去无助理解的复杂公式和内部符号。

---

## 5. 问题重述与问题分析

### 问题重述

不是复制题面，而是明确：

- 实际背景；
- 已知条件与数据口径；
- 目标、对象、约束和交付项；
- 单位、范围和必要边界；
- 对题面歧义的合理澄清。

没有新增信息价值的同义长段落可以删。

### 问题分析

问题分析回答“为什么这样解决”，重点说明：

- 关键困难和数据结构；
- 因素/变量之间的逻辑关系；
- 为什么从当前机制或数学结构切入；
- 当前路线相对明显替代方法的适用性；
- 前后问题如何递进、复用和传递结果。

不要只写“问题一用 XX，问题二用 YY”。

---

## 6. 模型假设：每条都要有用途

每条关键假设至少回答：

```text
为什么需要？
依据或合理性是什么？
它在哪个模型 / 公式 / 约束中真正使用？
它可能怎样影响结果或适用范围？
```

不被后文使用的假设删除。

仅为了方便求解但可能显著影响结论的强假设，必须说明影响；必要时进入敏感性、情景分析或稳健性检验。

不要罗列“空气阻力忽略、对象均匀”等与当前模型无关的模板化假设。

---

## 7. 符号、公式与量纲

符号宜少而清楚。同一符号不得跨章节改变含义。

关键公式出现前先解释为什么需要它，出现后说明：

- 变量含义；
- 单位/量纲；
- 参数来源；
- 数学或现实含义；
- 对应代码模块/算法步骤。

禁止为了“看起来数学”增加代码中根本没有使用的装饰公式。

目标函数、关键约束、变换与逆变换必须与代码一致。

---

## 8. 每问章节：建模逻辑优先

章节可按实际题型组织，不要求机械套固定标题。典型论证链：

```text
直接答案与本问目标
→ 数据与结构
→ 为什么选择当前模型
→ 模型建立：变量、公式、约束、参数
→ 如何求解
→ 主要结果
→ 为什么可信：验证 / 敏感性 / 现实约束
→ 局限与向后问接口
```

### 8.1 为什么选这个模型

在公式之前说明：

- 当前问题真正难点是什么；
- 模型利用了什么数据结构、机制或约束；
- 为什么比明显替代方法更适用；
- 复杂度是否带来真实收益。

路线明显时不用为了“比较充分”强行罗列多个模型。

### 8.2 如何求解

不能只写“使用 Python/MATLAB 求解得到结果”。

对于数值优化、启发式、仿真或机器学习，解释足以复现结论的：

- 算法/求解方法；
- 关键参数或停止条件；
- seed / 重复机制（适用时）；
- 可行性修复、数值稳定或验证设置；
- 为什么这种求解方式适合当前模型。

软件只是工具，不是论证。

区分数学模型、求解算法、求解器和经验策略：模型表达现实关系、目标和约束，算法负责估计或求解，求解器是实现工具，经验策略是基于规则的决策办法。同一模型换求解器应写为求解改进，不能冒充多个独立模型。比较路线时交代统一评价口径及选优取舍，不把全部探索过程写进正文。

### 8.3 结果分析

优先按：

```text
观察
→ 比较
→ 解释
→ 回答原题
→ 限制 / 适用条件
```

结果不能停在“如图表所示”，必须解释数值和现实含义。

题目要求方案或决策时，进一步给出适用对象、采取的行动和触发条件。例如识别出瓶颈后说明资源应调到哪里、受什么容量约束，核对方案可执行；仅排名或指标改善尚未直接回答行动要求。条件不足时保留条件性建议，不写成已经可实施的结论。

禁止：

- 逐格念表；
- 把不显著写成完全独立；
- 把相关写成因果；
- 把启发式当前最好解写成已证明全局最优；
- 把聚类簇编号直接命名为确定阶段；
- 用最好 seed 或最有利场景冒充稳定性/普遍优势。优化题最终方案可以选最好已验证可行解，并交代选择规则和相应证据。

### 8.4 验证、敏感性与可靠性

验证强度与结论风险匹配，不机械要求每问做同一种敏感性分析。

可根据题型选择：

- 残差/误差分析；
- 滚动、分组、留出或外推验证；
- 独立算法或不同原理验证；
- 小规模精确解 / 上下界；
- 现实数据对照；
- 参数扰动、情景分析和决策翻转率；
- 多 seed / bootstrap。

核心不是“做了多少实验”，而是“结果为什么可信”。

每问明确写出最优性或有效性的论证方式，并匹配题型：精确优化可使用证明、原始/对偶界、可行解与最优间隙，说明容差和范围；启发式使用可行性、界或小规模基准和重复运行，不能把最好已知解称全局最优；预测题检查面向真实场景的泛化、泄漏和误差；评价/识别题检查前提、稳定性与外部或机制依据；仿真/机理题检查守恒、收敛、校准和现实对照。不是每问都应证明“最优”，但每问都要说明其结论如何得到支持。

敏感性实验及其决策解释按[建模研究 Playbook](modeling-research-playbook.md)第 11 节；正文保留影响主要判断的变化与成立范围。

### 8.5 创新与小改进的表达

仅对实际完成且有依据的改进组织：原方法不足 → 本题具体改动 → 有效机制 → 对比/消融结果 → 代价与边界。
突出一个解决真实难点的改进即可；不以模型名新、堆叠算法或排版美观代替创新证据。无明显提升时如实写取舍，不写“显著优越”“首次提出”等无支持表述。

### 8.6 关键结果集中呈现

每问结果段优先给一份紧凑主结果表或清楚的数值句，包含对象、数值、单位和必要条件；精确方案/名单用可编辑表，趋势和结构用图，不强制两者都做。
主答案不只留在日志或长附录中；加粗只强调少量关键发现并服从模板，不整段加粗，不重复堆同一组数字。

---

## 9. 数据处理必须可见

不能只写“完成数据清洗”。关键口径至少说明：

- 样本/决策单位与数量；
- 原始、有效、排除数量（适用时）；
- 缺失、异常、零值、重复和单位处理；
- 处理规则及题意/统计依据；
- 插值、估计、仿真与真实观测的区别；
- 处理对结论可能造成的影响；
- 最终建模数据版本。

长表可以放附录，但影响结论的处理规则必须在正文可见。

---

## 10. 图表与总体技术路线

图表的赛中 Python+nature-figure 生成、来源接口及图表下说明统一按[绘图规范](python-visualization-policy.md)。写作只决定图表支撑哪项判断、放在哪段论证中；图与表高度重复时保留更直接的一种，大矩阵和长名单用“正文摘要 + 附录完整可编辑表”。

总体路线图确有必要时展示输入、方法、验证、真实跨问接口和输出，不展示内部 Agent 状态。尚未选入正式证据的探索图留工作区；入选及更新按[交付规范](final-delivery-packaging.md)。

---

## 11. 后台成果选编

正文、附录及后台材料的分层按[证据架构](paper-evidence-architecture.md)第 3 节；正式成果入选及动态同步按[交付规范](final-delivery-packaging.md)。

不要让论文变成项目目录转储，也不要因为“简洁”把直接答案和关键证据藏在后台文件里。

精简先删重复，保留建模动机、方法来源、比较条件和结论边界。删段或移表前回查题面及蓝图 `required_location`；题面要求正文展示的项目不能仅因节省页数移入支撑材料。批量排版修改先验证代表页面，再检查实际渲染，保护队员有意采用的格式。

---

## 12. 文献与外部数据

严格区分题面数据、真实外部观测、插值/外推/估计、假设/仿真和学术文献。

- 不编作者、题名、年份、DOI、URL 或访问状态；
- 引用已有思想、模型、算法、数据或经验公式时，在实际使用位置标注；
- 参考论文只借鉴研究设计和证据组织，当前题参数、阈值、结果和图表重新运行；
- “文献真实且支持当前主张”与“存在公开可下载全文链接”分开判断，遵循 `source-verification-policy.md`。

---

## 13. 全文连贯性

论文不是多个独立问答的拼接。每问都应该接上整体主线：

```text
为什么这样做
→ 怎么做
→ 得到什么
→ 为什么可信
→ 对下一步有什么作用
```

重点检查：

1. 摘要；
2. 总体路线图（需要时）；
3. 每问首段；
4. 主结果表与图题；
5. 结论。

只看这些位置，应能复述每问的直接答案、核心模型、关键结果、主要不确定性和跨问接口。

问间过渡交代“前问产物是什么、为什么成为本问输入、本问新增了什么”。题目本来独立时说明共同背景或不同目标即可，不虚构依赖关系。

---

## 14. 结论

结论围绕原题交付项归纳：

- 每问最终答案和关键数字/规则；
- 最重要的模型机制或决策依据；
- 主要验证和可靠性边界；
- 前后问形成的整体认识；
- 仍存在的关键限制和真正可行的改进方向。

不要新增正文从未验证的新结论。

---

## 15. 生成与验收

渲染检查、最终技术核验与论文评阅分别按第 2 节对应入口执行。完成状态只使用[核心流程](core-workflow.md)的定义，交付只使用[交付规范](final-delivery-packaging.md)的当前有效成果；检查未过时报告具体缺口。
