# 单代理与三角色协作

## 1. 选择与恢复

协作模式记录在项目现有 README：`agent_mode: SINGLE | THREE_ROLE`。先继承用户已作选择；首次完整赛题未选择时只问一次，未选定前可继续阅读与准备，不自动派生子代理。局部规划、解释、审稿或修图不为模式增加提问。此字段只描述人员分工，不改变产品的计划/执行模式。

`SINGLE` 由主代理按相同证据、写作和交付标准顺序完成。`THREE_ROLE` 使用主代理总控与三个固定子角色，按需唤醒并复用已有角色；无需每阶段全部并发，不为新问题重复创建同职责代理。无子代理工具时说明能力限制，由主代理顺序接手，不能声称已经委派或把默认单代理降为较低验收标准。

用户切换模式时，停止派发新任务，先收拢正在运行任务的有效成果、输入版本、未完成项和文件所有权。不能让旧角色和接手者同时写同一文件；必要时等待任务结束或明确交回写权限，再更新 README 的模式与接手信息。

## 2. 固定职责与文件所有权

| 执行者 | 主要责任 | 默认写入范围 |
|---|---|---|
| 主代理总控 | 题意与授权边界、分工、统一版本、证据验收、取舍冲突、交付与最终对外说明 | 项目 README、权威蓝图、统一状态与交付入口；共享文件只由主代理指定的一名写入者维护 |
| 建模手 | 机制判断、变量与约束、关键推导、备选取舍、失效条件和验证设计 | 既有逐问分析文件；有 `q{k}_model.md` 时沿用，否则使用 `q{k}_solution.md` 对应部分 |
| 代码手 | 输入处理、模型实现、真实运行、验证计算、Python 论文图表与来源记录 | 本次指定的代码/输出目录和独立 Run；公共模块的修改须取得明确所有权 |
| 论文手 | 从读题起梳理论文主线、逐问论证材料、摘要候选、整稿衔接与快读审查 | 本次指定的论文草稿或章节；保留队员已有主线、语气与有效表达 |

表中是职责映射，实际工程已有文件名优先。每个任务必须给具体可写路径，不能只写“代码都归代码手”。共享原题、原始数据和已冻结输入只读；同一正式文件只允许一个写入者。确需交接同一文件时先结束原任务并登记接手，不采用双方各改一版再盲目覆盖。

主代理保留最终核验责任。角色之间有争议时回到题面、数学推导、输入版本与独立实验，不按票数决定，也不把三个角色都说“通过”当三份独立验证。

## 3. 派发与接收

派发采用 [任务单](../assets/SUBAGENT_TASK_TEMPLATE.md)，至少包含：当前问及确认依据、目标和停止条件、输入路径与版本、已有审计位置、可写范围、期望产物、验证方法、上游依赖与禁止越界事项。只给必要上下文，优先传文件和证据位置，避免复制整段聊天。

子角色接收任务后先核对输入是否实际存在、版本是否一致。输入更新或依赖缺失时说明影响，不从聊天手填替代值。运行使用独立 Run 目录，不并写同一个 `latest` 输出；事实和 hash 引用 [运行账本](model-run-ledger.md)，不另建第二份运行元数据。

交回时给出：实际读取的输入版本、已改/新增文件、主要发现与证据、运行与验证状态、关键决策引用、论文可以主张什么、限制和未完成项。工具运行成功、模型结论成立和论文已可用分别说明；没有运行则标待运行。

主代理核对任务边界、文件差异、结果来源与关键验证，解决冲突后才纳入蓝图、论文和交付目录。独立复核应针对主要失效方式重新推导、复算或使用另一验证口径；照读求解日志不算独立复核。需要进一步验证时复用现有角色，不为固定角色之外再机械创建“投票代理”。

角色每次形成新成果或发现旧成果失效就交回变化范围；主代理按 [动态交付规则](final-delivery-packaging.md) 当轮更新支撑材料、说明及清单，不等三个角色或整问全部结束。交付目录仍由主代理统一写入，未核验的变更先显示过期/待更新，不复制半成品。

## 4. 每问的协作节奏

1. 用户确认当前问之前，建模手可以研究方案，代码手可以检查数据结构、接口与实现可行性，论文手可以梳理主线与证据缺口；不得以探索或可行性检查名义提前正式求解未确认问题。
2. 当前问确认后，建模手交清公式、单位、约束与验证要求，代码手实现并真实运行；论文手并行形成已有依据的解释与章节骨架，未完成数值显式留待验证。
3. 结果形成后，代码手按 [绘图规范](python-visualization-policy.md) 的稳定入口，使用 Python 在本问阶段生成所需论文图表；建模手/主代理核验机制和结论边界，论文手把已核验成果写成连贯论证，并为每张图表提供放在下方的解释性图注/表下注及正文分析。注释须说明展示内容、反映什么和支持什么判断，不能只有标题。不能等比赛末尾统一补画。
4. 主代理分别报告计算、核验、论文材料、交付状态，更新有效成果与版本。当前问完成后暂停，进入下一问方案讨论仍需用户单独确认。

论文手从早期介入，但不能反向要求代码“做出”预设结论。写作发现逻辑、数据或证据缺口时交回相应角色修复；答案可用后，将增量预算优先给关键论证、摘要和一致性，低收益调参可以停止。正确性和决定性验证仍是底线。

## 5. 小任务与中断

局部任务只唤醒实际需要的角色，单代理可直接完成，不人为补齐三份产物。运行中断、上下文压缩或角色失效后，从 README、任务单及权威成果恢复；继承审计锁和已确认方案，不重做首轮流程。保留失败证据和已验证文件，明确未完成项，不能把“角色结束”误报为“任务完成”。
