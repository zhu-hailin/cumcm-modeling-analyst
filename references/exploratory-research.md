# 第一阶段探索性研究规范

## 目标

第一阶段不能只靠题面关键词和模型常识“拍脑袋选算法”。在形成候选方案和推荐分之前，AI 应先对题目与附件做与决策有关的探索性研究，用真实证据回答：数据到底长什么样、关键假设是否成立、哪些模型值得进入正式候选。

探索性研究服务于**理解题目和选择路线**，不是提前完成最终求解。

可视化同时遵循 [python-visualization-policy.md](python-visualization-policy.md)，但 Stage 1 只允许生成会影响选模、数据理解或风险判断的 C 级探索图，不因为后续有完整 Visualization System 就提前堆正式论文图。

## 允许的探索性 Python

在 Codex、本地 Python 或其他可执行环境可用时，第一阶段允许并鼓励进行轻量探索，包括：

- 读取全部工作表、字段、数据类型、样本量和时间/空间范围；
- 检查缺失、重复、异常值、量纲、编码和明显数据质量问题；
- 描述统计、分布、分组差异和必要的基础可视化；
- 变量关系、相关性或共线性初查，但不得把相关直接写成因果；
- 时间序列的趋势、周期、季节性、自相关、结构突变和样本长度检查；
- 分类/聚类任务的数据规模、类别分布、可分性或聚类倾向初查；
- 优化问题的规模、约束可行性、图结构、搜索空间和计算复杂度初查；
- 简单 baseline、极小规模原型或可行性实验；
- 对候选模型关键前提做针对性测试；
- 对预计运行成本、数据需求和失败风险做实证判断。

探索性研究应优先回答“这会不会改变模型选择”，而不是为了图多或代码多而做分析。

## 第一阶段不做什么

第一阶段通常不做：

- 最终生产级代码工程；
- 全部正式结果与最终结论；
- 大规模超参数搜索；
- 长时间穷举或完整仿真；
- A/B 级正式论文图系统；
- 为了后续 Manifest 提前制造大量图；
- 最终论文排版；
- 为了提前交差而把探索性结果冒充最终结果。

如果一个实验已经等同于正式求解，应留到用户确认路线后的第二阶段。

## 评分必须吸收探索证据

每一问候选方案的推荐分应在探索后给出或更新。至少考虑：

- 题意是否匹配；
- 当前数据是否支持；
- 模型关键假设是否明显违背；
- baseline 是否已显示简单方法足够；
- 样本量是否支撑复杂模型；
- 计算规模是否现实；
- 是否存在可验证输出。

若探索结果推翻原先判断，应主动调整推荐分，不得为了维持第一次判断而忽略证据。

## 与各问题的关系

探索性研究分为两类：

### 全局探索

一次完成整题共享的信息，例如数据结构、公共字段、时间范围、统一单位、共享变量和问题依赖。

### 问题级探索

针对某一问决定模型选择的探索，例如：

- 问题一需要检查评价指标的分布和冗余；
- 问题二需要检查时间序列结构；
- 问题三需要检查优化规模和可行域。

逐题深解模式下，每进入一个新问题还应重新做必要的问题级探索，并结合上一问真实结果更新判断。

## Stage 1 图表存在的理由

任何探索图都应能回答至少一个问题：

- 是否改变候选模型；
- 是否暴露数据质量问题；
- 是否验证/否定模型前提；
- 是否改变参数、验证方案或计算策略。

若删除该图不影响上述任何判断，则通常不应生成或保留。

## 输出要克制

Stage 1 面向用户只展示**会影响路线选择的关键探索证据**，通常每问 2–5 条即可。不要把完整 EDA 日志、几十张统计图或长表格直接塞进第一阶段回复。

完整探索代码与有价值的结果可以保存到：

```text
源码/赛题A/问题1/outputs/figures/exploration/
```

真正进入 Stage 2 的论文图、验证图和正式表格在路线确认后再生成。

若探索代码或结果对最终方案没有实际价值，可清理无用临时产物；凡在路线选择或论文中被引用的探索证据必须可追溯。

## 诚实边界

- 没有实际读取的数据，不得声称已完成数据审计；
- 没有实际运行的探索实验，不得写成“实验表明”；
- 样本量太小或证据不足时，明确写“暂定”；
- 探索性结果只用于路线判断时，不得冒充最终正式结论。
