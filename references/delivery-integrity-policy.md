# 交付环境识别与 ZIP 完整性验收规范

## 目标

内部成果的交付方式必须根据运行环境调整，不能把 Chat / 云端文件下载场景的限制机械套到 Codex 本地工作区，也不能因为 Codex 在本地就省略验收。

> **本地工作区以真实目录为主，ZIP 是打包副本；Chat / 云端以可下载文件为主，ZIP 必须做更严格的跨平台预检。**

任何“ZIP 已生成”都不等于交付完成。

失败：

```text
DELIVERY_INTEGRITY_FAILED
```

修复前不得标记 `INTERNAL_DELIVERY_COMPLETE`。

---

# 1. 识别环境

## LOCAL_WORKSPACE_DELIVERY

Codex / Claude Code / 本地 Agent 在明确项目根目录中工作，可以直接读写本地文件和执行命令。

成果文件直接存在本地磁盘，ZIP 用于整理、传输和归档，不是唯一成果载体。

## CHAT_ARTIFACT_DELIVERY

Chat / 云端会话通过可下载附件交付，用户主要依赖 ZIP/文件链接，因此更关注文件名编码、下载层和解压软件兼容性。

无法判断时采用更严格的 `CHAT_ARTIFACT_DELIVERY` 验收。

---

# 2. Codex / 本地工作区

不应只生成四个 ZIP 后删除原目录。

推荐：

```text
<project-root>/deliverables/
├── 题目详解/
├── 参考论文/
├── 源码/
├── 其他/
├── 题目详解.zip
├── 参考论文.zip
├── 源码.zip
└── 其他.zip
```

用户指定输出目录时以用户目录为准。

四个未压缩目录是主成果，ZIP 是副本；打包失败不得影响原始成果。

本地可以保留清晰中文文件名，不需要为了 Chat 兼容性全改 ASCII。

如果当前压缩工具对中文 entry 存在兼容问题，可只对 ZIP 内路径 fallback 到 ASCII-safe，并用 `README.md / MANIFEST.md` 写中文映射。

---

# 3. Chat / 云端交付

- 外层仍保持四个中文 ZIP 名；
- ZIP 内中文路径必须真实验证；
- 无法稳定处理中文 entry 时才回退 ASCII-safe；
- `README.md / MANIFEST.md` 保留中文说明；
- 平台支持时，参考论文 DOCX/PDF 可额外独立交付作为兜底。

不能因为运行时目录里有文件就忽略用户下载后“空包/乱码”的问题。

---

# 4. 打包前检查源目录

至少确认：

- 关键文件真实存在；
- 非 0 字节；
- DOCX/PDF 质量检查已完成；
- Markdown 教程已完成；
- 源码、图表、表格和结果已写完；
- 没有空占位文件。

推荐先形成完整 staging / deliverables 目录，再统一打包。

---

# 5. ZIP 第一轮：结构测试

例如：

```bash
unzip -t 参考论文.zip
```

或等价 CRC / entry 检查。

`unzip -t` 通过只说明压缩结构基本正常，不代表用户真的能使用。

---

# 6. ZIP 第二轮：真实解压

每个内部 ZIP 必须实际解压到新的临时目录，并从**解压副本**检查：

- 文件数量和目录结构；
- 文件名是否乱码；
- 文件大小；
- 关键文件是否存在；
- 是否有 0 字节文件；
- Markdown/Python/文本是否可读；
- DOCX 是否有效；
- PDF 是否有效且页数 > 0；
- 图表/表格是否存在且非空。

禁止只检查打包前目录就声称 ZIP 已验证。

---

# 7. MANIFEST 对账

推荐每个成果目录根部生成 `MANIFEST.md`：

| 相对路径 | 内容说明 | 文件大小 | SHA-256 | 必须存在 |
|---|---|---:|---|---|

打包后解压，再核对路径、字节数和 SHA-256。

源目录有文件但解压后丢失、文件名无法对应、大小/hash 异常或关键文件打不开时，标记 `DELIVERY_INTEGRITY_FAILED` 并重新打包。

---

# 8. DOCX / PDF 额外验收

DOCX 至少检查：大小 > 0、容器可打开、`word/document.xml` 存在、正文非空、公式规范通过。

PDF 至少检查：大小 > 0、解析器可打开、页数 > 0、关键公式/图表页视觉检查通过。

Chat 模式平台支持时可额外提供 DOCX/PDF 独立下载；Codex 本地不需要下载链接，因为文件就在工作区。

---

# 9. 最终聊天回复必须真实

只有验证通过后才能说：四个 ZIP 已生成、能正常解压、关键文件存在并可打开。

如果本地成果目录完整但 ZIP 失败，应明确区分：“本地成果完整，但 ZIP 预检未通过”。

---

# 10. 验收清单

## LOCAL_WORKSPACE_DELIVERY

- [ ] 项目根目录 / 输出目录明确
- [ ] 四个未压缩成果目录存在
- [ ] 关键成果可直接打开
- [ ] 四个 ZIP 从这些目录创建
- [ ] 每个 ZIP 结构测试通过
- [ ] 每个 ZIP 实际解压一次
- [ ] 中文文件名 / 内部路径正常
- [ ] 打包前后关键文件一致
- [ ] 原始成果目录未删除

## CHAT_ARTIFACT_DELIVERY

- [ ] 四个 ZIP 实际生成
- [ ] 内部路径兼容性确认
- [ ] 结构测试通过
- [ ] 实际解压通过
- [ ] 解压后数量 / 文件名 / 大小正确
- [ ] DOCX/PDF 可打开且非空
- [ ] 平台支持时有论文独立文件兜底
- [ ] 不存在“运行时有文件、用户下载包却像空包”的情况

任一关键项失败：

```text
DELIVERY_INTEGRITY_FAILED
```

修复后才能标记：

```text
INTERNAL_DELIVERY_COMPLETE
```
