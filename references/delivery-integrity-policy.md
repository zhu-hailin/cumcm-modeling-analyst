# 交付环境识别与完整性验收

## 1. 环境与交付入口

`LOCAL_WORKSPACE_DELIVERY`：Codex 或获准使用本地工作区的 agent 在单赛题目录工作，按 [工作区规范](local-workspace-policy.md) 保留原件、数据、源码、结果与论文工作稿。默认交付入口是 `workspace_root/交付文件夹`，用户指定外部目录或已有目录时沿用。

`CHAT_ARTIFACT_DELIVERY`：云端会话以下载附件交付。按同样目录组织有效成果，再导出平台可下载的目录包或用户需要的分类包；论文成品可另附独立文件。实际验证中文路径，只有工具确有兼容问题时才回退 ASCII 路径并提供中文映射。

无法判断环境时，采用附件交付的可下载、解压与可读性要求，但不虚构用户本机路径。

所有环境都仅验收用户请求的范围。四包不是必经步骤，生成了文件或 ZIP 也不代表交付完成。

## 2. 冻结、清单与依赖

交付结构及说明使用 [交付目录规范](final-delivery-packaging.md)。工作稿、旧结果和审核稿留在工作区，交付目录只指向一个当前有效版本。

进入验收前：

- 文件写入已结束；关键成果真实存在、非空，来源是当前 Final Run、可复核推导或经确认论文。
- 明确正式计算环境和图表来源；工具按实际采用情况记录，不把 SPSSPRO 设为必需项。
- 从入口脚本及说明检查全部依赖，包括 Markdown、配置、辅助代码和数据；不按扩展名盲删。
- 外部依赖给出获取方式；许可不允许再分发的输入不擅自打包。
- `交付说明.md` 给出运行顺序、预期输出、限制和未完成项；论文附录文件名与交付清单一致。

从选定源成果生成独立 JSON 清单：

```json
{"files": [{"path": "支撑材料/01_结果表/结果.csv", "size": 123, "sha256": "实际64位hash"}]}
```

路径相对本次验收根目录，清单不记录自己的 hash。可将清单副本随交付保存；可信源版本和外部核验记录留工作区。对收到的 ZIP 事后生成自洽清单只证明当前内容，不能证明对应的是本次正式版本。

## 3. 目录与 ZIP 的共用机械检查

使用 `scripts/delivery_check.py`，详见 [命令与边界](final-delivery-packaging.md)：

- **目录：** 先预检条目数、字节预算、路径与文件类型，再解析内容或哈希。拒绝符号链接和 Windows junction/reparse point，避免“交付成功”依赖工作区外文件。
- **ZIP：** 先检查危险路径、重复项、链接、预算和 CRC，再真实解压到新临时目录，按同样逻辑检查内容。
- **内容：** 检查必需文件、清单大小/hash、DOCX 正文及图片关系、PDF 页数和内容指令、Python 语法、CSV/TSV 行宽。非空 TEX 仅证明源文件存在。
- **源稿选择：** `reference-paper` 要求 PDF；DOCX、TEX 或不交源稿由 `--paper-source docx|latex|none` 声明。未约定不自行更换团队论文格式。

预算是工具的机械资源上限，不是官方提交容量规则。工具只接受普通自包含文件，不自动下载依赖、运行包内代码或编译 LaTeX。输入在验收期间应保持冻结，不边生成边检查。

机械输出为 `MECHANICAL_ONLY`。对 XLSX、图片、公式版面等未实际解析的内容，另用相应工具验证；不能把存在、哈希一致或 PDF 含绘制指令说成视觉正确。

## 4. 隔离复现与视觉验收

以**最终目录副本或最终 ZIP 解压副本**为对象，而不是仅在原工作区运行：

1. 建立新的隔离验收区，保留原工作区与冻结结果。只提供说明声明的外部输入。
2. 真实打开论文并渲染检查代表性文字、公式、表格、图表与字体；验证 PDF 对应当前源稿。
3. 在适用计算环境中执行已授权入口，输出指向验收区，不能覆盖正式结果。
4. 标明执行的是重新求解，还是重建/核对已交付结果。多解、随机性和平台差异使用事先明确的容差与等价性检查。
5. 对账关键结果、模型约束、论文引用与清单，记录本次实际执行的命令、环境、结果与限制。

缺少硬件、软件许可或不可分发数据导致无法重跑时，明确未验证范围。不能用旧 PASS、旧截图或“源目录能运行”替代当前最终包验收。不能把机械检查失败用文档说明包装为完整交付通过。

## 5. 结论与恢复

最终回复先说明交付位置、实际完成范围与当前有效成果，再分别说明机械、复现、论文视觉和科学核验状态；不能只输出“PASS”。

关键缺陷标记 `DELIVERY_INTEGRITY_FAILED`；修复后重验受影响的最终材料。仅完成部分时如实报告，例如“计算与机械检查完成，隔离复现尚缺外部输入”。所有约定范围验收后才可标记 `INTERNAL_DELIVERY_COMPLETE`。

打包或验收失败不得删除、移动或覆盖原件、正式代码、冻结结果和论文。清理验收区前确认没有正式文件依赖它。官方导出另遵循 [官方提交规范](official-submission-policy.md)，内部目录/包不能自动视为可上传文件。
