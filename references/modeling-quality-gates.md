# 建模证据质量门

## 目标

优秀数学建模不靠“模型多”，而靠一条可追溯的证据链：

```text
识别数据结构
→ 按题意处理数据
→ 检查模型前提
→ 建立 baseline
→ 正式求解
→ 独立验证
→ 现实约束审计
→ 回答原题并传递给后问
```

本文件只保留会改变模型选择、结果可信度或论文结论的质量门。具体 EDA、代码、绘图和论文格式由对应 policy 负责，避免重复。

任一核心门未通过时统一标记：

```text
MODELING_EVIDENCE_GATE_FAILED
```

并写明失败原因，不再为每种小问题创建新的状态名。

---

## 1. 数据结构识别门

正式选模前必须记录：

```text
DATA_STRUCTURE_IDENTIFIED = true / false
样本单位：
目标变量：
数据结构：
关键限制：
```

至少检查是否属于：

- 成分/比例数据：非负、总和约束、零值、闭合效应；
- 时间序列：趋势、季节性、自相关、结构突变、时间泄漏；
- 空间数据：坐标系、距离、邻接和空间相关；
- 网络数据：节点、边、方向、权重和连通性；
- 配对/重复测量：同一对象的组内相关和不可随意拆分；
- 层级数据：个体、地区、设备或批次的嵌套关系；
- 排名/等级：只有顺序还是具有等距意义；
- 截尾/删失/故障数据：观测是否完整；
- 优化数据：决策变量、资源、守恒、整数性和可行域。

数据结构没有识别清楚时，不允许只根据“预测、评价、优化、分类”等关键词套模型。

---

## 2. 数据处理可追溯门

每个会改变数据的处理至少记录：

| 处理对象 | 处理前 | 处理后 | 规则 | 题意/统计依据 | 可能影响 |
|---|---:|---:|---|---|---|

必须说明缺失、异常、零值、重复、单位、编码和样本剔除的语义。禁止：

- 为了模型方便随意删样本；
- 先看结果再选择性删除不利数据；
- 把清洗值写回原始文件；
- 用一句“进行了数据清洗”代替真实规则；
- 把插值、估计、假设或仿真数据冒充观测数据。

---

## 3. 模型适用条件门

每个正式模型或统计检验都要能回答：

```text
模型名称：
解决哪个题目动作：
关键前提：
前提检查：
不满足时的替代方案：
```

示例：

- 列联表检验检查期望频数；
- 回归检查泄漏、残差和共线性；
- 聚类说明距离、标准化和簇数依据；
- 时间序列使用滚动验证而非随机切分；
- 启发式优化说明可行解、停止条件和重复实验；
- 成分数据说明零值处理、变换和逆变换；
- “相关”不得直接写成“导致”。

方法名称、公式、代码函数和逆变换必须一致。前提不满足时应换方法、分层、降级结论或明确限制，不能假装通过。

---

## 4. 分层与变量筛选门

当不同地区、时期、设备、工况、人群或状态的机制可能不同，可以分层，但要验证：

1. 分层前后分布或机制是否确有差异；
2. 统一模型加入组别/交互项是否已经足够；
3. 分层后样本量是否仍支持模型；
4. 分层模型在验证中是否更稳定。

聚类前先检查“距离由谁主导”。高相关变量可能重复放大同一信息，应根据题意使用相关聚类、PCA、VIF、LASSO、互信息、树重要性或领域知识筛选。禁止为了图好看或簇更清楚而事后挑变量。

---

## 5. baseline 与核心结论双证据门

每个核心结论先建立合理 baseline。复杂模型若没有在精度、稳定性、可解释性、计算成本或现实约束上带来真实收益，不应仅因“高级”而成为主模型。

A 级核心结论原则上需要：

```text
主模型证据 + 至少一种独立验证证据
```

独立验证应尽量来自不同原理，例如：

- 分类器 + 聚类结构/外部样本；
- 预测模型 + 滚动验证/简单基线；
- 启发式解 + 小规模精确解/上下界；
- 综合排名 + 权重扰动/方法替换/排名相关；
- 聚类 + 重采样稳定性/外部标签；
- 关联结果 + Bootstrap/替代标准化/偏相关。

核心结论只有单次运行或同原理模型相互重复时，应降级表述。

---

## 6. 现实约束审计门

最终结果必须检查题目适用的现实约束：

- 非负、上下界、总和和守恒；
- 容量、库存、流量和时间窗；
- 资源冲突、逻辑先后和路径连通；
- 整数性、唯一性和覆盖要求；
- 概率和成分总和；
- 单位与量纲；
- 业务可执行性。

推荐输出：

| 约束 | 最大违反量 | 是否满足 | 证据文件/代码 |
|---|---:|---|---|

数值指标很好但现实约束不满足，结果仍然不合格。

---

## 7. 完美指标警报

当测试准确率、F1、拟合优度或其他指标异常接近理论上限时，触发：

```text
PERFECT_SCORE_AUDIT_REQUIRED
```

至少检查：

- 测试集是否过小；
- 训练/验证/测试是否泄漏；
- 同一主体、同源样本或重复记录是否跨集合；
- 是否在测试集上反复调参；
- 类别不平衡是否掩盖错误；
- 是否只报告最有利的随机种子；
- 多折、多种子或外部验证是否仍然成立。

完美指标可以是真实结果，但在完成审计前不能当成“模型一定正确”的证据。

---

## 8. 潜在阶段解释审计

当聚类簇、主成分或隐状态被解释为“早期/中期/晚期”“轻度/中度/重度”等时间、程度或等级时，触发：

```text
LATENT_STAGE_INTERPRETATION_AUDIT_REQUIRED
```

必须提供至少一种排序依据：已知锚点、单调指标、机理/实验依据、外部标签或不同方法下的稳定顺序。

证据不足时只能称为“潜在状态”“相似性分组”或“程度代理”，不能把簇编号直接写成确定阶段。

---

## 9. 跨问题复用门

后问复用前问结果时，维护：

| 上游问题 | 下游问题 | 复用对象 | 文件/Final Run | 是否重算 | 说明 |
|---|---|---|---|---|---|

复用对象可以是数据、参数、模型、阈值、分类结果或结论。必须从正式文件和 Final Run 读取，禁止从聊天或论文文字手抄。

上游结果更新时，沿以下链检查：

```text
上游 Final Run
→ 跨问接口
→ 下游代码与结果
→ 图表
→ 教程
→ 论文
```

---

## 10. 论文证据表达门

每个结果段落按以下顺序组织：

```text
观察：图表中可核验的现象
→ 比较：与基线、组别或场景的差异
→ 解释：有证据支持的机制或原因
→ 结论：回答原题哪一项
→ 限制：在哪些条件下成立
```

禁止逐格念表、把统计不显著写成“完全独立”、把启发式当前最好解写成已证明全局最优，或把关联直接解释为因果。

---

## 11. 每问最小验收

- [ ] `DATA_STRUCTURE_IDENTIFIED = true`；
- [ ] 数据处理有数量、规则和依据；
- [ ] 最终模型对应题目动作且前提已检查；
- [ ] 存在 baseline；
- [ ] 核心结论有主证据和独立验证；
- [ ] 现实约束与单位通过；
- [ ] 完美指标和潜在阶段在触发时完成专项审计；
- [ ] 跨问复用来自正式文件和 Final Run；
- [ ] 结论强度不超过证据。

未通过时标记 `MODELING_EVIDENCE_GATE_FAILED`，说明缺口并回到方案讨论或验证阶段。
