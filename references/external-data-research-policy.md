# 外部真实数据与本土资料检索规范

## 目标

数学建模结论只要依赖题面未提供的现实事实、统计量、行业指标、政策口径或运营数据，AI 就应优先联网寻找真实、可核验的来源，不能凭常识或“看起来合理”的数值补齐。

找不到可靠数据时，应记录缺口、替代方案和对模型的影响。**宁可缺数据，也不能编数据。**

严重违规状态：

```text
FABRICATED_EXTERNAL_DATA
```

出现后必须停止使用该数据，回溯相关模型、Run、结果、图表和论文结论，重新建立证据链。

---

# 1. 哪些情况必须主动联网

题目或模型需要现实世界中的量，而题面和附件没有可靠给出时，应主动检索。例如：

- 机场起降架次、旅客吞吐量、航班量和航线结构；
- 人口、GDP、就业、价格、销量和交通流；
- 气象、环境、能源、物流、医疗和教育统计；
- 设备性能、工程参数和行业阈值；
- 政策、标准、收费规则和排放因子；
- 历史时间序列；
- 地区、企业、机场、港口和景区的真实运营数据；
- 用于校准、验证、边界检查和敏感性范围的数据。

例如题目涉及浦东机场起降数据，而附件没有完整提供时，不能自行假设日均架次、增长率或峰值容量，应从权威公开来源检索。

---

# 2. 来源优先级

中国赛题或中国现实场景默认按以下顺序查找：

1. **中国官方与法定统计来源**
   - 国家统计局、国家数据；
   - 民航局、交通运输部、生态环境部等国务院部门；
   - 省市政府、统计局和行业主管部门；
   - 统计年鉴、统计公报和政府开放数据；
   - 国家标准、行业标准和正式政策文件。
2. **现实对象的官方来源**
   - 机场、港口、企业、交易所和运营机构官网；
   - 年报、运营快报、官方公告和开放数据接口。
3. **中国权威行业与科研来源**
   - 行业协会；
   - 高校和科研院所正式报告；
   - 中文核心、CSCD、CSSCI、学位论文等可核验资料。
4. **国际权威来源**
   - 国际组织、国外政府机构和国际行业数据库；
   - 高质量国际论文与数据库。
5. **二次来源**
   - 新闻、博客、论坛和自媒体只作线索，关键数据继续追原始来源。

如果最可靠的原始数据来自国际机构，可以使用；但中国本地事实不应因为搜索方便就默认由外国二手资料代替。

---

# 3. 中国现实题目的文献结构

方法论、经典模型和原始算法可以使用高质量国际文献。涉及以下内容时，应主动寻找中文和本土资料：

- 中国政策与制度；
- 中国地区、机场、港口、交通、产业和市场现状；
- 国内统计口径；
- 中国行业参数和标准；
- 国内同类问题的应用研究；
- 赛题实体的真实运营背景。

如果论文几乎全部引用外国文献，而赛题明显属于中国现实场景，应复查是否漏掉中国官方统计、中文应用研究、国内标准和本土行业资料。

不设置机械的中文文献比例，也不为了数量塞无关文献。重点是证据是否贴合当前问题。

---

# 4. 严禁的补数据方式

禁止：

- 凭常识填写“合理值”；
- 把模型假设包装成现实统计；
- 只看搜索摘要就抄无法核验的数字；
- 用其他地区或年份的数据冒充当前对象；
- 把“行业通常为某范围”的中点当成观测值；
- 自行制造增长率、缺失年份、样本量或分布；
- 插值、均值填补或模拟后不说明性质；
- 为了让代码运行而偷偷生成现实观测值；
- 把 synthetic、simulated 或 assumed 数据写成“实际数据”。

估计、插值、外推、假设或模拟必须明确标注：

```text
OBSERVED_EXTERNAL
INTERPOLATED
EXTRAPOLATED
MODEL_ESTIMATED
ASSUMED
SIMULATED
```

只有 `OBSERVED_EXTERNAL` 可以不加限定地称为外部观测数据。

---

# 5. 取得数据后核验口径

不能只看数值，还要确认：

- 发布机构；
- 发布时间和统计期；
- 对象及地域范围；
- 指标定义；
- 单位；
- 累计值还是当期值；
- 自然年、财年、航季还是月度；
- 是否包含国内/国际、客运/货运等子口径；
- 是否存在修订值；
- 页面、表格或附件是否与引用数字一致。

同名指标口径不同，不能直接拼接。

---

# 6. Codex 中如何保存外部数据

Codex 单赛题工作区遵循 `local-workspace-policy.md`。

下载的外部原始文件保存到：

```text
01_data/external/
```

对外部数据进行清洗、单位统一、合并或特征构造后，结果保存到：

```text
01_data/processed/
```

不要覆盖 `01_data/external/` 中的原始下载文件，也不要把外部数据混入 `01_data/raw/` 冒充题目原始数据。

网页与来源账本记录在：

```text
07_references/websites.md
07_references/notes.md
```

如果下载的是论文、标准或正式报告，可放入：

```text
07_references/papers/
```

清洗脚本放入 `03_code/common/` 或实际使用它的 `03_code/qN/`。模型输出进入 `04_results/`，不能写回原始数据目录。

# 7. 外部数据追溯字段

每个会影响模型、参数、验证、图表或论文结论的外部数据，至少记录：

| 字段 | 说明 |
|---|---|
| 数据名称 | 具体指标 |
| 对象 | 地区、机构、设备或行业 |
| 发布机构 | 原始来源 |
| 来源 URL | 已实际核验链接 |
| 获取日期 | 实际检索日期 |
| 时间范围 | 数据对应时段 |
| 原始单位 | 来源原单位 |
| 使用单位 | 模型中的单位 |
| 口径说明 | 指标定义与范围 |
| 原始位置 | 网页段落、表格、Sheet 或行列 |
| 本地原始文件 | `01_data/external/` 中的位置 |
| 清洗后文件 | `01_data/processed/` 中的位置 |
| 处理脚本 | 对应 `03_code/` 路径 |
| 清洗转换 | 做了什么处理 |
| 使用问题 | 问题 k、模型或验证 |
| 使用 Run | 关联 Run ID |
| 数据类型 | OBSERVED_EXTERNAL / INTERPOLATED / ... |

只有留下这些信息，后续才能判断数据究竟来自哪里、做过什么处理、进入了哪个结果。

# 8. 找不到数据时怎么办

经过合理搜索仍找不到可靠数据时：

1. 明确告诉用户缺什么；
2. 说明搜索过哪些权威渠道；
3. 给出可选处理：用户补充、改模型、使用可核验代理变量、做区间或敏感性分析；
4. 必须使用假设时标为 `ASSUMED`，并说明它影响什么；
5. 不因为任务必须完成而制造一个数据值。

如果数据缺口会改变路线，应在当前问题的 `QUESTION_PLAN_CONFIRMATION` 前与用户讨论。

数据缺口、搜索范围和处理决定同步到：

```text
02_analysis/model_plan.md
07_references/websites.md
07_references/notes.md
```

---

# 9. 与旧题盲测的兼容

`BLIND_BENCHMARK_MODE` 仍允许搜索真实外部数据。

例如旧题涉及机场运营，可以搜索：

- 民航局或机场官方统计；
- 一般机场运行参数；
- 行业标准和公开数据。

查询应避免足以定位历史赛题答案的题号、题名、原文片段、附件名和特殊数据组合。

原则：**禁止搜答案，不禁止查现实。**

如果搜索现实数据时意外命中该旧题历史论文或完整解答，按 `search-mode-policy.md` 标记 `ANSWER_LEAKAGE_DETECTED` 并停止继续读取。

---

# 10. 与来源核验政策的关系

本规范决定什么时候必须找现实数据，以及真实性底线。

`source-verification-policy.md` 决定来源、链接、全文和元数据如何核验。

二者同时生效：

```text
现实数据缺口
→ 主动联网检索
→ 优先本土权威来源
→ 实际打开并核验
→ 保存到 01_data/external
→ 记录到 07_references
→ 清洗结果另存 01_data/processed
→ 进入模型和 Run
→ 结果与论文可追溯
```

---

# 11. 最终自检

在每问方案确认、Final Run、参考论文和终稿审核前检查：

- [ ] 是否存在题面未提供却被当作现实事实使用的数字？
- [ ] 数字是否有真实来源？
- [ ] 能否追到具体机构、页面或文件？
- [ ] 单位和统计口径是否一致？
- [ ] 外部原始数据是否位于 `01_data/external/`？
- [ ] 清洗结果是否另存于 `01_data/processed/`？
- [ ] `07_references/websites.md` 是否记录来源？
- [ ] 中国现实场景是否先查了中国官方和本土资料？
- [ ] 外国文献是否用于真正适合的方法论和国际证据，而非替代本土事实？
- [ ] 假设、插值、估计和模拟是否明确标注？
- [ ] 找不到数据时是否诚实报告，而不是补值？

任何关键现实数据无法说明来源时，不得把相关结果当作已验证的最终结论。
