# 模型运行账本与结果来源追踪规范

## 目标

Codex / Claude Code 在本地比赛环境中会频繁运行探索脚本、正式模型、参数扫描、随机算法和验证实验。

不能等到最后再凭聊天记忆判断“哪个结果才是最终版”。所有会影响模型选择、论文数字、图表或结论的正式运行，应留下轻量但可追溯的运行记录。

核心原则：

> **结果必须能追到某一次真实运行；正式运行不能只存在于聊天描述里。**

---

## 1. 两层记录

推荐：

```text
其他/运行与实验/
├── RUN_LEDGER.md
└── runs/
    ├── R001.md
    ├── R002.md
    └── ...
```

`RUN_LEDGER.md` 是索引；只有重要运行才单独建立 `Rxxx.md`，避免日志爆炸。

---

## 2. 什么必须记录

以下运行若发生，必须进入账本：

- 决定候选路线的 baseline；
- 最终正式模型运行；
- 最终参数标定；
- 最终预测；
- 最终优化求解；
- 最终 Monte Carlo / 仿真；
- 敏感性、鲁棒性、压力场景；
- 启发式算法多随机种子实验；
- 会进入论文的统计检验；
- 生成正式 A/B 级图表的数据运行；
- 路线重开前后用于比较的新实验。

一次性 debug、语法测试、无价值临时试跑无需全部记录。

---

## 3. RUN_LEDGER 最小字段

| Run ID | 时间 | 问题 | 目的 | 代码入口 | 输入版本 | 关键参数 | 随机种子 | 输出目录 | 结论/用途 | 状态 |
|---|---|---|---|---|---|---|---|---|---|---|

状态可用：

- `EXPLORATORY`
- `BASELINE`
- `CANDIDATE`
- `FINAL`
- `VALIDATION`
- `REJECTED`
- `SUPERSEDED`

如果无法获得可靠时间戳，不要伪造精确时间；可以使用运行顺序 ID 和日期。

---

## 4. 重要运行详细记录

`Rxxx.md` 建议包含：

```markdown
# Rxxx

- 对应问题：
- 运行目的：
- 代码入口：
- Git commit / 文件版本（可获得时）：
- 输入数据：
- 数据范围：
- 参数：
- 随机种子：
- 运行命令：
- 输出目录：
- 关键结果：
- 生成图表：
- 生成表格：
- 验证状态：
- 是否用于最终论文：
- 被哪个运行替代：
- 备注：
```

不得把未实际执行的计划写成 Run。

---

## 5. 最终结果必须指向 Final Run

进入问题完成状态前，应明确：

```text
FINAL_RUN_ID = Rxxx
```

本问最终：

- 数值；
- 排名；
- 路径；
- 预测；
- 参数；
- 图表；
- 表格；
- 敏感性/鲁棒性结论；

必须优先从该 Final Run 或明确关联的 Validation Run 读取。

禁止从旧截图、旧 CSV、聊天历史或已被替代的运行中手抄最终数字。

---

## 6. 结果版本替换

如果新运行取代旧结果：

- 旧运行标 `SUPERSEDED`；
- 记录替代它的新 Run ID；
- 更新 Visualization Manifest；
- 更新论文候选图/表；
- 更新题目详解；
- 更新本问最终答案；
- 若已经生成参考论文，必须重新做一致性检查。

不得删除旧运行记录后假装它从未存在；但无意义临时文件可以清理。

---

## 7. 随机算法与重复实验

对于 GA、PSO、ACO、SA、随机仿真、Bootstrap 等：

- 保存随机种子或种子生成方式；
- 记录重复次数；
- 记录最佳、平均、中位数和离散程度中真正需要的指标；
- 不得只选择最漂亮的一次结果冒充稳定表现；
- 如果最终选用某一次代表性路径/方案，应说明选择规则。

---

## 8. 与图表的关系

`VISUALIZATION_MANIFEST.md` 应增加 `Run ID` 字段：

| 图号 | 文件 | 问题 | Run ID | 数据源 | 生成代码 | 目的 | 等级 | 论文 |
|---|---|---|---|---|---|---|---|---|

这样形成：

```text
论文结论
↕
论文图/表
↕
Visualization Manifest
↕
Run ID
↕
输入数据 + 参数 + 代码
```

---

## 9. 与论文的关系

论文中关键数字若存在重复出现，应能追到同一个 Final Run。

如果摘要写 `12.6%`、正文写 `12.58%`、表格写 `12.61%`，必须判断：

- 是否只是统一舍入问题；
- 还是混入了不同运行版本。

不能用“差不多”处理版本冲突。

---

## 10. 运行失败也有价值

只有当失败会影响决策时才记录，例如：

- 原路线约束不可行；
- 某方法数值不稳定；
- 计算规模无法在赛时完成；
- baseline 明显胜过复杂模型；
- 关键假设在实测中失败。

这类运行可以标 `REJECTED`，并记录它为什么触发路线调整。

失败不是需要隐藏的东西，它是建模决策证据。
