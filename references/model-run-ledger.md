# 模型运行账本与结果来源追踪规范

## 目标

Codex 在本地比赛环境中会频繁运行探索脚本、正式模型、参数扫描、随机算法和验证实验。

不能等到最后再凭聊天记忆判断哪个结果才是最终版。所有会影响模型选择、论文数字、图表或结论的运行，都应留下轻量但可追溯的记录。

> **结果必须能追到某一次真实运行；正式运行不能只存在于聊天描述里。**

---

## 1. 保存位置

Codex 默认保存到：

```text
04_results/logs/
├─ RUN_LEDGER.md
└─ runs/
   ├─ R001.md
   ├─ R002.md
   └─ ...
```

`RUN_LEDGER.md` 是索引；只有真正影响方案或最终成果的重要运行才单独建立 `Rxxx.md`，避免日志爆炸。

---

## 2. 什么必须记录

以下运行若发生，必须进入账本：

- 决定候选路线的 baseline；
- 最终正式模型运行；
- 最终参数标定；
- 最终预测或优化；
- 最终 Monte Carlo / 仿真；
- 敏感性、鲁棒性和压力场景；
- 启发式算法多随机种子实验；
- 会进入论文的统计检验；
- 生成正式 A/B 级图表的数据运行；
- 路线重开前后用于比较的新实验。

一次性 debug、语法测试和无价值临时试跑无需全部记录，可留在 `99_temp/` 或普通日志中。

---

## 3. RUN_LEDGER 最小字段

| Run ID | 时间 | 问题 | 目的 | 中文代码入口 | 输入版本 | 关键参数 | 随机种子 | 输出目录 | 生成图像及用途 | 结论/用途 | 状态 |
|---|---|---|---|---|---|---|---|---|---|---|---|

状态可用：

```text
EXPLORATORY
BASELINE
CANDIDATE
FINAL
VALIDATION
REJECTED
SUPERSEDED
```

如果无法获得可靠时间戳，不要伪造精确时间；可以使用运行顺序 ID 和日期。

Codex 中的正式代码入口优先指向：

```text
03_code/q1/第一题.py
03_code/q2/第二题.py
03_code/总运行.py
```

复杂问题可以指向 `第一题_模型求解.py` 等中文职责模块。不要把已经被替换的 `main.py`、`run_all.py` 或临时脚本继续写成最终入口。

---

## 4. 重要运行详细记录

`04_results/logs/runs/Rxxx.md` 建议包含：

```markdown
# Rxxx

- 对应问题：
- 运行目的：
- 中文代码入口：
- Git commit / 文件版本（可获得时）：
- 输入数据：
- 数据范围：
- 参数：
- 随机种子：
- 运行命令：
- 输出目录：
- 关键结果：
- 生成论文图：
- 生成验证图：
- 生成探索图：
- 生成 AI 沟通图：
- 生成表格：
- 验证状态：
- 是否用于最终论文：
- 被哪个运行替代：
- 备注：
```

不得把未实际执行的计划写成 Run。

---

## 5. 最终结果必须指向 Final Run

进入问题完成状态前，明确：

```text
FINAL_RUN_ID = Rxxx
```

本问最终的数值、排名、路径、预测、参数、图表、表格和敏感性/鲁棒性结论，都必须从该 Final Run 或明确关联的 Validation Run 读取。

禁止从旧截图、旧 CSV、聊天历史或已被替代的运行中手抄最终数字。

根目录 `README.md`、`02_analysis/model_plan.md` 和本问教程应记录本问 `FINAL_RUN_ID` 及真实中文代码入口。

---

## 6. 结果版本替换

如果新运行取代旧结果：

- 旧运行标记 `SUPERSEDED`；
- 记录替代它的新 Run ID；
- 更新中文代码入口和运行命令；
- 更新 `VISUALIZATION_MANIFEST.md`；
- 更新最终图、表和数值；
- 更新题目详解和本问答案；
- 更新根目录 `README.md`；
- 已生成参考论文时重新做一致性检查。

不得删除重要旧运行记录后假装它从未存在；无意义临时文件可以清理。

---

## 7. 随机算法与重复实验

对于 GA、PSO、ACO、SA、随机仿真、Bootstrap 等：

- 保存随机种子或种子生成方式；
- 记录重复次数；
- 记录真正需要的集中趋势和离散指标；
- 不得只选择最漂亮的一次结果冒充稳定表现；
- 最终选用某一次代表性路径或方案时说明选择规则。

---

## 8. 与图表的关系

`VISUALIZATION_MANIFEST.md` 应至少包含：

| 图号 | 文件 | 用途类型 | 问题 | Run ID | 数据源 | 中文生成脚本 | 图面标记 | 进入论文 | 进入官方提交 |
|---|---|---|---|---|---|---|---|---|---|

用途类型：

```text
PAPER_FIGURE
VALIDATION_FIGURE
EXPLORATION_FIGURE
AI_COMMUNICATION_ONLY
SECURITY_AUDIT_ONLY
```

AI 沟通图必须使用 `AI沟通图_` 前缀、显示“AI内部沟通图｜非论文材料”，并明确不进入论文和官方提交。

证据链为：

```text
论文结论
↕
论文图 / 表
↕
Visualization Manifest
↕
Run ID
↕
中文代码入口 + 输入数据 + 结果文件
```

---

## 9. 与论文的关系

论文中重复出现的关键数字应能追到同一个 Final Run。

如果摘要写 `12.6%`、正文写 `12.58%`、表格写 `12.61%`，必须判断是统一舍入差异，还是混入不同运行版本。

论文图还必须能追到同语义中文绘图脚本。`AI_COMMUNICATION_ONLY` 和 `SECURITY_AUDIT_ONLY` 不得作为论文图。

---

## 10. 运行失败也有价值

只有失败会影响决策时才需要记录，例如：

- 原路线约束不可行；
- 某方法数值不稳定；
- 计算规模无法在赛时完成；
- baseline 明显胜过复杂模型；
- 关键假设在实测中失败。

这类运行可以标记 `REJECTED`，并说明为什么触发路线调整。

失败不是需要隐藏的东西，它是建模决策证据。
